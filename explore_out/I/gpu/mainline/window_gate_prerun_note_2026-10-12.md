# test_window_gate on the GTX 1660 SUPER: pre-run note, 2026-10-12 (EXPLORATORY)

This note is committed on `claude/explore-I` before the run starts. It fixes what runs and what will be described.
**There is no reading.**

## What runs

- **The test.** `test_window_gate`, Part C / D, through `explore_gpu.mainline` on the GTX 1660 SUPER, using the test's
  own `run_job`, seeding and record format. This branch's `test_window_gate.py` is byte-identical to the main line's
  (0754d61).
- **The path.** Part C's path: `run_sc` with D8 (S = 8, P = 4, k = 16, conv), the test's REAL schedule of 43,200 steps.
  `--iters` is not used.
- **The machine.** The run moved here from the RTX 3070, which ran out of host memory running it beside
  test_delta_recipe.
- **Order.**
  1. CEIL_C on seeds 2540–2541: the validity runs.
  2. WIN3_SPLIT_D8, HINGE_D8 and WIN3_SLOW_D8, each on seeds 2540–2559. All three arms run on all 20 seeds whatever
     CEIL_C shows.
- **Seeds.** 2540–2559 are fresh. They overlap none of X's (500–559), L's (1500–1559) or R's (900–959) seeds, and no
  block on the main line's seed list; round 5 reserves 2540–2559 for this run. Checked on every branch of the
  repository on 2026-10-12.
- **Commands** (from the repository root, on the commit that adds this note or later):

      python -m explore_gpu.mainline --test test_window_gate --arm CEIL_C --seeds 2540-2541 --device cuda --workers 2
      python -m explore_gpu.mainline --test test_window_gate --arm WIN3_SPLIT_D8 --seeds 2540-2559 --device cuda --workers N
      python -m explore_gpu.mainline --test test_window_gate --arm HINGE_D8 --seeds 2540-2559 --device cuda --workers N
      python -m explore_gpu.mainline --test test_window_gate --arm WIN3_SLOW_D8 --seeds 2540-2559 --device cuda --workers N

  Every worker runs one thread on every device (fixed in mainline.py with this note). N follows from the server's RAM,
  which is the user's call.
- **Records.** They go to `explore_out/I/gpu/mainline/test_window_gate_NVIDIA_GeForce_GTX_1660_SUPER_results.json`, keyed
  `ARM|seed`. Each record carries the device meta, including the thread count, and a code SHA over the test's modules
  and `explore_gpu/device.py` and `mainline.py`. The file's meta names the machine "GPU:NVIDIA GeForce GTX 1660 SUPER",
  so the test's `--also` pooling cannot take these records for X's or L's. Records from the RTX 3070's aborted attempt,
  if any exist, are not described.

## What will be described

The descriptions are generated by `python -m explore_gpu.window_gate_writeup`, committed with this note, into
`window_gate_descriptions.md`. It uses `test_window_gate`'s own functions.
- **Validity, by the test's own rule.** Part C (and D) is VALID if CEIL_C binds on both 2540 and 2541. Otherwise the
  counts below are printed under "NOT VALID".
- **Each arm's BOUND ROUTED count, with its Wilson 95% interval.** BOUND ROUTED is the test's success for Parts C and D
  (`test_stream_recipe.outcome == "BOUND ROUTED"`).
- **Discordant pairs against the controls, paired by seed.** Each pairing reports b (first arm only) and c (control
  only):
  - WIN3_SPLIT_D8 vs HINGE_D8, the test's G2 pairing;
  - WIN3_SPLIT_D8 vs WIN3_SLOW_D8, G4's pairing;
  - WIN3_SLOW_D8 vs HINGE_D8, the test's printed "original G2".
- **Beside X's, L's and the pooled X + L counts and pairs**, computed by the same functions from
  `results/X/window_gate_results.json` and `results/L/window_gate_results.json`. The GPU run is never pooled with them.

**Not printed:** p-values, SHOWN / NOT SHOWN, the test's reading ("eight streams bind without labels or restarts"),
and any "replicates" or "consistent" label.

## What the CUDA CHECKs did and did not cover

A CUDA run is a new run. It is not bit-comparable with X's or L's CPU runs: compare outcomes, not curves. Both cards'
CUDA CHECKs passed. They validated the sequential path as mainline runs it (K4b: arm A and the S75 models) and, on fake
CUDA tensors, the forwards of LocalBDH and the split noise of `test_window_gate.split_op` (K8). Part C's models at
S = 8 were not run lock-step against the CPU.
