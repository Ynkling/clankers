# Audit of the project, 6 October 2026

*Scope: everything up to Revision 7 and batch 15. Method: three independent code audits (model and task; recipes and statistics; the exploratory harness and screens S24–S42), a literature sweep, and a review of the research logic against the records. Every number below was recomputed from the results files or read from the code at the cited line; inferences are marked as such.*

## 0. The ten findings that matter

1. **No bug changes a reported result.** Every pre-registered count and p-value reproduces from the results files; the statistics functions match scipy to machine precision; every path is strictly causal; nothing leaks the answer. The low-severity items are listed in §2.
2. **A width-3 window gate was screened in batch 1, beat the plain gate (15/20 vs 7/20 on seeds 160–179), and was dropped** because it cannot see a distant cue. The recurrent gate cannot either, in practice. Everything the project has fought since (position splits, the hinge, the runaway recurrence at eight streams) is a pathology of the recurrent gate that the window gate cannot have. It was never combined with slow memory, never run at four or eight streams. §3.1.
3. **The gate needs two tokens of memory at the write positions, not one.** The model reads the answer at the query's KEY position (CTX one token back), but the stream-labelled *write* happens at VAL positions (CTX two back). Revision 7 says "one token"; the eight-stream decoders (S38–S41) probed key and stream-token positions only, never the write positions; S41's NOREC arm cannot label writes by construction, so its reading is predetermined. §3.2.
4. **The gate reads raw, un-normalized, un-convolved token embeddings, and one gate matrix is applied at every layer.** A per-layer gate over the residual stream, which is how every related architecture routes (MoM, Raven, SSE, Triadic Linear Attention), has never been tried here. It is the only route to distant cues that does not need a long recurrence. §3.3.
5. **At eight streams the learning rate and the memory decay were never varied.** Every eight-stream run used Adam 1e-3 or Muon 0.005 with decay 0.95 (half-life 14 tokens on 99-token sequences; the earliest same-stream triple is weighted 1/118 of the latest). Recent work shows recall failures in recurrent models are often optimization, not expressivity. §3.4.
6. **S41's "cap" shrinks W_h 2.2× at update 1** (its spectral norm is ≈1.08 at initialization, above the 0.5 cap), so it tests a small recurrence from the start, not a cap on growth. §2.3.
7. **The split screens (S36, S37) scored BOUND, not BOUND ROUTED, and bundle an optimizer-state reset without a reset-only control.** Revision 7's routed counts are right (taken from the per-seed tables); the screens' own verdicts are not. Merges at k = S are the standard mixture-of-experts collapse; spare channels are the standard fix. §2.4.
8. **The closest published relative is Triadic Linear Attention (arXiv 2609.36529, Sept 2026):** a d×E×d state written as k ⊗ k₂ ⊗ v, whose E slices are separately gated memories. Our score (x·x)(g·g) is that form with g as k₂. The report must cite and differentiate it; our contribution is the recurrent softmax gate, the label-free symmetry breaking, and the binding analysis. §4.
9. **About sixty pre-registered claims per machine at α = 0.05 means two or three false positives are expected** if every null were true. Trust the results replicated on both machines (H0, S0, Q2; E1 and E2 in direction) and the pooled disjoint-seed tests from now on. §5.
10. **Process:** two specifications were lost between sessions and two result files were mixed up. Commit every specification to the repository before it runs, and let L commit its own results. §5.

### 2.2 Deviations between description and code

- **Muon's "0.005 / ×0.1" is nominal.** torch's Muon scales each matrix's rate by √max(1, rows/cols): the gate matrices get ×1.0, the decoder ×1.41, the output head ×1.1–1.2 (`test_early_recipe.py:326`). Documented in the docstring; the report's numbers hold exactly only for the gate.
- **The Muon rate was never selected on a learned gate.** 0.005 is the smallest of {0.005, 0.01, 0.02} at which the *perfect* gate bound on two seeds (`explore_muon_recipe.py:99-101`); it is the lower edge of the grid and a validity floor, not a tuned value. Every learned-gate Muon run used it. A sweep (0.0025, 0.005, 0.01) at two streams costs about an hour.
- **Newton–Schulz runs in bfloat16** inside `torch.optim._muon`; this is the host dependence found in batch 15. For CPU work a float32 Newton–Schulz (a 20-line custom step) would make Muon runs reproducible across processors.
- **Gate initialization:** W_in, W_h, W_g ~ N(0, 0.1²) (`test_multilayer_binding.py:266-273`), unlike the stack's 0.02. For a 32×32 W_h this gives spectral radius ≈ 0.6 and spectral norm ≈ 1.08 at initialization — consistent with S42's ρ₀ = 0.52–0.63, and the reason S41's cap acts from update 1. The gate's pre-activation at initialization has std ≈ 0.011, so the gate is 1/k ± 0.002: this, with the LayerNorm after attention cancelling any constant in G, is the structural reason for the 10⁻⁵ gate gradient (Background in Revision 7 states the fact; this is the mechanism).

### 2.3 The exploratory screens: what they actually measured

- **S41 NOREC** (W_h = 0; gate from v_t and v_{t−1}) sees the stream at KEY positions and at the query, but at VAL positions it sees only VAL and KEY. The write cannot be stream-labelled, so NOREC cannot express the routing the task needs; 0/10 is a property of the arm, not evidence about recurrence. Drop its reading.
- **S41 CAP and PREV_CAP** shrink W_h from σ_max ≈ 1.08 to 0.5 at update 1 and project every step. They test "a small, contractive recurrence from the start", which is a reasonable intervention, but not "a cap on growth" and not "the same initialization as the paired run" beyond update 0. Read them that way.
- **S38–S41's decoders** probed h at KEY (3j+1) and CTX (3j) positions, never at VAL (3j+2), where the write is labelled. For the plain recurrent gate "not decodable at KEY implies not at VAL" holds; for the GATE_PREV arms, key-position decodability is 1.0 by construction (u_key = W_in e_KEY + W_prev e_CTX), so S40's "input decodes the stream at 0.97–1.00" is a tautology and the relevant positions were never measured.
- **S36 and S37** scored BOUND (`explore_split_target.py:217,268-273`) although the docstring of a later screen notes that a run bound with all four streams on one channel; the report's routed counts (6/10 vs 3/10, 6/10 vs 5/10) came from the per-seed tables and are correct. The split zeroes W_g's Adam moments *and step* in place, restarting bias correction for the whole matrix (the first update is ≈ lr·sign(g) on every row); S24 controlled this with its NOISE arm, S36/S37 did not.
- **S42** compares ρ(W_h) > 1 with |W_h h| > 1 at 50-update resolution and counts a tie as "ρ first"; σ_max(W_h) > 1 from initialization in ~97% of seeds. The reading "the stream is lost when ρ passes one" stands as a description (7 of 10 runs), but the 150-update rule is loose.
- **The harness** caches runs by `arm|seed` only (`explore_common.py:214`); the code SHA is stored once and never compared, so a cached run from older code can be reused silently, and a failed run (ok = False) is cached and never retried. Add the code SHA (and CPU) to the cache key.

### 2.4 Mis-aimed effort

Five screens over batches 7–13 (S21, S24, S27, S36, S37) tried to break merges at k = S = 4. Merges at k = S are the mixture-of-experts "expert collapse" problem, and the standard remedy is overprovisioning (more experts than needed), which is exactly what k = 16 did (9/80 merged against 32/80). A language model would use k ≫ S anyway. The merge work is justified only by the eight-stream coarse split at k = 16, and there the cause turned out to lie upstream (the gate state). Recommendation: treat spare channels as the merge fix, keep the targeted split (KEYMASS) as a tool, and stop screening merge-breakers at k = S.

## 3. Beliefs the records do not support, and the paths they closed

### 3.1 "The gate must be recurrent"

**Record.** Batch 1, screen S1 (`explore_local_gate.py`, LOCAL3): the gate computed from a width-3 causal convolution of the embeddings, h_t = tanh(W_in Σ_{j<3} w_j ⊙ v_{t−j}), g_t = softmax(W_g h_t), no recurrence. Seeds 160–179, plain Adam 1e-3, no recipe: DISCOVERED 15/20 against arm A's 7/20 (12 vs 4, p = 0.077, "promising"). On the same twenty seeds, the full recipe later reached SLOW_HINGE 18/20 and SLOW_MEM 12/20. LOCAL3 bound faster (median transition 2400 against 3600). Its five failures were four KEY splits and one run routed perfectly (margin 1.0, η² by stream 1.0) but not bound. It cannot position-split (the window carries no position), and its docstring predicted exactly this failure profile.

**Why it was dropped.** Batch 2 ran it on the header layout: 2/10 bound, both by key splits. The recurrent gate also bound 0/10 there, and no gate has solved the header layout since.

**What this means.** Every obstacle the main line has worked on since Revision 6 is a property of the recurrent parameterization: the position splits that the hinge removes are the recurrence counting triples; the eight-stream loss of the stream is the recurrence becoming expansive. A window gate can do neither. The recipe-scope test showed that slow memory prevents key splits (Q2). So the natural combination, never run, is **LOCAL3 + SLOW, with no hinge**. If it works, the recipe no longer needs the hinge's key positions, which removes item 2 of Revision 7's "what stands in the way", and the gate becomes a convolution: parallel, cheap, and the shape every modern linear-attention model already uses for its gates (Mamba, H3, RWKV's token shift).

**Prediction (fixed here, before any run):** LOCAL3 + SLOW at S = 2, P = 4: ≥ 36/40 on seeds 160–199, with KEY failures gone. At S = 8, k = 16 the state of a window gate carries the stream at every write position by construction, so if Revision 7's diagnosis is right it should bind on some seeds where every recurrent arm bound none. If it does not, the eight-stream problem is not (only) the gate's memory, and §3.4's knobs are next.

**What it does not solve:** distant cues. Neither gate does; §3.3 is the path for those.

### 3.2 "The gate needs only one token of memory"

Revision 7, Section 11: "Since each key's own stream token sits one position earlier, the gate needs only one token of memory." The read happens at the query's KEY position (`test_binding_capacity.py:218`: qpos = 3(SP+j)+1; the model predicts tokens[qpos+1]; "?" is never an input), where CTX is one back. But the write that must carry the stream is at the VAL position, where CTX is two back, and the project's own routing criterion (the stream-to-channel map) is measured at VAL positions (`test_scale_axes.py:292-297`). So: one token at the read, two at the write. Consequences: S41's NOREC is predetermined (§2.3); S38–S41 never decoded the write positions; the sentence in Section 11 and the S40 bullet need correcting. The fix is cheap: rerun the decoder at VAL positions on the recorded configurations (S47 below).

### 3.3 "A gate that is a function of the token cannot express the routing"

Phase I showed this for a one-layer model whose gate read the embedding. The main-line gate still reads `embed(tokens)` — raw, not LayerNormed, not convolved (`test_multilayer_binding.py:323-325`) — and a single G = g_t·g_s is built once and applied at all three layers through the shared attention module (`:330-331`). The router gets no information from the stack.

In a three-layer model the residual stream at layer 2 already carries recency-mixed context (that is how the single channel binds at 4e-3 through the conv, and how the no-conv gate binds at all), and in the header layout, layer 1's attention can copy a block's header into every position. A **per-layer gate over the residual stream** — the design of MoM, Raven, SSE and Triadic Linear Attention — has never been tried here, and it is the only route to distant cues that does not require the gate's own recurrence to hold a token for 3P steps. Risk: `test_readout_path` showed that gradient coupling *from* the gate's state *into* the residual harmed the gate; the reverse coupling is different but untested, so run it with and without a stop-gradient into the stack. Triadic Linear Attention is evidence that a content-based second key, read from the hidden state at every layer, works at language-model scale.

### 3.4 "Eight streams fail because of the gate"

True as far as it goes (the perfect gate binds; the learned gate's state loses the stream), but incomplete:

- **Learning rate.** Every eight-stream run used Adam 1e-3 or Muon 0.005. At two streams, conv_lr showed 4e-3 changes the outcome qualitatively. Okpekpe & Orvieto (arXiv 2508.19029) report that recall failures in modern recurrent models are often an optimization problem with a narrow rate window. A sweep at eight streams (3e-4, 1e-3, 3e-3; W_h at a tenth of the gate's rate as a fourth arm) costs about a day on E.
- **Decay.** 0.95 has been fixed since Phase III. On 99-token sequences the earliest same-stream triple carries 1/118 of the latest one's recency weight, with no softmax to sharpen the mixture; LayerNorm removes the absolute attenuation but not the ratio. The perfect gate still binds, so the memory copes with perfect routing; with partial routing the memory's early signal is weak, which lengthens the race the recipe relies on. Decay 0.98 (half-life 34) is a one-line change. A learned per-channel decay (Gated DeltaNet's forget gate) is the longer-term fix for the "memory horizon" limitation.
- **Capacity.** Barnfield et al. (arXiv 2605.05189) give a sharp threshold for a d×d outer-product memory: top-1 retrieval of n pairs needs d² ≈ n log n. Our per-channel state is 256×32; at S·P = 32 pairs this is not binding, but the formula tells us where it will be as P and S grow.

- "Timing does most of the work, the direction adds the rest" was overstated in the draft of Revision 7 and corrected; the random-kick control was 1 vs 3 against the hinge.
- "The hinge barely takes part under Muon" (batch 9) was wrong; a few early firings were the mechanism (S32, S34). Corrected in Revision 7.
- "X and L are independent replicates" — corrected; disjoint seeds from test_muon_recipe on.
- "Muon's bf16 kernels explain X–L differences" — corrected; X and L never reproduced each other under Adam either.
- "S24 is a label-free merge breaker" — it was not until a trigger existed, and the first trigger was wrong; the targeted split (KEYMASS) now aims correctly in 10 of 11 cases but its benefit beyond the optimizer reset is unmeasured (§2.3).

## 4. Literature that should change what we do or cite

Verified by search this week: Triadic Linear Attention (2609.36529), Raven (2607.25357), Sharp Capacity Thresholds (2605.05189), Dimension-Free Saddle-Point Escape in Muon (2605.09331), and the ICML 2026 paper on Muon and balanced expert usage. The other identifiers come from the sweep's search snippets; check each when citing.

**Must cite and differentiate**
- *Triadic Linear Attention* (Sieberling et al., 2609.36529): three-dimensional recurrent state k ⊗ k₂ ⊗ v, E separately gated slices, MQAR capacity grows with E. Our (x·x)(g·g) score is this form with g as the second key. Difference: our g is a recurrent softmax over the sequence context; theirs is a learned projection of the token; our subject is label-free discovery of the partition.
- *Raven: High-Recall Sequence Modeling with Sparse Memory Routing* (2607.25357): per-token learned top-k router over memory slots; Gumbel noise is its only anti-collapse device. The nearest architectural neighbour and a natural baseline; its noise is on the router logits (ours in S26 was on the weights).
- *Sparse State Expansion* (2507.16577), *Mixture-of-Memories* (2502.13685): content-routed multi-memory baselines. We must show why a context-tracking gate beats a content-only router on the stream task.
- *Gated DeltaNet* (2412.06464), *DeltaProduct* (2502.10297), *Titans* (2501.00663): single-memory baselines. The delta rule overwrites a key's value, so it cannot keep two bindings of the same key; that is exactly the partition's selling point and should be shown head to head.
- *BDH-CQ* (Pathway, 2608.09888): the official follow-up; eight simultaneous bindings in BDH's memory; cite as the comparison point.
- Prior art for the mechanism: Ba et al. 2016 fast weights (1610.06258); Schlag, Irie & Schmidhuber 2021 (2102.11174); three-factor / neuromodulated plasticity (Frémaux & Gerstner 2016; Gerstner et al. 2018); Miconi et al. differentiable plasticity (1804.02464) and Backpropamine (2002.10585); Masse et al. 2018 context-dependent gating (1802.01569) — the gate is a vector neuromodulator and XdG is its supervised ancestor; Chaudhary 2025 (2510.21908), a neuromodulated Hebbian module in a decoder transformer.
- Theory of the stationary point: Chen et al. 2022 (2208.02813) on when MoE routers do not collapse; Ziyin 2024 (2309.16932) on symmetry-induced stationary subspaces (keep weight decay off the gate; ours is zero); Long, Gu & Xie 2026 (2605.09331): Muon escapes flat saddles in O(1) steps against O(D) for element-wise methods — a theoretical reason for our Muon result; the ICML 2026 Muon/MoE paper: router balance is set by the effective rank of the router's inputs, and Muon preserves it.

**Techniques to try**
- *LRU* (Orvieto et al. 2023, 2303.06349) and block-diagonal LRNNs (2602.12021): recurrences whose eigenvalues stay inside the unit disk by construction, computed by a parallel scan. The principled version of S41's cap and of the "contractive or parallel gate" Revision 7 asks for. Caution from 2603.01959 and 2505.21749: diagonal transitions cannot track non-Abelian state; stream identity across interleaved streams may need input-dependent (bilinear or Householder) transitions.
- *Parallel evaluation of nonlinear RNNs* (DEER 2309.12252; quasi-DEER/ELK 2407.19115): removes the token-by-token gate cost without changing the gate.
- *Auxiliary-loss-free balancing* (DeepSeek, 2408.15664): a per-channel bias nudged by usage; label-free, gradient-free, per-token at inference. Fits k = S only (it pushes toward uniform usage).
- *Gradient reversal* (DANN, 1505.07818) and *HSIC* (1910.00270) as generic replacements for the hinge: an adversary or a kernel independence penalty between g_t and position, using only position, which a language model always has. Validate with a fresh probe, not the training adversary (Elazar & Goldberg 2018, 1808.06640).
- *K-facts interference protocol* (Lee et al., 2609.33093): competition among simultaneously active facts dominates recall in gated linear attention; adopt it when comparing against heads-as-channels.
- *Two-timescale theory* (2605.15530, Stackelberg view of layer-wise rates): formal backing for "memory at lr/10, gate fast".

## 5. Methodology and process

- **Statistics.** About sixty pre-registered one-sided claims per machine at α = 0.05: two or three false positives expected under the global null. The conclusions that matter are replicated on both machines or come from disjoint-seed pooled tests; keep it that way. Print Wilson intervals with every band: "RELIABLE" at 18/20 has a lower bound of 0.70.
- **Bit-for-bit pairing** has served the CPU phase well (it caught the thread-count nondeterminism and the file mix-ups). It blocks pooling across machines, cost batch 15 its 2.80 GHz runs, and will not exist on a GPU. From here, pair within a machine where recorded runs exist, and otherwise run disjoint seeds and pool.
- **Specifications.** Two were lost in relay. Commit each test's specification to `specs/<test>.md` before the test is written; the agent reads it from the repository. This also makes the pre-registration verifiable by commit hash, which is worth more than the convenience.
- **L's results.** The four remaining Phase V files were committed while this audit was being written (`d0e6c85`). A `record_L.py` that copies a file into `results/L/`, checks its CPU label, and appends the row to `results/README.md` would make L's side a one-liner from now on.
- **Code structure.** Tests import tests (`test_muon_recipe` → `test_early_recipe` → `test_slow_start` → …), each 1000–1500 lines, with hundreds of CHECKs. Do not refactor the CPU main line (it would break the pairing chain); build the GPU port as a small package (`model`, `task`, `metrics`, `stats`, `harness`, `checks`) from the start.
- **Harness.** Key the cache by code SHA and CPU as well as `arm|seed`; retry failed runs; never cut an arm a claim depends on.
- **Reviews.** Local-model reviews are useful as devil's advocates when given the numbers; the two that arrived without them were wrong on their main points. The fact-check-by-independent-agent step before Revision 7 found about twenty-five overstatements and should stay in the workflow.
