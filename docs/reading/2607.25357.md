# Raven: High-Recall Sequence Modeling with Sparse Memory Routing (arXiv 2607.25357v1)

Afzal*, Bick*, Xing, Cevher, Gu (EPFL / CMU / Cartesia). 28 Jul 2026. 28 pages incl. appendices A.1–A.8. Read in full from `pdftotext -layout` output. Page numbers below are the paper's own (the "N" at each page break in the text file).

**One line.** Raven is a GSA/SWA-style dual-state linear-attention layer (a key state and a value state, each M = 256 "slots" per head) in which a per-token sigmoid + Top-K router chooses which slots a token is written to, and a Mamba-2-style scalar decay is applied *only to the written slots*. Routing is write-only; the read is a dense softmax over all slots. The only anti-collapse device is Gumbel(0,1) noise on router logits during training. Evaluated by 400M/800M LM pretraining on SlimPajama and zero-shot recall/NIAH; no synthetic training tasks, no MQAR, no context-partition experiments.

## 1. What the paper actually does

### 1.1 The RSM framework (Sec. 3, pp. 4–6)

State per head: S_t ∈ R^{M×d}, "each row S_t[i] is an independent memory slot" (p. 4). General update S_t = g_t(S_{t−1}, x_t), o_t = f(S_t, x_t) (Eq. 7).

- **Def. 1 (slot-separable):** S_t[i] = g_{t,i}(S_{t−1}[i], x_t) (Eq. 8). **Prop. 1:** for the linear update S_t = D_t S_{t−1} A_t + U_t (Eq. 9), slot-separable ⇔ D_t diagonal (Eq. 10; proof A.2, p. 23). "Equation (9), which incorporates decays on both sides of the linear update, was also introduced by Zhong et al. (2025)" (p. 4).
- **Def. 2 (Router):** "A router r_t = r(x_t, t) ∈ R^M is a vector that determines, at each time step, how new information is distributed across slots. The entry r_t[i] specifies the write intensity for slot i ... Routers may depend on the current input x_t (input-dependent routing) or only on time t (time-dependent routing)." (p. 4)
- **Def. 3 (RSM), Eq. 11:**
  `S_t = (1 − r_t) ⊙ S_{t−1}  +  r_t ⊙ ( D_t S_{t−1} A_t + U_t )`  (preserved memory + updated memory), ⊙ broadcasting row-wise, D_t ∈ R^{M×M} diagonal, A_t ∈ R^{d×d}, U_t ∈ R^{M×d}, r_t ∈ R^M.
  "when r_t[i] = 0, slot i is frozen—its content persists exactly. When r_t[i] = 1, it is fully updated. Intermediate values interpolate. A slot written at time j retains its content until the router selects it again, enabling long-lived storage with targeted updates." (p. 4)

Existing models as RSMs (Table 1, p. 6; Secs. 3.3–3.4): SWA = one-hot time-dependent router e_t (t mod M), no decay (Eq. 12); ABC = r_t = softmax(W x_t), dense, no decay (Eq. 13); GSA = r_t = σ(W x_t)^{1/τ}, dense (Eq. 14); SSMs (Mamba-2, GLA, LinAtt, RetNet) = dense all-ones router r_t = 1_M with scalar/diagonal decay (Eqs. 15–16); DeltaNet = dense router with rank-one forget `S_t = S_{t−1}(I − β_t k_t k_t^⊤) + β_t v_t k_t^⊤` (Eq. 17). Thesis: "The missing combination—sparse, input-dependent routing paired with explicit decay—is precisely what Raven introduces" (p. 6). (Table 1's Raven row is garbled by the extraction; from Eqs. 18–21 it should read Router g_t/1^⊤g_t, Content [k_t v_t]^⊤, Decay I (A_t = I; the slot-wise decay lives in the router term), Readout (S^v_t)^⊤ f(S^k_t q_t).)

### 1.2 The Raven recurrence (Sec. 4.1, p. 6; boxed in A.4, p. 24) — exact equations

```
Raven Recurrence (A.4, p. 24):
  m_t = σ(W x_t),
  g_t = { m_t[i]  if i ∈ TopK(m_t) ;  0.0  otherwise },
  r_t = g_t / ( α Σ_{i=1}^{M} g_t[i] ),
  a_t = −SoftPlus(w^⊤ x_t) · exp(∆),
  S^k_t = exp(a_t r_t) ⊙ S^k_{t−1} + (1 − exp(a_t r_t)) k_t^⊤ ,
  S^v_t = exp(a_t r_t) ⊙ S^v_{t−1} + (1 − exp(a_t r_t)) v_t^⊤ ,
  o_t  = (S^v_t)^⊤ softmax( S^k_t q_t ).
```

Eq. (18), p. 6, is the two state updates with "readout o_t = (S^v_t)^⊤ softmax(S^k_t q_t), where ⊙ broadcasts over the feature dimension d. When r_t[i] is large, slot i is decayed and overwritten. When r_t[i] ≈ 0, exp(a_t r_t[i]) ≈ 1 and the slot is left untouched. Raven uses separate SWA-like states for writing keys and values."

Eq. (19), p. 6 (decay): `a_t = −SoftPlus(w^⊤ x_t) exp(∆)`, "∆ is a learnable scalar, as in Mamba-2. Since a_t enters the recurrence only through exp(a_t r_t), unselected slots (r_t[i] = 0) experience no decay regardless of a_t; their content is frozen until the router selects them." Note the *write* coefficient is exactly the complement of the decay: each slot is an input-rate EMA of the keys (resp. values) routed to it; the slot never accumulates magnitude (convex combination), unlike an outer-product Hebbian state.

Eq. (21), p. 8 (unified "write-and-forget" form, state transposed to d×M): `S_t = S_{t−1}(I − P_t) + v_t p_t^⊤`, with SWA: p_t = e_t, P_t = e_t e_t^⊤; **Raven: p_t = 1 − exp(a_t r_t), P_t = diag(p_t)**; DeltaNet: p_t = k_t, P_t = k_t k_t^⊤. "Raven occupies the middle ground: P_t is diagonal (not rank-one), sparse (at most K nonzero entries), and input-dependent." In RSM terms, Raven is GSA's Eq. (14) with the dense router σ(W x_t)^{1/τ} replaced by the sparse p_t = 1 − exp(a_t r_t).

Unrolled form (Sec. 7.1, p. 14): `S_t[i] = Σ_{j=0}^{t} k_j (1 − exp(a_j r_j[i])) ⊙ exp(Σ_{ℓ=j+1}^{t} a_ℓ r_ℓ[i])` — "Since r_t[i] ≠ 0 only when slot i is selected, S_t[i] depends only on tokens routed to it."

### 1.3 The router — answers to the specific routing questions

- **What the router reads.** `m_t = σ(W x_t) ∈ R^M` (Eq. 20, p. 7), where x_t ∈ R^{d_model} is the sequence-mixer input at that layer — the same vector that is projected to q_t, k_t, v_t and to the decay a_t (Sec. 2.1, p. 2: "the token x_t ∈ R^{d_model} is linearly projected to q_t, k_t ∈ R^d and v_t ∈ R^M"). So the router reads the residual stream at that layer, through a single linear layer (the MLP variant `m_t = f(W_2 GELU(W_1 x_t + b_1))` is ablated, p. 12). Each (layer, head) has its own router and its own slots ("We use four heads per block and separate per-head hidden states S^v_t and S^k_t", p. 25). Nothing is shared across layers.
- **Context beyond the current token: none, explicitly.** No short convolution ("Raven drops these entirely", p. 7), no recurrent router, no positional input (Def. 2 allows r(x_t, t), but the only time-dependent router in the paper is SWA's e_t). The stated goal is "input-dependent, so that the model can learn to route by content rather than by position" (p. 7). Position enters only through decay: Raven "replaces RoPE-based position handling with decay that implicitly encodes relative position" (p. 10). Inference (mine): in the standalone model there is no positional embedding at all, so the layer-1 router is a function of the token embedding alone; any context-dependence of routing at deeper layers comes from the residual stream carrying lower-layer reads. The paper never analyses this.
- **Number of slots.** M = 256 per head (default; "consistent with previous linear models at the 400M and 800M scales", p. 13), 4 heads, 24 layers, two states (k and v) each. Ablated M ∈ {128, 256, 512} under a fixed memory budget (Table 7).
- **Top-K.** Keep the K largest sigmoid scores, zero the rest, renormalise: `r_t = g_t / (α Σ_i g_t[i])` — "routing weights that sum to one over at most K selected slots" (p. 7) (to 1/α in general). "α ∈ R is a hyperparameter that normalizes the router as the training sequence length grows (similar to τ for GLA). We choose α = 1 for the 400M model and α = 4 for the 800M model." Default K = 32 in the ablations ("K = 32 (out of M = 256 slots, i.e., 12.5% occupancy) strikes the best balance", p. 13); but see §6 — the headline Table 2/3 numbers match the K = 128 row of Table 7.
- **Sigmoid vs softmax.** Sigmoid (DeepSeek-V3 style) is the default; softmax `m_t = softmax(W x_t)` (Eq. 22) ablated and worse.
- **Gumbel noise.** Eq. (23), p. 12: `m_t = f(W x_t + n), n ∈ R^M ∼ Gumbel(0, 1)`, "where f(·) is sigmoid or softmax". Added to the **logits**, before the nonlinearity and before Top-K. **Scale fixed at Gumbel(0,1); no temperature, no annealing schedule is mentioned anywhere.** Train-only: "It is removed at inference for deterministic routing."
- **Straight-through?** Not mentioned anywhere in the paper. Inference: as in standard MoE KeepTopK gating, the selection is a hard mask but the kept weights m_t[i] are themselves differentiable, so gradients reach W only through the selected entries (and through the renormalisation); unselected slots receive no gradient from that token. No STE, no Gumbel-softmax relaxation is used despite citing Jang et al. (2016) — the Gumbel sample is used purely as exploration noise.
- **Writing selected slots.** Both states are written with coefficient `1 − exp(a_t r_t[i])` (slot-wise EMA of k_t and of v_t). The slot's decay and its write intensity are one number.
- **Do slots have their own forget gates?** No. One scalar a_t per head per token (Mamba-2 parametrisation, Eq. 19; the GLA-style `A_t = σ(W x_t)^{1/4}` is ablated and worse, Table 5). The effective per-slot decay is `exp(a_t r_t[i])` = head decay × routing weight. So "where" (r_t) and "how long" (a_t) are separate parameters but multiply into a single per-slot rate.
- **Reading / combining slot outputs.** `o_t = (S^v_t)^⊤ softmax(S^k_t q_t)`: slot scores S^k_t q_t ∈ R^M, softmax over all M slots, output is the softmax-weighted sum of the M value-slot vectors. **The router is not used at read time; reads are dense.** Then output gating and (standard) output projection (A.6: "We use QK normalization and apply output gating in the RSM block", p. 25). Empty (zero) slots are *not* masked: "empty slots contribute a value of 1 in the readout (since exp(0) = 1 in the softmax) ... we observed no difference when omitting this mask and using zero-initialized states directly" (p. 26).
- **Efficient form (A.5, p. 25).** Two GLA passes (as in GSA): `o′_t = GLA{q_t, k_t, 1 − exp(a_t r_t), exp(a_t r_t)}`, `o_t = GLA{softmax(o′_t), v_t, 1 − exp(a_t r_t), exp(a_t r_t)}`, i.e. implementable with flash-linear-attention GSA kernels.

### 1.4 Anti-collapse: what is and is not there

- **Only device: Gumbel(0,1) logit noise in training** (Sec. 6.2.2, 7.3). Motivation: "routers can collapse onto a small subset of slots early in training and never recover — a well-known failure mode in MoEs (Shazeer et al., 2017). In our setting, router collapse is particularly harmful: slots that are never selected remain uninformative, permanently reducing the effective memory capacity of the model." (p. 12)
- **No load-balancing loss, deliberately**: "Unlike MoE routers, Raven omits a load-balancing loss ... uniform memory allocation is counterproductive here: Raven intentionally routes unevenly. Retrieval-critical tokens (e.g., passkeys) are routed to dedicated slots and protected from overwrite, while general content is distributed across shared slots." (p. 7) "forcing equal ESL across slots would prevent the emergence of retrieval slots and expose stored tokens to unnecessary overwrite" (p. 15).
- **No capacity factor, no slot dropout, no auxiliary/z-loss, no router-specific learning rate, no router initialisation details.** The word "dropout" appears only in A.7's interpretation of the router as "a form of selective Dropout ... into the online learning loss" (p. 26).
- **Measurement of usage/collapse/specialisation.** Qualitative only. Def. 4 (p. 14): effective sequence length `T_Eff(i) = ‖r_i‖_0 = Σ_{t=1}^{T} 1[r[i,t] ≠ 0]` (Eq. 24). Figures 5, 8 (normalised ESL per slot, NIAH-1 sample at 16K, 400M, layers 1/12/24 × 4 heads) show "three regimes ... short ESL (red), long ESL (green), and intermediate (blue)" (p. 14); "head 3 in layer 24 activates only a few memory slots to store tokens. In contrast, other heads, such as head 4 in layer 1, activate many more slots" (p. 27). Figures 6, 7: on a passkey prompt, "some slots specialize as retrieval slots, receiving almost exclusively passkey tokens ... while others are reserved for non-retrieval content ... Shared slots (blue) are rare in heads with strong retrieval behavior" (p. 14); "only a few heads are responsible for retrieving and storing passkey tokens without overwriting them ... some heads, such as head 2 in layer 24, do not allocate dedicated memory slots for retrieval tokens; instead, they automatically use shared memory for both retrieval and regular tokens" (p. 28). **No numbers** (no fraction of dead slots, no entropy, no usage histogram values, no training-time curves) are given; the x-axis of Figure 8 runs 0–128 although M = 256 (unresolvable from the text). The Gumbel ablation (Table 6) is the only quantitative evidence about collapse, and it is indirect (task accuracy).

### 1.5 Block design (Sec. 4.2, A.6)

Gated MLP channel mixer, SiLU, optional QK-RMSNorm, output gating, skip connections, **no short convolutions** ("Raven attains state-of-the-art retrieval without them, suggesting that input-dependent routing and per-slot decay are sufficient to address the recall bottleneck: the first controls where information is written, and the second controls how long it persists", p. 9). Llama tokenizer. Hybrids: Raven interleaved with two full NoPE attention layers (or SWA).

### 1.6 Training details (A.3, pp. 23–24)

SlimPajama-627B. 400M: 15B tokens, seq 2048; 800M: 32B tokens, seq 4096. Batch 0.5M tokens. Adam, lr 4×10⁻⁴ (same for everything; no router-specific lr), cosine schedule, **1B tokens warmup** (≈2000 steps; ≈6.7 % of the 400M run). 24 layers (Mamba-2: 48), 4 heads. Memory budget matched: 12.5M recurrent elements total (≈0.52M/layer) at 400M, 16.5M at 800M (Table 2 caption). Codebase flash-linear-attention. **No instability, no sensitivity to the Gumbel scale, no loss curves, no seeds/variance are reported.** Router W and ∆ initialisation not given (only "as in Mamba-2").

### 1.9 Test-time-training view (A.7, Table 10, pp. 26–27)

Linear attention `S_t = S_{t−1} + k_t v_t^⊤` (Eq. 27) "can be viewed as a single step of gradient descent on the online loss L(S) = −⟨S k_t, v_t⟩, S_t = S_{t−1} − ∇_S L(S)" (Eq. 28). Table 10 (extraction garbled; reconstructed from the surrounding text and the visible fragments): LinAtt L = −⟨S^⊤ k, v⟩; RetNet/Mamba-2 add ½‖√(1−a) S‖²_F giving S_t = a S_{t−1} + β k v^⊤; GLA uses Diag(1−a_t); **Raven: L = −(1−exp(a_t r_t))⟨S_{t−1}^⊤ k_t, v_t⟩ + ½‖√(1−exp(a_t r_t)) S_{t−1}‖²_F, update S_t = S_{t−1} Diag(exp(a_t r_t)) + (1 − exp(a_t r_t)) k_t v_t^⊤.** "The router in Raven extends this objective by introducing a form of selective Dropout ... when slot i is not selected (r_t[i] = 0) the regularizer vanishes, so that slot incurs no weight decay and its content is preserved exactly. One can look at Raven update as applying sparse TTT and only updating selected slots." (p. 26). Delta-rule models use `L(S) = ½‖S^⊤ k_t − v_t‖²` (Eq. 29), "connections to Associative Memory introduced in Hopfield Networks"; they refer to "Table 7 of Team et al. (2025) [Kimi Linear] for more details on the TTT framework."

This competitive structure is natural in MoEs — where experts should not all fire at once — but is less appropriate for memory, where independent slot assessment is preferable."

## 3. Relevance to the BDH-CQ reconstruction

**What matches Pathway's wording.**
- The TTT framing of A.7 is independently the same framing as BDH-CQ's "linear attention being the conceptually simplest standalone realization": Raven writes `S_t = S_{t−1} + k_t v_t^⊤` as "a single step of gradient descent on the online loss L(S) = −⟨S k_t, v_t⟩" and says "By varying the choice of online objectives and the corresponding gradient-based update rules, a broad family of linear recurrent models can be recovered" (p. 26). Pathway's general form S_t = U_θ(S_{t−1}, D_t) with "linear correction rules on S" reads most naturally as exactly this template: S_t = S_{t−1} − η ∇_S L(S_{t−1}; D_t) with L quadratic in S, which is affine in S_{t−1}. Table 10 is a ready-made menu of such rules: Hebbian (LinAtt, special case S_t = S_{t−1} + U(D_t)), Hebbian + weight decay (RetNet/Mamba-2/GLA/Raven), and error-correcting delta rule (`L = ½‖S^⊤ k_t − v_t‖²`, Eq. 29 → S_t = S_{t−1}(I − β k k^⊤) + β v k^⊤, Eq. 17), which Raven explicitly links to "Associative Memory introduced in Hopfield Networks". The word "correction" fits the delta/Hopfield rule (Eq. 17 / Eq. 29), not Raven's own rule.
- Eq. (9)/(11)'s two-sided linear update `S_t = D_t S_{t−1} A_t + U_t` (credited to Zhong et al. 2025, arXiv 2505.19488) is a general "linear rule on S"; Raven points to that paper as the origin — a candidate reference for what Pathway may mean.

**What does not match.**
- Raven's own update depends on S_{t−1} only through a diagonal, input-dependent decay (`S_{t−1}(I − P_t)` with P_t diagonal, Eq. 21). It is Hebbian write + routed forgetting, not an error-correcting rule; there is no S_{t−1}-dependent write content. So Raven is *not* an instance of a non-trivial U_θ(S_{t−1}, D_t) beyond what Mamba-2/GLA already are.
- Nothing in Raven resembles the latent loop H_0 = E(x*, S_K), H_{r+1} = F(H_r, S_K), ŷ = G(H_R). Readout is single-shot `o_t = (S^v_t)^⊤ softmax(S^k_t q_t)`; there is no iterative refinement, no multi-step read, no reasoning benchmarks (no Sudoku/ARC).
- The one structural idea possibly useful for the reconstruction: Raven's readout is a *nonlinear* (softmax) read over slots of a *linearly* updated two-part state (key-slots and value-slots) — the "higher-order linear attention" class (Zhang, Qin, Gu 2025b, arXiv 2510.27258, cited p. 16: "multiple coupled memories are updated by a linear recurrence (without requiring a softmax-free attention readout)"). If BDH-CQ's S_K is read by a nonlinear F_θ repeatedly, a softmax-over-slots read of a dual state is one concrete, published template. This is my inference, not something the paper says about BDH-CQ (it never mentions BDH).

## 4. Relevance to distant context cues

**Which component carries information across distance, and at what time scale.** The frozen-slot mechanism: a slot not selected by the router is "frozen—its content persists exactly" (p. 4) with no decay "regardless of a_t" (p. 6). Its clock ticks in *writes to that slot*, not in tokens (Def. 4, ESL). So the horizon of a slot is unbounded until it is reselected; a selected slot is then EMA'd at rate 1 − exp(a_t r_t[i]) (per-head learned decay × routing weight; α scales the whole thing, α = 4 at 800M making writes/decays 4× gentler — inference: α is a global horizon knob analogous to GLA's τ, which is exactly how the paper describes it, p. 7). This is what produces the 16× length extrapolation: "different slots see different subsequence lengths" (p. 14).

**Is the context signal given or inferred?** Inferred, label-free, from LM pretraining alone — but at the **token level**, not the stream level. The router sees only x_t at that layer (Eq. 20), and the thing it learns to detect is "is this token retrieval-critical?" (passkey digits vs background text). Training: end-to-end next-token loss with Gumbel exploration noise; no auxiliary loss, no supervision ("without any explicit supervision to do so", p. 15).

**What is absent.** (i) No mechanism to *carry a block/stream identity* across tokens inside the router: no conv, no recurrence, no router state. (ii) The paper never discusses "the same key needing different slots in different contexts". Its specialisation is by token type (retrieval vs non-retrieval), where the needle is identifiable from its own tokens — in NIAH the cue and the content coincide. (iii) In the standalone model the layer-1 router is (inference) a function of the token embedding only, i.e. exactly our raw-embedding gate with window width 1. Any context-dependence at deeper layers must come from the residual stream carrying lower-layer reads — which is precisely our untried "per-layer gate over the residual stream" idea; Raven shows it trains stably at scale, with different heads/layers specialising differently (Fig. 7, p. 27: layer 24 head 2 uses shared slots; "only a few heads are responsible for retrieving and storing passkey tokens", p. 28) — but gives no evidence that such a router ever learns a *context partition*.

**Prediction for our header layout (mine).** A Raven router dropped into BindTask-header would route by token identity (key splits), as our window gate did (2/10 by key splits), because nothing in m_t = σ(W x_t) at layer 1 can see CTX_s. The paper's design doesn't solve our distant-cue problem; it does make the residual-stream per-layer router the most natural place to look for a solution, and adds a second idea — routed decay — that increases the *payoff* of a correct partition (a stream's channel stops decaying while another stream's block is being processed), without by itself making the partition discoverable.

## 5. Relevance to our gate

### 5.1 Side-by-side

| | Ours (k channels) | Raven |
|---|---|---|
| Gate input | raw token embedding v_t (window gate: v_{t−2..t}; recurrent: h_t) — one gate for all layers | residual-stream input x_t of that layer, per layer *and* per head |
| Scoring | softmax over k (competitive) | sigmoid per slot (independent) + Top-K + renormalise to 1/α |
| Sparsity | soft (hard only in oracle) | hard Top-K (K = 32–128 of 256), train and test |
| Exploration | plateau-triggered split (copy busiest row to emptiest + noise on weights); slow memory lr | Gumbel(0,1) noise on logits every token, train only, fixed scale |
| Balance | spare channels (k = 16 for S ≤ 8) | no load balancing, "intentional imbalance"; many slots (256) |
| Decay | fixed 0.95 everywhere | exp(a_t r_t[i]): learned per-head input-dependent, applied only to written slots |
| Write | g_t[c] · outer product (Hebbian accumulation) | EMA of k_t and of v_t into slot (convex) |
| Read | g_t · g_s gating on both sides: score = (x_t·x_s)(g_t·g_s)decay^{t−s} | dense softmax over all slots; routing not used at read time |
| Memory unit | channel = full associative matrix | slot = one key vector + one value vector |

The read-side difference matters most. Because Raven reads densely, if the same key k were written into S slots (one per context) the read scores q·S^k[i] would be equal for all S slots and the softmax would *average the S values* — Raven's routing cannot disambiguate conflicting bindings at read time; only context mixed into q_t and k_t by lower layers can. Our g_t·g_s acts on both write and read, which is exactly what BindTask needs. Raven therefore does not test, and would not by itself solve, our research question; our design is strictly more suited to it. (Inference from the equations.)

### 5.2 What to borrow (concrete)

1. **Routed decay (the main transferable idea, directly addresses "memory horizon" and partly "distant cues").** Replace the fixed per-channel decay with Raven's Eq. 18/19 pattern: channel c decays only in proportion to how much is written to it.
   `M^{(c)}_t = exp(a_t · g_t[c]) · M^{(c)}_{t−1} + g_t[c] · (write_t)`, `a_t = −softplus(w^⊤ u_t) · exp(∆_c)` (u_t = gate input; ∆_c learnable scalar per channel, or one ∆ per layer as in Raven).
   The pairwise score becomes `score(t,s) = (x_t·x_s) Σ_c g_t[c] g_s[c] Π_{u=s+1}^{t} exp(a_u g_u[c])`: a binding in channel c survives untouched while other streams' blocks are routed elsewhere. Initialisation (mine, chosen to reproduce the current behaviour at g = 1): with w = 0, softplus(0) = 0.693, so set ∆ = ln(−ln 0.95 / 0.693) ≈ −2.6 to get exp(a) = 0.95 when g_t[c] = 1. Raven's ablation says the Mamba-2 softplus form beats the GLA sigmoid^{1/τ} form (Table 5: SWDE 31.5 vs 28.0, FDA 19.6 vs 11.5). Caveat: Raven's write is the complement 1 − exp(a_t r_t[i]) (EMA); our Hebbian accumulation can keep a separate write weight g_t[c], but then the state norm is no longer bounded by construction — keep our LayerNorm.

2. **Gumbel noise on gate logits instead of (or before) the plateau split.** `g_t = softmax(z_t + n_t)`, `z_t = W_g h_t`, `n_t ∼ Gumbel(0,1)` i.i.d. per token and channel, training only, no annealing (the paper uses none). For a softmax gate this is exactly a Gumbel-softmax sample at temperature 1 (Jang et al. 2016, arXiv 1611.01144). Why it may not need annealing (inference): fixed-scale noise self-anneals — once the gate's logit gaps exceed a few units, the argmax rarely flips. Two cautions specific to us: (a) in Raven a mis-routed write is still readable because reads are dense; in our model a noisy write to channel c′ is read only if the query is also routed to c′, so noise perturbs the score g_t·g_s on both ends — try noise on the write gate only (see item 5); (b) Table 6 shows the gain is not universal (FDA 13.8 vs 17.7 for the default router), so measure on the grouped task before adopting.

3. **Per-layer router over the residual stream.** Raven is an existence proof that `r_t^{(ℓ,h)} = f(W^{(ℓ,h)} x_t^{(ℓ)})`, with no conv and no recurrence, trains stably at 400M–800M with lr 4e-4 and no router-specific tricks, and that layers/heads specialise differently (Fig. 7, p. 27). Suggested transcription: `g_t^{(ℓ)} = softmax(W_g^{(ℓ)} · LN(h_t^{(ℓ)}))`, separate per layer (and per channel-group if we ever have heads), with layer 1's gate still fed the embedding (equivalently, h^{(1)}). Nothing in the paper tells us whether layer 1 copying a block header into later positions actually happens — that remains our hypothesis to test.

4. **Sigmoid + Top-K + renormalise as an ablation, not a replacement.** `r_t = TopK(σ(W x_t)) / (α Σ_i ·)`, with K = 1 or 2 of k = 16. The paper's argument for independent scoring ("less appropriate for memory, where independent slot assessment is preferable", pp. 11–12) is made for LM recall where a token may legitimately belong in several slots. For a *partition* task competition is the point, so I expect softmax to remain right for us; but the ablation is cheap and would tell us whether hard sparsity at train time helps or hurts the discovery of splits. Raven's own numbers warn against over-sparsity: NIAH-2 at 8K is 18.4 with K = 32 but 81.6 with K = 128 (Table 7).

5. **Decouple write gate and read gate (my inference from the comparison, not in the paper).** `score(t,s) = (x_t·x_s)(g^r_t · g^w_s)decay^{t−s}` with `g^w = softmax(z + Gumbel)` during training and `g^r = softmax(z)` (or a separate head). This isolates exploration to the write side as in Raven while keeping read-side routing, which Raven lacks.

6. **Many slots, no balancing — supported.** Our spare channels (k = 16 for S = 4, 8) are the analogue of Raven's "finer-grained router has more targets" (M = 256 ≫ K = 32) and of its explicit refusal of a load-balancing loss. Raven's Table 7 also warns that too many slots with too little capacity each collapses some tasks (512 slots: SQuAD 7.5 / 3.8), so k should not be scaled blindly if channel capacity shrinks with k.

7. **Inference-time hard routing.** Raven uses hard Top-K at train and test with no straight-through estimator; if our soft gate is sharp after training we can evaluate with argmax (top-1) without retraining — a cheap check of whether the learned partition is "really" discrete.

### 5.3 What they would gain from us

- A test of whether their router can discover *context partitions* rather than token-type specialisations: BindTask grouped/header layouts, with the perfect-gate oracle as a validity ceiling and key-split / position-split / stream-split diagnostics. Raven's write-only routing predicts failure on grouped BindTask unless lower layers inject context into q/k; that is a sharp, falsifiable claim.
- Our finding that a recurrent gate "counts positions" is a direct caution for anyone adding recurrence to a Raven router (they explicitly want "content rather than position", p. 7, but never test for position-based routing; their standalone model has no positional signal at layer 1 at all).
- Our training recipe (slow memory lr, early hinge, plateau-triggered targeted split) is an alternative anti-collapse mechanism they could compare against Gumbel noise, which they adopted without ablating alternatives.
- Read-side routing (g_t·g_s) as a way to disambiguate same-key slots, which their dense softmax read cannot do.

### 5.4 Supports / contradicts / warns

- **Supports:** sparse content-dependent write routing reduces interference and is learnable end-to-end without labels; no load-balancing penalty; spare slots; the per-layer residual-stream router is viable; a learned per-channel forget gate coupled to the gate ("decay only where you write") is the natural next step for our horizon problem; collapse happens "early in training" and does "never recover" — matches our merges at k = S and justifies spare channels/splits.
- **Contradicts / qualifies:** "competitive softmax is best" — Raven finds sigmoid better (for its task); "hard partition is ideal" — Raven's optimum is intermediate K and task-dependent; "routing must carry context" — for NIAH-type recall, token-type routing suffices (so good recall numbers are not evidence of context routing — the same caution as our P = 4 single-channel result).
- **Warns of:** (1) over-sparsity at long range; (2) "consistent gains" claims that are not consistent cell-by-cell — check per-task; (3) mixing a decay-positional linear layer with RoPE attention destroys extrapolation (Table 9) — if we ever add attention layers use NoPE; (4) unmasked empty slots in a softmax read act as a null sink (irrelevant unless we add a softmax read over channels); (5) the headline model may not be the "default" one (see §6) — a reminder to keep our own reported configs pinned.

## 7. Verdict

Raven does not touch our core question — it never asks whether a router can discover *which context* a token belongs to; its specialisation is by token type on tasks where the needle announces itself — and its routing is write-only with a dense read, so it could not even express the "same key, different contexts" disambiguation that our g_t·g_s does. What it gives us is (a) a clean, published, scale-tested recipe for a per-layer residual-stream router with hard Top-K, sigmoid scores, Gumbel(0,1) logit noise as the sole anti-collapse device, and no balancing loss — which raises my confidence that our planned per-layer residual gate is trainable and that Gumbel logit noise is worth trying as a cheaper, continuous alternative to the plateau split; and (b) one idea we should implement first: **routed decay**, exp(a_t g_t[c]) — decay a channel only in proportion to how much is written to it — which turns our fixed 0.95 horizon into a learned, write-triggered one and is exactly the mechanism behind Raven's 16× extrapolation. It will not by itself make the header-layout partition discoverable, but it should enlarge the gap between the oracle partition and a single channel (addressing our "task a single channel provably cannot solve" problem), and it is a few lines of code. Confidence: high that the mechanisms are correctly transcribed (the equations are explicit and boxed in A.4); moderate that Gumbel noise transfers to a softmax gate whose routing also governs reads; low-to-moderate that anything here helps the distant-cue problem beyond motivating the per-layer router. Keep in mind when citing numbers that the headline 400M configuration appears to be Top-128, not the Top-32 "default".
