## 1. What the paper actually does

### 1.1 The model (Section 3, pp. 2–4) — equations copied in the paper's notation

Three functional groups of decoder-only transformer blocks: a **prelude P** (embeds tokens into latent space), a **core recurrent block R** (iterated; "modifying states s ∈ R^{n×h}"), and a **coda C** (un-embeds + prediction head). Sequence length n, hidden dim h, vocabulary V. Given r recurrent iterations and tokens x ∈ V^n (p. 3):

```
e  = P(x)
s0 ∼ N(0, σ² I_{n·h})
si = R(e, s_{i−1})      for i ∈ {1, …, r}
p  = C(s_r),
```

"where σ is some standard deviation for initializing the random state. … Given an init random state s0, the model repeatedly applies the core block R, which accepts the latent state si−1 and the embedded input e and outputs a new latent state si. After finishing all iterations, the coda block processes the last state and produces the probabilities of the next token." (p. 3)

**Input injection (the concatenation + adapter), p. 4:** "Given an embedding matrix E and embedding scale γ, the prelude block first embeds input tokens x as γE(x), and then applies lP many prelude layers with the layout described above. Our core recurrent block R starts with an adapter matrix A : R^{2h} → R^h mapping the concatenation of si and e into the hidden dimension h (Bansal et al., 2022). While re-incorporation of initial embedding features via addition rather than concatenation works equally well for smaller models, we find that concatenation works best at scale. This is then fed into lR transformer layers. At the end of the core block the output is again rescaled with an RMSNorm nc. The coda contains lC layers, normalization by nc, and projection into the vocabulary using tied embeddings E^T."

So, in effect **[inference, restating the prose as an equation]**: s_i = n_c( TransformerLayers_{×lR}( A·[s_{i−1} ; e] ) ), with A a learned linear map on the concatenation. e is per-token (n×h): the same shape as s.

**Layer internals ("microscopic design", p. 3):** causal self-attention with RoPE (base 50000), gated SiLU MLP, RMSNorm, "learnable biases on queries and keys, and nowhere else." Every layer uses the **sandwich norm** (p. 3):

```
x̂_l = n2( x_{l−1} + Attn( n1(x_{l−1}) ) )
x_l  = n4( x̂_l + MLP( n3(x̂_l) ) )
```

"To stabilize the recurrence, we order all layers in the following 'sandwich' format, using norm layers ni, which is related, but not identical to similar strategies in (Ding et al., 2021; Team Gemma et al., 2024)" (p. 3). "While at small scales, most normalization strategies, e.g. pre-norm, post-norm and others, work almost equally well, we ablate these options and find that this normalization is required to train the recurrence at scale" (pp. 3–4). Footnote 2 (p. 4): "Note also that technically n3 is superfluous, but we report here the exact norm setup with which we trained the final model."

**Shapes.** Architecture summarized by the triplet (lP, lR, lC) and r. Small-scale models: (1, 4, 1), h = 1024. Large model: (2, 4, 2), h = 5280. "This model has only 8 'real' layers, but when the recurrent block is iterated, e.g. 32 times, it unfolds to an effective depth of 2 + 4r + 2 = 132 layers" (p. 4).

**Why re-inject e every step (p. 3)** — the two load-bearing passages:

> "This architecture is based on deep thinking literature, where it is shown that injecting the latent inputs e in every step (Bansal et al., 2022) and initializing the latent vector with a random state stabilizes the recurrence and promotes convergence to a steady state independent of initialization, i.e. path independence (Anil et al., 2022)."

> "**Motivation for this Design.** This recurrent design is the minimal setup required to learn stable iterative operators. A good example is gradient descent of a function E(x, y), where x may be the variable of interest and y the data. Gradient descent on this function starts from an initial random state, here x0, and repeatedly applies a simple operation (the gradient of the function it optimizes), that depends on the previous state xk and data y. Note that we need to use y in every step to actually optimize our function. Similarly we repeatedly inject the data e in our set-up in every step of the recurrence. If e was provided only at the start, e.g. via s0 = e, then the iterative process would not be stable¹, as its solution would depend only on its boundary conditions."
> Footnote 1: "Stable in the sense that R cannot be a monotone operator if it does not depend on e, and so cannot represent gradient descent on strictly convex, data-dependent functions, (Bauschke et al., 2011)".

**Design alternatives rejected (Remark 3.1, p. 3):** diffusion-style noise "si = R(e, si−1) + n where n ∼ N(0, σi In·h)" — "we find the injection of noise not to help in our preliminary experiments, which is possibly connected to our training objective." And a step-conditioned core "si = Ri(e, si−1), i.e. a core block that takes the current step as input (Peebles and Xie, 2023), but find that this interacts badly with path independence, leading to models that cannot extrapolate."

Motivation for the P/R/C split (p. 3): fixed-depth LLM analyses (Skean et al. 2024; Sun et al. 2024; Kaplan et al. 2024) show "the initial and the end layers of LLMs are noticeably different, whereas middle layers are interchangeable and permutable."

### 1.2 Training objective (Section 3.3, p. 4)

Random iteration count per sequence (Schwarzschild et al., 2021b):

```
L(θ) = E_{x∈X} E_{r∼Λ} L( m_θ(x, r), x′ )
```

x′ = x shifted left. Λ is a **log-normal Poisson**: "Given a targeted mean recurrence r̄ + 1 and a variance that we set to σ = 1/2, we can sample from this distribution via

```
τ ∼ N( log(r̄) − ½ σ², σ )        (1)
r ∼ P(e^τ) + 1,                   (2)
```

given the normal distribution N and Poisson distribution P" (p. 4; the extraction stacks the fractions — "σ = 12" and "− σ 2" with a "1" above — I read them as σ = 1/2 and ½σ²; Fig. 3 reports the sampled r̄ = 32 distribution: Mean = 33.0, Median = 29.0, Mode = 24.0). "The distribution most often samples values less than r̄, but it contains a heavy tail of occasional events in which significantly more iterations are taken."

**Truncated backpropagation (p. 4):** "we backpropagate through only the last k iterations of the recurrent unit. This enables us to train with the heavy-tailed Poisson distribution Λ, as maximum activation memory and backward compute is now independent of r. We fix k = 8 in our main experiments. At small scale, this works as well as sampling k uniformly, but with set fixed, the overall memory usage in each step of training is equal. Note that the prelude block still receives gradient updates in every step, as its output e is injected in every step. This setup resembles truncated backpropagation through time, as commonly done with RNNs, although our setup is recurrent in depth rather than time."

**Locked-step sampling (p. 5):** one r per micro-batch, synchronized across workers; "note that at large batch sizes, training could be further improved by optimally sampling and scheduling independent steps r on each worker, to more faithfully model the expectation over steps in Equation (1)."

### 1.3 Training details that matter (Section 4, pp. 4–6; App. A.2, pp. 24–25)

- **Main model:** (2, 4, 2), h = 5280, 55 heads × 96, MLP inner 17920, RMSNorm ε = 1e−6, r̄ = 32. "about 1.5B parameters in non-recurrent prelude and head, 1.5B parameters in the core recurrent block, and 0.5B in the tied input embedding" (p. 5). Vocab 65536 (BPE trained on the instruction split), sequence length 4096, `<|begin_text|>` at each document start; document tails without context discarded ("grounding problem", Ding et al. 2024).
- **Initialization at scale (p. 5):** Takase et al. (2024) "Spike No More": "a variance of σ_h² = 2/(5h). We initialize all parameters from a truncated normal distribution (truncated at 3σ) with this variance, except all out-projection layers, where the variance is set to σ_out² = 1/(5hl), for l = lP + r̄lR + lC the number of effective layers, which is 132 for this model. As a result, the out-projection layers are initialized with fairly small values (Goyal et al., 2018). The output of the embedding layer is scaled by √h. To match this initialization, the state s0 is also sampled from a truncated normal distribution, here with variance σ_s² = 2/5." (Fractions garbled by extraction — "σh2 = 5h" with a "2" above, "σout2 1 = 5hl", "σs2 = 25"; the reconstructions 2/(5h), 1/(5hl) follow Takase et al.'s prescription; 2/5 = (2/(5h))·h is what "to match" the √h-scaled embedding requires. Treat σ_s² = 2/5 as a reconstruction, high confidence.)
- **Optimizer (p. 5):** "Adam optimizer with decoupled weight regularization (β1 = 0.9, β2 = 0.95, η = 5 × 10−4) … modified to include update clipping (Wortsman et al., 2023b) and removal of the ε constant as in Everett et al. (2024). We clip gradients above 1. We train with warm-up and a constant learning rate …, warming up to our maximal learning rate within the first 4096 steps." Peak LR of the successful run: **4 × 10⁻⁵** (p. 6). The LR "is never cooled down from its peak" (p. 7).
- **Scale:** 4096 MI250X GPUs (512 Frontier nodes), batch 1 sequence/GPU → 16M tokens/step, 47,000 steps, 795B tokens, 21 segments of ≤12 h in Dec 2024; 52–64 TFLOP/s per GPU (41–51% AFU), 1–1.2M tokens/s. Non-recurrent twin baseline: same architecture, 1 pass through the core, 180B tokens.
- **Data (Fig. 4, p. 5; App. C):** generic-text 28.71%, code 25.36%, scientific 18.73%, synthetic 8.14%, longform 7.50%, math 6.14%, generic-instruct 2.09%, Q&A 1.58%, math-instruct 1.51%, writing-instruct 0.12%, misc-reasoning 0.11% (chess, lichess puzzles). Instruction data mixed into pretraining (Allen-Zhu & Li 2024). Includes CLRS-Text algorithmic traces. "we were not able to ablate this mixture."

### 1.4 Failure modes reported (Section 4.3, p. 6; Fig. 5)

Three runs, first 10,000 steps:

1. **Bad Run 1** — sandwich structure but "parameter-free RMSNorm layers, no embedding scale γ, a parameter-free adapter A(s, e) = s + e, and a peak learning rate of 4 × 10−4" → "quickly stalled." Diagnosis: **representation collapse** (Noci et al. 2022): "The correlation of hidden states in the token dimension quickly goes to 1.0 (middle plot), meaning the model predicts the same hidden state for every token. We find that this is an initialization issue that arises due to the recurrence operation. Every iteration of the recurrence block increases token correlation, mixing the sequence until collapse."
2. **Bad Run 2** — added the embedding scale factor, switched to pre-norm, learned adapter → recovers from near-1.0 correlation after ~150 steps, but **the recurrence is ignored**: "validation perplexity is the same whether 1 or 32 recurrences are used. This initialization and norm setup has led to a local minimum as the model has learned early to ignore the incoming state s, preventing further improvements."
3. **Main** — "reverting back to the sandwich block format, and further dropping the peak learning rate to 4 × 10−5. This run starts smoothly, never reaches a token correlation close to 1.0, and quickly overtakes the previous run by utilizing the recurrence and improving with more iterations." Then "training continues smoothly for the next 750B tokens without notable interruptions or loss spikes."

Health metrics they tracked (p. 25): per-layer effective Adam LRs, optimizer RMS, L1/L2 parameter and gradient norms, "recurrence statistics such as ||s_k − s_{k−1}|| / ||s_k||, ||s_k||, ||s_0 − s_k||" (garbled in extraction; reconstructed), "correlation of hidden states in the sequence dimension after recurrence and before the prediction head", and validation perplexity at r ∈ {1, 4, 8, 16, 32, 64}.

Engineering gotchas (App. A.2, p. 24): "due to interactions of automated mixed precision and truncated backpropagation, PyTorch gradients are only correct while executing the compiled model" (the closest thing to a "bug" they report); RCCL interconnect hangs beyond 128–256 nodes with `NCCL_NET_GDR_LEVEL=PHB`, fixed by a hand-written DDP "sending only packages of exactly 64MB across nodes"; AMD fork of flash-attention needed.

### 1.6 Zero-shot inference features (Section 6, pp. 9–11)

- **Adaptive compute by KL exit (6.1):** "the KL-divergence between two successive steps. If this divergence falls below 5 × 10−4, we stop iterating, sample the output token, and move to generate the next token." MMLU category means (Fig. 10/13): high school mathematics 12.7, abstract algebra 13.6, machine learning 14.2, philosophy 14.6, clinical knowledge 14.7, world religions 15.1, logical fallacies 15.6, HS world history 15.8, professional law 16.0, moral scenarios 16.2 steps. MT-Bench 5.63 → 5.56.
- **Remark 6.1 (missing KV entries, p. 10):** "we attend to the last, deepest available KV states in the cache. Because all recurrent KV cache entries are generated by the same K,V projection matrices from successive hidden states, they 'match', and therefore the model is able to attend to the latest cache entry from every previous token, even if computed at different recurrent depths."
- **KV-cache sharing (6.2):** "We set a fixed KV-cache budget for the recurrence at every token k, and at iteration i, read and write the cache entry i mod k." Budget 4 did not hurt MT-Bench.
- **Zero-shot continuous CoT (6.3, pp. 10–11):** "Instead of sampling a random initial state s0 at every generation step, we can warm-start with the last state sr from the previous token. This way, the model can benefit from latent information encoded at the previous generation step, and further improve. As shown in Figure 10, this reduces the average number of steps required to converge by 1-2." Relation to Coconut (Hao et al. 2024): "the main distinction between both approaches is whether to pretrain from scratch for recurrence, or whether to finetune existing fixed-depth models to have this capability - and whether Chain-of-Thought data is required."
- **Self-speculative decoding (6.4):** draft with few iterations N, verify with M > N; drafted states are reused.

### 1.7 Latent trajectories (Section 7, pp. 11–13; App. B, pp. 25–35)

- Trajectories {s_i} analysed via distance to s* (r = 128 iterate) and PCA (first 6 and first 40 directions). "In comparison to previous work, such as Bai et al. (2019), where the training objective directly encodes a prior that pushes trajectories to a fixed point, we only train with our truncated unrolling objective" (p. 12).
- **Context-dependent convergence (Fig. 11, p. 11):** "highly token-specific convergence rates emerge simply with scale. This is interesting, as the model is only trained with r fixed for whole sequences seen during training. We see that convergence is especially slow on the key part of the question"; "The context dependence can also be seen in the different behavior among the three identical tokens representing each of the three dots" (p. 12); "the distance to s* does not always decrease monotonically (e.g. for school)".
- **Three motifs (Fig. 12, p. 12):** convergence to a fixed point (most tokens); **orbits** ("for harder questions, such as in the 2nd row [the token '3' in 'Claire makes a 3 egg omelette'], the state of the token quickly falls into an orbit pattern in all three pairs of PCA directions. The use of multi-dimensional orbits like these could serve a similar purpose to periodic patterns sometimes observed in fixed-depth transformers trained for arithmetic tasks (Nanda et al., 2022)"; also on structural tokens "makes", "thinks"); **sliders** ("the trajectory noticeably drifts in a single direction, which the model could use to implement a mechanism to count how many iterations have occurred", p. 13).
- **Path independence verified (p. 13, Figs. 22–25):** "When re-initializing from multiple starting states s0, the model moves in similar trajectories, exhibiting consistent behavior. The same orbital patterns, fixed points, or directional drifts emerge regardless of initialization."
- Fig. 15 caption (p. 26): "the system prompt is clearly separable when plotting only the top two PCA directions relative to all tokens (and different for questions 1 and 2)." Fig. 16: rotation of "3" "is only observed for mathematics-related reasoning, and thinking tokens, and does not appear for trivia questions."

## 3. Relevance to the BDH-CQ reconstruction

Pathway's loop (from the brief): H_0 = E_θ(x*, S_K), H_{r+1} = F_θ(H_r, S_K), ŷ = G_θ(H_R); memory S_t = U_θ(S_{t−1}, D_t), with linear attention as the special case S_t = S_{t−1} + U_θ(D_t).

**What matches, structurally (strong):**
- Huginn is literally a three-stage (P, R, C) ↔ (E_θ, F_θ, G_θ) design with a weight-shared block iterated R times and the "data" re-injected every iteration: s_i = R(e, s_{i−1}) ↔ H_{r+1} = F_θ(H_r, S_K). Huginn's e plays the role of S_K: a fixed conditioning object produced once, then concatenated to the evolving state at every step through a learned adapter A·[s ; e]. Huginn gives the *reason* for that design in Pathway's own terms: the loop should be a stable, data-dependent iterative operator (gradient-descent-like), and that requires the data in every step (p. 3 + fn. 1). This is the paper's clearest contribution to the reconstruction: **re-using S_K at every step is not an implementation quirk; it is what makes the refinement loop well-posed and path-independent.**
- Huginn's recipe for training such a loop — random iteration count per sequence (log-normal Poisson, Eq. 1–2), truncated backprop through the last k = 8 iterations, no step index fed to the block, random initial state — is a complete, public recipe that BDH-CQ *could* have used; the paper shows it scales. **[inference]** The brief's BDH-CQ numbers (Sudoku-Extreme) are not evaluated here; Huginn's own arithmetic is weak (Fig. 14), so this paper supports the *architecture pattern*, not any claim about puzzle-solving ability.
- Also matching: the "complementarity" thesis (p. 14) — a memory/retrieval component plus a depth-recurrent reasoning component — is exactly BDH-CQ's decomposition (Hebbian memory S + refinement loop F_θ).

**What differs / does not match:**
- **Nothing about the memory update rule.** Huginn has no S, no "linear correction rules", no S_t = S_{t−1} + U(D_t). Its cross-token mechanism is full causal softmax attention with RoPE inside every layer of P, R and C. The only touch-point is the Future-Work remark that linear attention is "limited in the number of comparisons" and depth recurrence lets "blocks containing linear operators … repeat until all necessary comparisons between sequence elements are computed" (p. 14), with the cited delta-rule linear transformer (Yang et al. 2024b, DeltaNet) being a genuine "linear correction rule on S" (S_t = S_{t−1}(I − βk kᵀ) + βv kᵀ — **[inference]** this is the most natural reading of Pathway's phrase, but it comes from the citation, not from this paper's content).
- **The injected object.** Huginn injects a per-token embedding e ∈ R^{n×h} of the *current sequence* — the raw data — not a compressed memory. BDH-CQ injects S_K (a fixed-size state after ingesting K demonstrations). Huginn's loop therefore has unrestricted access to every context token at every iteration; BDH-CQ's has only what the Hebbian write rule retained.
- **Initial state.** Huginn uses s_0 ∼ N(0, σ²I) (σ_s² = 2/5, matched to the embedding scale) and argues s_0 = e *without re-injection* is unstable. BDH-CQ's H_0 = E_θ(x*, S_K) is a data-dependent init — compatible with Huginn, *because* S_K is still re-injected: Huginn's own zero-shot warm start (s_0 ← s_r of the previous token, Section 6.3) is a data-dependent init that works without retraining. **[inference]** One tension to flag: in the brief's formula the query x* enters only through H_0, not through F_θ. By Huginn's argument (data must be present in every step), either x* is also encoded in S_K (the query tokens were ingested into the memory too), or H_r is a per-token state over the query positions with intra-query mixing inside F_θ so x* persists in H_r, or the loop is simply not of the monotone-operator type with respect to x*. Pathway's wording does not let us decide; Huginn says the first or second option is the safe design.
- **Attention to the context vs. reading a state.** In Huginn, the number of iterations the model spends grows with the amount of in-context information (Fig. 9: 8–12 iterations zero-shot → ~20 one-shot → ~32 at 25–50 shots). **[inference]** The analog in BDH-CQ would be that each F_θ step performs one (linear-attention) read from S_K, so R steps = R sequential retrievals = multi-hop reasoning over the ingested demonstrations; more demonstrations → more hops needed before convergence. Huginn's "more context → later saturation" is exactly the signature one would predict for that, and it is also a *testable* prediction for a BDH-CQ-style model: steps-to-KL-convergence should grow with K.
- **Failure mode that BDH-CQ must avoid:** Huginn's Bad Run 2 learned to ignore the incoming state s (val ppl identical at r = 1 and r = 32). The diagnostic is cheap — loss vs. R on a held-out set (Fig. 5 right) — and the fixes were architectural (sandwich norm, learned concat adapter, embedding scale) plus a 10× lower LR. A BDH-CQ reproduction should monitor this from step one.
- **Not a fixed-point solver.** Unlike DEQ (Bai et al. 2019), Huginn does not solve for a fixed point and observes non-convergent orbits/sliders; it still works with KL-based early exit. If BDH-CQ's "latent refinement" is DEQ-like (fixed-point), that would be a different training objective (equilibrium models "solve the 'direct' problem", p. 13); Huginn argues "truncated unrolling is a scalable alternative."

## 4. Relevance to distant context cues

**Which component carries context across distance:** standard causal softmax self-attention with RoPE, present in every layer of P, R and C. Time scale: the full 4096-token training window (and the KV cache at inference). The context is **inferred from data** — no labels, task ids or boundaries beyond a `<|begin_text|>` token at document starts — and trained only by next-token prediction with random unroll depth. There is no gate, router or channel anywhere in the model.

**What the recurrence adds to context use:**
1. Each iteration of R re-attends to the whole context (at the same depth of all previous tokens during training; at the deepest available depth at inference, Remark 6.1). So information from a distant token can be fetched, transformed, and fetched again — multi-hop over the context within one position. The paper's own evidence is Fig. 9 (saturation shifts from ~8–12 to ~32 iterations as few-shot examples are added) and Table 5 (+11 points when the relevant fact is placed in context).
2. The latent state demonstrably encodes "which part of the prompt am I in": "the system prompt is clearly separable when plotting only the top two PCA directions relative to all tokens" (Fig. 15, p. 26). **[inference]** That is a stream/segment identity emerging in the residual stream without supervision — but it is produced by attention over the segment, not by a per-token recurrent signal.
3. Convergence speed is per token and context-dependent — identical tokens ("...") behave differently depending on context (p. 12).

**Direct transfer to our header layout:** the paper gives no mechanism we can copy for a *linear-attention* model, because Huginn's distant-cue carrier is softmax attention, which a decayed Hebbian memory does not have. What it does give is the argument on p. 14: a linear-attention block can make only a bounded number of comparisons per layer, and depth recurrence multiplies that budget. **[inference]** In our terms: the header-layout write at VAL needs two hops at the same position — hop 1: recover "the most recent CTX" from memory; hop 2: use it to route the write. Our current gates compute g_t once from raw embeddings (window or recurrent), so hop 1 can never inform the routing, whatever the layer count. A gate that reads a context-informed state (per-layer residual gate) or a depth-recurrent BDH block with input injection are the two ways to buy the second hop. Caveat **[inference]**: with decay 0.95 and only content-based reads, "most recent CTX" is a soft mixture (previous block's CTX still has weight 0.95^{2P+1} ≈ 0.63 at P = 4, ≈ 0.42 at P = 8 relative to the current one), so hop 1 may need either a sharper decay channel or a position-sensitive read; Huginn's RoPE softmax attention does not face this.

## 5. Relevance to our gate

### 5.1 Concrete, implementable ideas

**(a) Per-layer residual gate with Huginn-style input injection.** Huginn's finding that the recurrent block should see *both* the evolving state and the raw embedding, concatenated through a learned adapter ("concatenation works best at scale", p. 4; the parameter-free sum A(s, e) = s + e was part of the collapsed Bad Run 1) maps directly onto the per-layer gate:

```
u_t^{(l)} = A [ RMSNorm(h_t^{(l)}) ; v_t ]        A ∈ R^{(N+d_v)×N} learned, h^{(l)} = residual stream entering layer l, v_t = raw embedding
g_t^{(l)} = softmax( W_g tanh(u_t^{(l)}) )
```

The raw v_t keeps the gate anchored to the token (Huginn: the data term that makes the operator well-posed), the residual stream brings what layer l−1 retrieved (e.g. the block header). RMSNorm the state before the adapter (Huginn normalizes at the end of the core with n_c, and after every residual add). Keep one shared W_g across layers if you want the "same operator at every depth" prior; Huginn shares R entirely.

**(b) Depth-recurrent BDH block (the Huginn recipe at CPU scale).** Iterate our 3-layer block i = 1…R at each position with the gate recomputed from the iterate, train with random R and truncated backprop:

```
e_t = v_t   (or a 1-layer prelude)
s_t^{(0)} ∼ N(0, σ_s² I), σ_s matched to the scale of e_t
s_t^{(i)} = Block( A [ s_t^{(i−1)} ; e_t ] ),   g_t^{(i)} = softmax(W_g s_t^{(i)})  (routing per iteration)
R ∼ log-normal Poisson, small r̄ (e.g. 3–4), backprop through the last k (k = R at our scale is affordable)
```

Do **not** feed the iteration index i (Remark 3.1: kills extrapolation). Do **not** add per-step noise (did not help). The random-R objective forces routing decisions that are stable across depth (a built-in regularizer against depth-specific hacks) and gives zero-shot adaptive exit: stop when KL(g^{(i)} ‖ g^{(i−1)}) < 5·10⁻⁴ (their threshold). Note Huginn's "routing to the same expert multiple times, before switching" remark (p. 14) is this idea stated for MoE routers.

**(c) Initialization and scale matching.** Huginn: out-projections at variance 1/(5·h·l) with l = effective depth (very small), everything else 2/(5h), embeddings ×√h, random state variance matched (2/5). Translate: initialize W_h (recurrent) and the gate's output projection small relative to W_in, so the recurrent/contextual path starts as a perturbation of the token path, and if h_0 is random, give it the same scale as W_in v_t so neither input dominates the adapter at init.

**(d) Learning rate.** Huginn's "ignore the recurrent state" local minimum was cured by (norms +) a 10× lower peak LR (4e−4 → 4e−5) with a 4096-step warmup. This is the same phenomenon as our router collapse / degenerate splits, and it supports our slow-LR recipe in spirit (slow down whatever path can find the shortcut). Worth trying: a lower LR specifically on the gate's *recurrent* weights W_h (not on the whole gate), since W_h is the path the model learns to ignore.

**(e) Monitoring.** Add Huginn's health metrics to our runs: (i) correlation of gate vectors g_t across tokens (their "token-dimension hidden-state correlation → 1.0" is the collapse signature; for us, all tokens routed identically = single-channel collapse); (ii) ‖h_t − h_{t−1}‖/‖h_t‖ for the recurrent gate (is the state actually moving?); (iii) loss at R = 1 vs R = max for the depth-recurrent variant — if equal, the block is ignoring its state (Bad Run 2).

**(f) Weight averaging.** EMA of late checkpoints (β = 0.9 over the last 75 with dilation 7) gave +4–5 GSM8K points for free; trivial to add to our plateau-split protocol.

**(g) Stability of the recurrent gate at eight streams.** Huginn's answer to expansive recurrence is architectural (RMSNorm after every residual add; the data term e every step), not spectral constraints — but it cites Bear et al. 2024 (arXiv 2410.23451, "Rethinking Deep Thinking: Stable Learning of Algorithms using Lipschitz Constraints") for the constraint route. For h_t = tanh(W_in v_t + W_h h_{t−1}) the cheap analog is spectral-normalizing W_h (‖W_h‖₂ < 1) or adding RMSNorm on h_t before W_g.

### 5.2 Which of our beliefs the paper supports, contradicts, warns about

- **Supports** the per-layer residual gate as the next move: the whole paper is evidence that a context-informed state, re-processed with the raw input still present, is the right basis for iterative decisions, and that extra passes are spent on *using context* (Fig. 9).
- **Supports** the slow-LR / "don't let the shortcut win early" philosophy (Bad Run 2).
- **Supports** the view that routing/decision pathologies are *initialization + normalization* problems first ("We find that this is an initialization issue that arises due to the recurrence operation", p. 6), consistent with our experience that the recipe matters more than the gate formula.
- **Warns** that our recurrent gate's position counting is the mirror image of what Huginn deliberately avoids: any step/position-conditioned behaviour hurts extrapolation and path independence (Remark 3.1). Yet Huginn also observes that the model *learns its own counter* ("sliders", p. 13) when useful — counting emerges even when the index is withheld, so removing explicit position information will not by itself stop a gate from counting.
- **Warns** that several of their fixes are scale-dependent: "At small scales, most sensible initialization schemes work" and "most normalization strategies … work almost equally well" (pp. 3–5). At N = 256 on CPU we should not expect the sandwich norm or Takase init to matter much; conversely the interesting emergent dynamics (orbits, context-dependent convergence) "emerge simply with scale."
- **Does not address** label-free discovery of a stream partition: there is no gating or channel structure in the model, and all cross-token interaction is softmax attention. Nothing here tells us whether a k-channel Hebbian router can discover streams from the loss alone.
- **Contradicts nothing we have measured**, but note the r = 1 collapse to chance (Table 4): a model trained for recurrence can become *useless* without it. If we go depth-recurrent, we should check the R = 1 behaviour is still sane (or accept that it is not).

## 6. Loose threads

Things a hurried reader would miss:
- **Random-r training uses one r per micro-batch** (locked-step sampling, p. 5) — the "expectation over r" of Eq. (1) is approximated per step; they flag per-worker sampling as an improvement.
- **r = 1 performance is near chance** and stops improving after 180B tokens (Table 4, p. 9) — the non-recurrent layers do not absorb the gains.
- **Non-monotonicity in r** for 2–3-digit multi-operand addition (Fig. 14, p. 23): "inconsistent ordering as a function of recurrence … and also some peaks in performance at 5 and 4 operands." More iterations is not always better per task.
- **KV-cache cost scales with r** (every iteration has its own K,V for the 4 core layers) unless shared with the i mod k scheme; MT-Bench budget 4 was fine (p. 24).
- **The model is trained with r fixed over the whole sequence**, yet per-token convergence rates emerge (Fig. 11). Per-token adaptive compute was never trained for.
- **The system prompt is linearly separable in latent space** (Fig. 15, p. 26) — an emergent segment/context representation.
- **Orbits appear on math and on structural tokens** ("makes", "thinks"), not on trivia tokens (Figs. 16–17, pp. 27–28) — the dynamics are content-selective.
- **Noise injection did not help; step-conditioning hurt** (Remark 3.1, p. 3).
- **n3 is "technically superfluous"** (fn. 2, p. 4) — they report the exact trained setup anyway.
- **"PyTorch gradients are only correct while executing the compiled model"** under AMP + truncated backprop (p. 24).
- **LR never cooled; EMA used instead** (pp. 7, 9). **Data mixture unablated**; heavy math/code/instruction mix including CLRS-Text algorithmic traces and chess (App. C, pp. 36–37) — the "reasoning" results sit on top of reasoning-heavy pretraining data.
- **Oversight concern** (App. A, p. 22): latent reasoning is not human-readable; they offer the trajectory analysis as partial mitigation.
- **Future work they name** (Section 9): fine-tuning to compress the recurrence; RL by hardness (Zelikman et al. 2024, Quiet-STaR, arXiv 2403.09629); internalizing CoT into recurrence (Deng et al. 2024, arXiv 2405.14838); multiple successive recurrent stages (Takase & Kiyono 2023, arXiv 2104.06022; Csordás et al. 2024 MoEUT); recurrent MoE; recurrent depth over linear-attention blocks.

## 7. Verdict

This paper is the public, scaled-up template for the "refinement loop" half of BDH-CQ: a weight-shared block iterated a random number of times, with the conditioning object (here the embedded input e; in BDH-CQ the memory S_K) concatenated back in at every step through a learned adapter, random initial state, truncated backprop, no step index — and it explains *why* the re-injection is necessary (stable, path-independent, gradient-descent-like iteration). It says nothing about the memory update rule or "linear correction rules on S"; the only bridge to that is its Future-Work remark that linear-attention blocks become expressive when recurred in depth, which is itself a strong hint about how a BDH block and a reasoning loop fit together. For our gate, the transferable lessons are architectural and procedural rather than a new mechanism: give the router the context-informed residual state *and* the raw embedding (concatenated, learned adapter, normalized), buy a second hop with depth (per-layer gate, or a small depth-recurrent block trained with random R), monitor cross-token correlation of the gate and loss-vs-R for the "ignore the state" collapse, and treat LR/init as the first-line fix. It does not touch the open question of label-free stream discovery, and it warns that most of its own fixes only bite at scale. Confidence: high on the architecture/training facts and the BDH-CQ structural mapping; medium on the multi-hop interpretation of Fig. 9 and on the transfer of its stability fixes to a 3-layer, N = 256 Hebbian model.
