## 1. What the paper actually does

### 1.1 One-paragraph summary

A feedforward MLP whose hidden units are replaced by "Active Dendrites Neurons": each unit computes an ordinary linear feedforward activation on the input x, **and** a set of dendritic segments each computes a dot product with a separate **context vector c**; the strongest (in v2: largest-magnitude) segment response is passed through a sigmoid and **multiplies** the feedforward activation; a layer-wide **k-Winners-Take-All (kWTA)** then zeroes all but the top-k units. Trained end-to-end by plain backprop. The context vector is the **task-ID one-hot** in multi-task RL (Meta-World MT10), and in continual learning (permutedMNIST) it is a **per-task prototype (mean input vector)** which at test time is **inferred by nearest-prototype lookup (Euclidean) on the current input**, with optional train-time inference by online clustering with a Hotelling T² test. Results: MT10 87.5% vs 76.6% for an MLP given the same one-hot context as input (p. 9); permutedMNIST 94.6% (10 tasks) / 81.4% (100 tasks) with task info at train time, 94.3% / 76.9% with no task info at any time; 97.2% / 91.6% when combined with SI (pp. 11–12). The mechanism yields "overlapping but distinct and sparse subnetworks" per task (Abstract, p. 1).

### 1.2 The Active Dendrites Neuron — equations (Section 3.1, p. 5), copied

Feedforward term, eq. (1), extracted cleanly:

> "Given input vector x, weights w, and bias b, our neuron computes the following feedforward activation:
> t̂ = w> x + b (1)"

Dendritic segments and max, eq. (2) — the extraction scattered the subscript; the text reads "d = max u> / j c / j". **[reconstruction]** from the surrounding prose ("each dendritic segment j computes u>j c, given weight uj and context vector c ... We select the segment with the strongest response to the context when computing dendritic activation d"):

    d = max_j  u_j^T c                                   (2)

Modulation function, verbatim (p. 5):

> "In order to modulate feedforward activation t̂ by the dendritic activation d, we use modulation function f (t̂, d) where f (m, n) = m × σ(n). Here, σ(·) is the sigmoid function which takes a real number and maps it into the range [0, 1]."

Full neuron, eqs. (3)–(5) — garbled across lines in the extraction; **[reconstruction]**:

    ŷ = f(t̂, d)                                         (3)
      = f( w^T x + b ,  max_j u_j^T c )                    (4)
      = ( w^T x + b ) × σ( max_j u_j^T c )                 (5)

Interpretation, verbatim (p. 5):

> "Here, a strong positive dendrite response to the context vector will retain the feedforward activation. Conversely, weak or negative responses to the context vector will significantly reduce the activation. We note that there are many variations of (2) that are possible. We found that the network works best when we select the dendrite activation with the largest absolute value and retain the sign in d (Section 6.3)."

**Absolute-max gating — the variant actually used (Section 6.3, p. 24).** Motivation, verbatim:

> "One problem with this formulation is that it becomes difficult to turn a neuron off (i.e., force it's activation value to be zero) due to the max operator. That is, if dendritic segment j learns to turn off the unit, then based on sigmoidal gating, we should expect that u>j c is a small number with large absolute value (very negative). However, it's likely that for some other segment j′ (j ≠ j′), u>j′ c > 0 > u>j c which means that segment j′ will be selected by the max operator instead of segment j, hence increasing the chance that the neuron will be selected by the kWTA process. This motivates absolute max gating in which the activation with the largest magnitude is selected and its sign is kept."

Equations (garbled in extraction; **[reconstruction]**):

    j* = argmax_j | u_j^T c |
    ŷ  = ( w^T x + b ) · σ( u_{j*}^T c )

Note the sigmoid is applied to the *signed* value of the winning segment, so a strongly negative winning segment drives the gain toward 0 (unit off), a strongly positive one toward 1 (unit fully on). There is no gate bias term in the equations (and Table 2 counts 2800×10×10 = 280,000 dendritic parameters exactly, i.e. no per-segment bias).

**kWTA sparsity on the layer output, eq. (6) (Section 3.2, p. 6)**, extracted cleanly enough:

> k(ŷi) = ŷi if ŷi is one of the top k activations over all i; 0 otherwise (6)
> "where i indexes neurons in the same layer. The effect of kWTA is to ensure sparsity by selecting the top k activations and setting all others to zero. Feedforward layers that are modulated by dendritic segments and apply kWTA thus produce sparse activity patterns that are highly context-dependent. Additionally, our feedforward layers also use sparse weights as proposed in Ahmad and Scheinkman [2019]."

kWTA is applied *after* the dendritic modulation (Figure 2 caption, p. 6: "After all dendritic segments compute an activation value, the highest value modifies the linear weighted sum computed by feedforward weights"; "Each layer outputs sparse activations, as determined by a kWTA activation function"). The paper does not mention the duty-cycle "boosting" that Numenta's kWTA implementation (Ahmad & Scheinkman 2019; Cui et al. 2017 spatial pooler) normally carries; whether boosting was on is **not stated** (my memory of the public nupic.research code is that `boost_strength` is a config option — verify in the repo before relying on it).

**Numbers of segments and sparsity levels (Tables 2, 3; Sections 4.1.1, 4.2, 6.1.4):**

| | MT10 (RL) | permutedMNIST (CL) |
|---|---|---|
| Hidden layers | 2 × 2,800 | 2 × 2,048 (2,000 when matching SI/XdG) |
| Which layers get dendrites | only the 2nd hidden layer (the 1st has "standard neurons", p. 7) | both hidden layers |
| Segments per neuron | 10 (= number of tasks) | T (= number of tasks); App. B.3 also tests a fixed 10 |
| Weights per segment (= dim of c) | 10 (one-hot task ID) | 784 (prototype = mean image) |
| Dendritic weight sparsity | 0% (dense) | 0% (dense) |
| Activation sparsity (kWTA) | top 25% of units active | top 5% of units active |
| Feedforward weight sparsity | 10% zeros (fixed random mask) | 50% zeros (incl. the output layer — I checked the parameter count: 2,914,314 matches 50% on all three weight matrices) |
| Non-zero params | 7,169,964 FF + 280,000 dendritic = 7,449,964 (MLP baseline 7,994,004; "Large MLP" 9,165,004) | 2,914,314 FF + T × 3,211,264 dendritic |

Verbatim (p. 7): "Each Active Dendrites Neuron in our network has exactly 10 dendritic segments (same as the number of tasks to learn) so that each segment can potentially learn to recognize a unique context vector." And (p. 10): "When attempting to learn T consecutive tasks, the hidden neurons are equipped with T dendritic segments each to give it sufficient capacity to recognize a unique context vector for each task."

### 1.3 How the dendritic weights are trained; what prevents collapse

**Training is plain backprop through the (abs-)max and through kWTA; no straight-through estimator, no auxiliary loss, no special initialization is described.** Verbatim (Section 3.3, pp. 6–7):

> "The above properties are implemented such that the entire network is differentiable and trainable end-to-end using backpropagation." (p. 5)
> "We make two notes: first, only the neurons that were selected by the kWTA function will have non-zero activations (and thus non-zero gradients). Therefore, during the backward pass, only the weights corresponding to those winning neurons will be updated. Second, for each of those winner neurons, only the dendritic segment j that was chosen by the max operator is updated; all other segments uj′ for j′ ≠ j remain untouched. Thus a very small sparse subset of the full network is actually updated for each input." (pp. 6–7)
> "We hypothesize that a functional specialization will emerge where different dendritic segments will each learn to identify specific context vectors. Since most dendritic segments that don't respond to a specific context will not be updated, any context-dependent modulation of the neuron should be preserved from task to task." (p. 7)

So the gradient reaching segment j* is ∂L/∂ŷ · (w^T x + b) · σ′(u_{j*}^T c) · c — the standard subgradient of max (PyTorch `max` backward). Losing segments get exactly zero gradient; losing units (kWTA) get exactly zero gradient.

**Anti-collapse: nothing explicit.** The paper has no winner-take-all *across segments* beyond the max itself, no segment-level sparsity, no diversity penalty, no initialization trick. What the paper offers (and what I infer):

- The only stated mechanism is the hard assignment itself: a segment that does not win for context c is never pulled toward c (quoted above). This is competitive learning with a hard winner — the same regime as k-means / online VQ. **[inference]** It prevents the *loser-dragging* form of collapse (everything drifting to a common vector) but not the *dominance* form (one segment winning for every context). The paper's own data say dominance is not catastrophic here: Table 4 (p. 31) shows **1 segment: 85.6%** vs 10 segments: 87.5% vs 20 segments: 89% on MT10. With a 10-d one-hot context a single segment u is simply a lookup table of 10 per-task gate logits (u^T c = u_task), so one segment can already express an arbitrary per-task gain per neuron; extra segments add only a little. Likewise App. B.3 (p. 33): with a fixed 10 segments for 100 tasks, 78.5% vs 81.4% with 100 segments, explained as: "since the dendritic segments are dense and prototype context vectors are sparse (as most pixels in an MNIST image are black), a single segment can learn to identify multiple context vectors, and thus there can be far fewer dendritic segments than unique context vectors."
- Initialization is random and diverse (Figure 11, p. 14: "At the beginning of training, the responses are random with scattered positive, negative, and near-zero responses. After training, most responses are weak and only a few are either strongly positive or negative."). The paper never states the init distribution. (From memory of Numenta's `DendriteSegments` module: Kaiming-uniform over (units × segments × dim_context), i.e. the default `nn.Linear` scheme; unverified here.)
- Diversity of *subnetworks* (which is what matters for interference) comes from the layer-level kWTA over thousands of units rather than from segment competition: with random init, each context picks a random ~5% (or 25%) subset of winners, and two contexts coincide on the same subset with negligible probability; learning then sharpens whichever units/segments happened to win. **[inference]** This is why no anti-collapse machinery is needed at 2,048 units — and why it is *not* automatically transferable to k = 4–16 channels, where random initial winners collide often (see Section 5 below).
- The one failure mode they did fix is the "cannot turn off" problem, solved by absolute-max gating (quoted in 1.2). Also note (p. 14): "in the multi-task RL scenario, we observe both strong positive and negative responses while the continual learning scenario only shows strong positive activity. We are unclear as to why this particular behavior emerges in continual learning but not multi-task RL."

### 1.4 Where the context vector comes from

**(a) Multi-task RL (MT10):** given, not inferred. Verbatim (p. 7): "For our multi-task RL experiments, the context vector c encodes the task ID as a one-hot encoded vector. We considered other options to generate c, such as first pre-processing the one-hot encoding by a linear layer, but found that a one-hot encoding was adequate." And (p. 20): "All tasks share an identical state space st ∈ R39 and action space at ∈ R4. Because there are 10 different tasks, c is a 10-dimensional one-hot encoded vector that describes the task ID." Both the policy π(a_t|s_t, c) and Q(s_t, a_t|c) are context-conditioned (p. 20). The MLP baseline gets exactly the same one-hot, concatenated to the state (input 49 = 39 + 10): "Thus both the Active Dendrites Network and the baseline network receive identical information at each time step; the primary difference between the two architectures is how the context vector is handled." (p. 8). Goal positions are fixed across training (p. 7), so the context is constant for a whole 500-step episode.

**(b) Continual learning (permutedMNIST): the prototype method (Section 4.2.1, pp. 10–11).**

Training method 1 (task labels available during training): the prototype for task τ is the element-wise mean of all training inputs of that task:

    p_τ = (1/|V_τ|) Σ_{x ∈ V_τ} x

"where Vτ denotes the set of all data samples x that the model observes to train on task τ. The dimensionality of the context vector is thus identical to the dimensionality of the input vectors. This context vector is specific to each task and agnostic to the target label." (p. 11)

Training method 2 (no task labels at any time): online clustering. Verbatim (p. 11): "When the system receives a new batch of training samples from a task, we use an unpaired multivariate t-test to compare the current samples to previously observed training samples. If the new batch of samples is similar to earlier training samples, they are assigned to an existing prototype. If not, the new batch of samples is assumed to correspond to a new task, and a novel prototype is instantiated. In this case, there isn't necessarily a one-to-one mapping between tasks and prototype context vectors." Details (Section 6.2.3, pp. 22–24): stated inductive bias — "all training examples in a batch correspond to the same task, since continual learning scenarios usually only observe examples from a single task within a given batch" (p. 22). Algorithm 1 (greedy: "assigns X to the first cluster j that it suitably matches") loops over existing clusters, calls IsMatch(X, Y_j); on a match, Y_j ← Y_j ∪ X and p_j is updated to include X; otherwise a new cluster Y_{M+1} ← X with prototype = element-wise mean of X. (The tail of Algorithm 1 — the "else create a new cluster" lines after step 10 — is missing from the extraction at the page break between pp. 22 and 23; the prose on p. 22 describes it.) IsMatch is Hotelling's T² (Algorithm 2, p. 24):

    t² = (|X||Y_j|)/(|X|+|Y_j|) · (x̄ − ȳ)^T Σ^{-1} (x̄ − ȳ)
    f  = (|X|+|Y_j| − d − 1) / ( d (|X|+|Y_j| − 2) ) · t²

"If f > p then we reject the null hypothesis ... and thus create a new cluster. ... a new cluster and prototype emerge if and only if we reject the null hypothesis for all M t-tests." (p. 24). Σ is the pooled covariance; "we replace all standard matrix inversions with the Moore-Penrose pseudo-inversion" (Algorithm 2 caption). Threshold: "we used a significance threshold of p = 0.9. We chose this value arbitrarily" (App. B.2, p. 32). Two oddities worth knowing if you reimplement: (i) the quantity compared to "p" is the F-statistic itself, not a p-value (so p = 0.9 is a threshold on f, despite the name); (ii) Algorithm 2 step 5 reads "ΣY ← 1/(|Y|−1) (X − ȳ)(Y − ȳ)>", which must be a typo for (Y − ȳ)(Y − ȳ)^T. Figure 16 (p. 33) reports the number of clusters formed vs tasks ("sensible ... not too few nor too many"); the actual counts are only in the figure, not in the text.

**Inference at test time — always inferred, for both methods, from the current input alone.** Verbatim (p. 11):

> "Selecting prototypes during inference: For both methods above, we do not provide any task information to the system during evaluation. Instead it must dynamically select the correct context vector and provide that to the network. We enable this dynamic approach by selecting the closest prototype vector to each test example using Euclidean distance. That is, for a test example x′, the chosen prototype is: arg min_{pτ} ||x′ − pτ||₂ computed over all prototypes pτ stored in memory."

So yes: the context *is* inferred rather than given at test time, it is unsupervised (nearest centroid, L2), and it is a function of the **same input** being classified — no temporal carrying is involved.

**How well does inference work? The numbers (p. 11):** "we achieve accuracies of 94.6% and 81.4% on 10 and 100 consecutive permutedMNIST tasks, respectively, when context is provided during training, and accuracies of 94.3% and 76.9% when context is dynamically chosen during training." I.e.:

| permutedMNIST | 10 tasks | 100 tasks |
|---|---|---|
| Prototype given at train, inferred at test (method 1) | 94.6% | 81.4% |
| Prototype clustered at train, inferred at test (method 2) | 94.3% | 76.9% |
| Method 1 + SI | 97.2% | 91.6% |
| Method 1, fixed 10 segments (App. B.3; which method is not stated, I assume method 1) | — | 78.5% |

**Caveats the paper does not spell out [inference]:** there is no oracle row (true task label given at test), and the accuracy of the nearest-prototype assignment itself is never reported, so the cost of test-time inference cannot be isolated. For permutedMNIST it is almost certainly near zero: the mean MNIST image has strong spatial structure, each permutation scrambles it into a distinct 784-d centroid, and every test image carries the full permutation signature — so nearest-centroid is close to perfect. The 81.4 → 76.9 gap at 100 tasks is therefore mostly the cost of imperfect *train-time* clustering (wrong/merged/split prototypes), not of test-time inference. permutedMNIST is a weak test of context inference: the context is readable off every single input. This matters for us (Section 4).

### 1.5 Training details that matter

- MT10 (Table 2, p. 21): MTSAC (multi-task SAC), 3,000 epochs × (one 500-step episode per task) = 15M env steps; 250 gradient steps per epoch; batch 2,560 from a 1M replay buffer; policy and Q lr 3e-4; target update 5e-3; one Active Dendrites Network for π, another for Q; per-task entropy coefficients α_τ. "The training hyperparameters are identical for the Active Dendrites Network and the MLP baseline" (p. 20). 10 trials (Exp. 1); Exp. 2 = best of 5 runs for each of 5 inits.
- permutedMNIST (Table 3, p. 23): Adam, batch 256, single output head (10 units reused across tasks, chance = 10%), 1 to 5 epochs per task, lr tuned per T: method 1 uses 5e-4 (T = 2, 5, 10), 3e-4 (T = 25, 50), 1e-4 (T = 100); method 2 uses 1e-3 (T ≤ 10), 3e-4 (25), 1e-4 (50, 100). "hyperparameters were optimized individually for each setting" (p. 22). MLP baselines use tiny lrs (3e-6 at T = 10; 1e-6 / 3e-7 at T = 100) — presumably the best anti-forgetting setting for a plain MLP. Depth: "having just a single hidden layer reduced accuracy by a few percentage points while 3 hidden layers provided a minimal performance boost. For 100 tasks, a single layer reduced accuracy by 3% and three layers improved accuracy by 0.5%." (pp. 21–22). SI combination: hidden 2,000, 20 epochs per task, lr 5e-4, SI c = 0.1, ξ = 0.1 (p. 22). Results averaged over 8 seeds.
- No separate learning rate for dendritic weights, no warm-up, no auxiliary losses, no regularizer on the gate are described anywhere.

"using more than a single hidden layer and modulating only the final hidden layer produces the best results. In addition, modulation with more dendritic segments than the number of tasks results in marginal increases in success, while less dendritic segments than the number of tasks produces a marginal decrease in success." (p. 31)

**permutedMNIST**: table in 1.4 above. Tasks tested: 2, 5, 10, 25, 50, 100 (Figure 8). Comparison with XdG (Figure 9, p. 13; XdG numbers taken from Masse et al. 2018, not printed in the text): "Our results with a large number of tasks are significantly better than XdG, and slightly worse than XdG combined with SI, but without their limitations." According to this measure, it appears that the network has indeed learned to invoke minimally overlapping subnetworks for different tasks." **The effective-parameter reduction (App. B.1, pp. 31–32)** — important for understanding what the gate really is. Total weights per layer: W_l = (1 − s_F)(n_l + 1) n_{l−1} + (1 − s_D) p T n_l (feedforward incl. bias; dendritic with p = prototype dim) [reconstructed from a garbled line; s_F = 0.5, s_D = 0]. Then, verbatim: "During testing σ(max_j u>j c) is constant for each vector ci. The equation can be re-written as: ŷ = (w>x + b) di where di = σ(max_j u>j ci), 0 < i ≤ T. For any given test input, we can select the nearest prototype vector i and use the appropriate scale factor di." And: "Note that in the experiments reported here, with a small fixed number of context vectors, it is actually possible to learn di directly via backpropagation. ... We did not implement this as it would also limit the flexibility of the overall architecture and disallow future scenarios where the context vector changes dynamically per input." (p. 32)

## 2. Verbatim quotes that matter

- Abstract (p. 1): "Analysis on both benchmarks demonstrates the emergence of overlapping but distinct and sparse subnetworks, allowing the system to fluidly learn multiple tasks with minimal forgetting."
- Biology of the modulatory time scale (p. 4): "In basal dendritic segments, dendritic spikes travel to the cell body and can depolarize the neuron for an extended period of time, sometimes as long as half a second [Antic et al., 2010, Major et al., 2013, Gao et al., 2021]. During this time, the cell is significantly closer to its firing threshold and any new input is more likely to make the cell fire. This suggests that basal active dendrites have a modulatory, long-lasting impact on the cell's response, with a very different role than proximal, or feedforward, inputs".
- Source of context in biology (p. 4): "Active dendritic segments typically receive contextual input that is a different input than received in proximal segments. These context signals can arrive from other neurons in the same layer, neurons in other layers, or in the form of top-down feedback."
- Sparsity rationale (pp. 4–5): "If the representations of two different tasks have near-zero overlap, it is possible to significantly reduce task interference."
- Local update (pp. 6–7): "only the dendritic segment j that was chosen by the max operator is updated; all other segments uj′ for j′ ≠ j remain untouched. Thus a very small sparse subset of the full network is actually updated for each input."
- One-hot adequate (p. 7): "We considered other options to generate c, such as first pre-processing the one-hot encoding by a linear layer, but found that a one-hot encoding was adequate."
- Same information, different use (p. 8): "Thus both the Active Dendrites Network and the baseline network receive identical information at each time step; the primary difference between the two architectures is how the context vector is handled."
- Test-time inference (p. 11): "For both methods above, we do not provide any task information to the system during evaluation. Instead it must dynamically select the correct context vector and provide that to the network."
- vs XdG (p. 12): "Task information is inferred in our system (via prototyping) whereas XdG provides the system with a task ID during training and testing. As such, our system is solving a problem that is known to be significantly more challenging [van de Ven and Tolias, 2019]." and "Subnetworks automatically emerge via the use of dendritic segments for each new task whereas XdG pre-allocates a different subnetwork for each task".
- Semantic overlap (p. 12): "dendritic segments can choose subnetworks that overlap more for tasks that are more semantically related, thus requiring less network capacity."
- Both ingredients needed (p. 14): "the combination of both active dendrites and sparse representations yield significantly better results than either one on its own." / "reducing sparsity translates to a sharp drop in accuracy".
- Why subnetworks help (p. 17): "errors will only propagate through the active subnetwork. Only the active neurons will update their feedforward weights and only the winning segment within those active neurons will update their dendritic weights. Thus, by utilizing context the brain can isolate information flow, and direct learning itself in a highly localized and task specific manner."
- **Role of context / recurrent context (p. 17) — the passage closest to a language/sequence setting:** "What is the role of context? In this article we have used a context vector that represents the current task. Prior experimental and modeling work shows the utility of various other types of context. In recurrent networks, it is possible to use the previous activity of the network as context for dendrites. In this case a layer of neurons becomes a powerful sequence memory system [Hawkins and Ahmad, 2016]. For sensorimotor inference, if the coordinates of an external reference frame is used as context, neurons can perform object recognition with actively moving sensors and by integrating information over time [Hawkins et al., 2017]. ... In the neocortex, if the inference results of neighboring cortical areas are used as context, dendrites can be used to disambiguate uncertain information and perform voting [Hawkins et al., 2017]."
- (p. 17): "Dendrites recognize patterns that best match their synapses, and up-modulate their neurons such that they are more likely to win. This in turn invokes context specific subnetworks that route information flow and gate learning in order to effectively learn and perform the task at hand."
- Multiplicative networks (p. 18): "In the case where the modulation function f involves multiplication, our Active Dendrites Networks are an instance of multiplicative networks. Jayakumar et al. [2020] demonstrated that multiplicative networks can excel in multi-task scenarios by learning dynamic representations in a task-specific manner."
- GLN/DGN contrast (p. 18): "Although inspired by dendrites these models 1) don't activate sparse subnetworks, 2) have fixed random dendritic weights (to model cerebellar dendritic branches), and 3) are binary classifiers".
- Future work (p. 18): "it will also be important to explore additional methods for generating context vectors for a given task. Another important direction for future research is to investigate sparse dendritic segments, following neuroscience evidence suggesting that each segment relies on just a handful of synapses [Branco and Häusser, 2011]."
- Gate is a lookup table at test time (p. 32): "The dendritic segments determine a context-dependent scale factor per neuron, based only on one of T possible context vectors. This scale factor is learned during training but then is static during testing." and "disallow future scenarios where the context vector changes dynamically per input."
- Historic sparse segments (p. 32): "In our previous work [Hawkins and Ahmad, 2016] we used extremely sparse dendritic weights (> 99% sparsity). These weights were dynamically determined during the learning process by sampling from components of the context vector. Consistent with the biology of active dendrites, the number of weights per segment was limited to a small constant (such as 30)."
- Few segments suffice (p. 33): "a single segment can learn to identify multiple context vectors, and thus there can be far fewer dendritic segments than unique context vectors."

## 3. Relevance to BDH-CQ reconstruction

**No match.** This paper is a feedforward MLP with multiplicative context gating; it has no recurrent state matrix, no update of the form S_t = S_{t−1} + U(D_t), no "linear correction rule on S", and no latent refinement loop H_{r+1} = F(H_r, S_K). Nothing in it can be read as describing Pathway's update rule or reasoning loop. The only two items that touch BDH-CQ's vocabulary, both weak:

1. The prototype store is a non-parametric memory updated additively by running means (p_j "updated to include each x ∈ X", Algorithm 1) — a linear correction of a stored vector by new data, but of a centroid, not of a Hebbian state, and with no read-out other than nearest neighbour.
2. The Discussion's pointer that "In recurrent networks, it is possible to use the previous activity of the network as context for dendrites. In this case a layer of neurons becomes a powerful sequence memory system [Hawkins and Ahmad, 2016]" (p. 17). That HTM sequence memory (not described in this paper) is a recurrent predictive state driven by lateral context on distal segments — a cousin of a state-update rule, but Hebbian/binary, not the Pathway form.

Treat this paper as irrelevant to the BDH-CQ reconstruction.

## 4. Relevance to distant context cues

**Which component carries context, and over what time scale:** none of the model's own components carry anything across time. The network is purely feedforward; each input is processed independently. The context vector is either (a) supplied externally at every step (MT10: one-hot task ID, constant over a 500-step episode and over all of training), or (b) recomputed at every step from the current input alone (permutedMNIST: argmin_τ ||x′ − p_τ||₂). The context is a very slow variable (constant per episode / per task) relative to the input stream, exactly like our stream identity inside a block — but the paper never has to *carry* it, because the environment hands it over at each step or the input itself is stamped with it.

**Given vs inferred:**
- MT10: GIVEN (task label), both at train and test.
- permutedMNIST method 1: given at train (to form prototypes), INFERRED at test (nearest prototype).
- permutedMNIST method 2: INFERRED at train (Hotelling-T² change-point clustering over batches, with the stated bias that a batch is single-task) and at test (nearest prototype). This is unsupervised with respect to task labels; the class labels are still used for the main loss.

**How the inference component is trained:** it is not trained by gradient. Prototypes are running means (not backprop; the paper nonetheless counts them as parameters, T × 784, p. 32); the clustering is a fixed statistical test with an "arbitrarily" chosen threshold p = 0.9 (p. 32). Only the *consumer* of the context (the dendritic weights) is learned, by backprop, with gradient only to the winning segment of winning units.

**What this does and does not tell us about our header layout [inference]:**
- Their inference works because every single input carries the full context signature (a pixel permutation is visible in each image). In our header layout the K and V tokens inside a block carry no stream signature at the moment they are written (the same keys occur in every stream; the stream-specific values are what must be learned); the only clean signature is the CTX token, 2P tokens back. Their nearest-prototype trick, applied to the current token, would return the key's identity, not the stream — i.e., it would reproduce exactly our "key splits" failure (recurrent gate 0/10, window gate 2/10 by key splits). A pooled mean over a block (their prototype = mean) would likewise be dominated by the shared K tokens. So the published mechanism does not solve the distant-cue problem; it sidesteps it.
- What it does establish, cleanly: *if* a distinct context vector is available at the write and read positions, a learned context→subnetwork mapping (segments + kWTA) is enough to partition representations with minimal interference, and does about as well as a hard-coded partition (XdG), even inferred at test time. This is the same message as our oracle-gate ceiling and our 5%-labelled-nudge result (10/10): the expressivity is there; the missing piece is producing c_t at distance.
- Their method-2 clustering is a *change-point detector over contiguous batches*. The header layout is also contiguous-by-block. A sequence analog would be a boundary detector that fires on the CTX token (a distribution shift) and latches a new context until the next boundary — but in our task the boundary is trivially the CTX token itself, so the hard part is the latch, not the detection.
- The paper's biological framing offers the right abstraction: a *separate* slow modulatory input path (distal/basal segments, plateau potentials lasting "as long as half a second") that is distinct from the fast content path. The paper's own suggestion for where such a context comes from in a sequence model is "the previous activity of the network" (recurrent) or "the inference results of neighboring cortical areas" (another layer/column) — i.e., exactly our recurrent gate and our untried per-layer residual gate.

## 5. Relevance to our gate

### 5.1 Mapping their mechanism onto ours

Their unit-level gate: gain_i = σ(u_{i,j*}^T c), j* = argmax_j |u_{ij}^T c|; then layer-level kWTA over units; gradient only to winners. Ours: g_t = softmax(W_g h_t) over k channels, soft, coupled across channels (raising one lowers the others), used for both write and read, with a hinge penalty to discourage degenerate splits.

Structural differences that matter:
1. **Independent per-unit gains vs a simplex.** Their gates are not normalized across units; several units can be fully on. Competition is injected afterwards by kWTA, which is a hard top-k. In our terms, that is "sigmoid routing + top-m" rather than softmax routing. The score (x_t·x_s)(g_t·g_s) would then no longer be bounded by 1 unless we renormalize after kWTA.
2. **Hard winner, plain gradients.** They use no straight-through estimator; losers get zero gradient and simply stay where initialization left them. With 2,048 units that is harmless; with k = 4–16 channels a loser channel can be permanently dead — the paper's regime relies on massive over-provisioning of units (2,000+ units, 5–25% active), i.e. the analog of our "spare channels (k = 16)" belief, taken to an extreme.
3. **Context-driven, not content-driven.** Their gate reads a *separate* context vector; the content x never enters the gate. Our gates read the token embedding v_t (window / recurrent) — mixing content and context is precisely what lets ours split by key. Their architecture argues for a dedicated context pathway whose input is as content-free as possible.
4. **Multiple segments = a small bank of context detectors per unit, with max.** For a one-hot context this is just a per-task gain lookup (one segment suffices, Table 4). The max over segments only buys something when context vectors are dense/overlapping and a unit should respond to several of them (App. B.3). For our S streams with k channels, the "segments" story matters only if the context representation is distributed rather than one-hot.

### 5.2 An "active-dendrite gate" for our channels — concrete proposal [inference, built from their equations]

Let c_t ∈ R^{d_c} be a context vector at token t (source below). For each channel i = 1..k keep J segments U_i ∈ R^{J × d_c} (J small, e.g. J = 2–4; their evidence says J ≥ #contexts is only marginally better than J = 1).

    d_{t,i,j} = U_{i,j} · c_t                                   (segment responses)
    j*_{t,i}  = argmax_j | d_{t,i,j} |                           (absolute-max selection, their Section 6.3)
    a_{t,i}   = σ( d_{t,i,j*} )                                  (per-channel gain in (0,1))
    g_t       = kWTA_m( a_t )                                    (keep top-m channels, zero the rest; m = 1 or 2)
    optionally g_t ← g_t / Σ_i g_{t,i}                           (restore the simplex so score stays bounded)

Gradients: plain autograd through abs-max and kWTA (as they do); no STE. Only the winning channel's winning segment is updated at token t. If dead channels become a problem (likely at k ≤ 16), add the one thing they did not need: a boosting/duty-cycle term (Numenta's own kWTA boosting from the spatial pooler, Cui et al. 2017) that raises a_i for channels that have not won recently — this is the principled version of our "copy the busiest row to the emptiest" split. Initialization: random, diverse per segment (they relied on it; they report random scattered responses at init, Figure 11). Keep g_t shared across layers as now, or compute it per layer from that layer's c_t.

**Soft-to-hard schedule.** Their ablation says gating without sparsity is weak and sparsity is "sharp[ly]" necessary (p. 14). The analog for us: anneal our softmax toward kWTA (temperature → 0, or softmax followed by top-m masking late in training) rather than relying only on the hinge penalty. This is consistent with our observation that the recipe needs an *early* hinge penalty — early soft exploration, later hard partition.

**Where c_t comes from (the unresolved part).** The paper offers three templates:
- (i) *Given*: c_t = the oracle stream one-hot — our Perfect gate; their MT10 result shows a learned mapping from a one-hot context to a sparse subnetwork works well with plain backprop and no tricks ("a one-hot encoding was adequate").
- (ii) *Inferred from current input by prototype matching*: c_t = argmin_τ ||h_t − p_τ|| over a bank of prototypes. Usable for us only if h_t already carries the stream — i.e., only on top of the per-layer residual gate (layer-1 attention copies the block header into each position, then layer-2's gate matches it against prototypes). Note their prototypes are *not* learned by backprop; a learned analog is a VQ/codebook with EMA updates — same mechanism, same collapse concerns.
- (iii) *Recurrent context*: "use the previous activity of the network as context for dendrites" (p. 17) — c_t = h^{(ℓ)}_{t−1} or an EMA of it. This is our recurrent gate with a different, decoupled readout; the paper gives no evidence on it beyond the HTM citation.
- (iv) *Train-time labels, test-time inference* (their method 1): give the stream label as c_t during training only to shape the segments, then switch to an inferred c_t. Our 5% nudge is a weaker version; their data (94.6 vs 94.3 at 10 tasks) suggest labels at train time are not even essential when the signature is readable from the input.

**For a language setting:** the paper says nothing specific about language. The relevant passages are the Discussion's "previous activity of the network as context" and "inference results of neighboring cortical areas ... voting" (p. 17), the explicit wish to allow "scenarios where the context vector changes dynamically per input" (p. 32), and "explore additional methods for generating context vectors for a given task" (p. 18). My reading: in language the natural c_t is a slowly varying summary of the discourse state (topic / speaker / document) produced by another layer or by a slow recurrent path, not the current token — which is the per-layer-residual-gate idea in our list.

### 5.3 Which of our beliefs it supports, contradicts, or warns about

Supports:
- The oracle partition is learnable by a gate given a clean context (MT10 87.5% vs 76.6% with identical information) — consistent with our Perfect-gate ceiling and the labelled-nudge 10/10.
- Spare capacity helps: 20 segments > 10 segments > 1 segment on MT10 (89 / 87.5 / 85.6), and thousands of units with 5–25% active — consistent with our k = 16 spare-channel result, and with "merges at k = S".
- Hard, sparse routing beats soft/dense: "reducing sparsity translates to a sharp drop in accuracy"; gating alone is weak without kWTA. Supports moving our gate toward kWTA / low temperature.
- Deriving the gate from processed features rather than raw input: on MT10, dendrites only on the second hidden layer (87.5%) beat dendrites on both (82.5%) and a single-layer network (58.9%) — mild support for our untried per-layer gate over the residual stream (gate at layer ≥ 2), though in the CL experiments both layers were gated, so the evidence is mixed.
- Gating both the write and read with the same g_t is analogous to their gating of the same units for the same context at every presentation — nothing contradicts it.

Contradicts / cautions:
- Their success with *inferred* context is specific to inputs that carry the context signature; it does not show that context can be discovered from the loss alone, which is our question. Nothing in the paper is label-free in our sense: the task label is given (RL) or the data distribution itself is the label (pMNIST).
- They make no claim about position-counting or key-splits; but their design principle (gate reads a separate context vector, never the content) is a direct diagnosis of why our content-reading gates split by key or by position.
- Pitfall: max-gating cannot switch a unit off; use absolute-max with sign retained (Section 6.3). If we ever gate with max-over-segments, copy this.
- Pitfall: with hard selection and plain gradients, non-winners never move. Their fix is overprovisioning; ours would need boosting or splits (which we already do by hand).
- Pitfall (pooled summaries): their prototype is a mean over inputs — fine when the mean carries the signature, useless when it is dominated by shared content (our K/V tokens).
- Pitfall (RL-style variance): they report high run-to-run variance and resort to best-of-5 selection (Exp. 2); our 10-seed success counts are the right metric, as we already use.
- Note the per-task gain is "static during testing" (p. 32): the whole dendritic apparatus collapses to a per-(unit, context) scalar table when contexts are few and discrete. For S discrete streams and k channels, an active-dendrite gate given the stream is literally a k × S table — the oracle one-hot is one point in that table. The interesting content is entirely in how c_t is produced.

### 5.4 Forget gate / horizon
Nothing in the paper. The only related item is biological: plateau potentials keep a cell near threshold for "as long as half a second" (p. 4), i.e. a modulatory state with a decay far slower than the input rate — a loose argument for a per-channel slow context state with its own (learned) decay, separate from the content memory's decay 0.95.

Inside the paper:
- **Algorithm 1 is truncated** in the extraction (steps after "update pj to include each x ∈ X" are lost at the p. 22/23 page break). The prose on p. 22 supplies the missing branch (new cluster Y_{M+1} ← X, prototype = mean of X).

## 7. Verdict

This paper does not touch BDH-CQ and does not solve distant context cues: its context is either handed over at every step (task ID) or is readable off every single input (permutation signature), and the model is feedforward with no component that carries anything across time. What it does establish, cleanly and with numbers, is the half of our problem we already believed: given a distinct context vector, a multiplicative per-unit gate driven *only* by that context, plus hard top-k competition, learns a near-orthogonal routing by plain backprop with no STE, no auxiliary loss and no special initialization, and does about as well as a hard-coded oracle partition (MT10 87.5% vs 76.6% for the same information fed additively; pMNIST 81.4% at 100 tasks, 76.9% fully unsupervised at the task level). Its two transferable design lessons for our gate are (1) decouple the gate's input from the content path — our content-reading gates split by key/position precisely because they read content — and (2) make the routing sparse and hard (kWTA / absolute-max), since in their ablations gating without sparsity is weak and sparsity is the component whose removal causes the "sharp drop". Its one warning is that hard selection with plain gradients leaves non-winners frozen, which they absorb by overprovisioning thousands of units; at k ≤ 16 we would need boosting or our split heuristic. The actionable next steps it suggests are modest: (a) try a sigmoid+top-m ("active-dendrite") gate fed by a per-layer residual context rather than the raw embedding, with an annealed hardness; (b) read Flesch et al. 2022 (arXiv:2203.11560, Hebbian context gating with *exponentially decaying task signals*) and Heald et al. 2021 (COIN) before designing a context-carrying path, since both are about exactly the inferred, decaying context signal we lack. Confidence: high on what the paper says (full read, numbers verified against the parameter counts); moderate on the transfer to our k-channel setting, which rests on my inferences in Sections 4–5, not on anything the paper tested.
