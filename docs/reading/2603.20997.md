## 0. What this paper is, in one paragraph

An empirical catalogue (20+ runs, no theorems) of which **token representations** allow a **dot-product router** to pick the right far-away token for sparse attention inside a hybrid SSM/attention model. The routed object is a **position in the sequence** (which tokens get expensive attention) — not an MoE expert, not a memory slot, not a head. **Routing is directly supervised in every experiment** by an auxiliary cross-entropy loss on the correct position. Headline: routers fed raw embeddings, unidirectional recurrent states, mean/max-pooled segment summaries, a global mean, or Fourier-mixed features land at 0.9–29% routing precision (chance ≈ 1.6%); one layer of attention (causal or bidirectional), a bidirectional Mamba scan, a single Perceiver inducing point, or sparse bidirectional attention placed *before the same router* gives 98.4–99.7%. The slogan is "two ingredients": (1) per-token representations carrying context, (2) pairwise token comparison in the router.

## 1. What the paper actually does

### 1.1 The setting — what exactly is routed, and where

- **Architecture under test: FCI = Flow–Council–Investigator** (p. 5). *Flow* is a Mamba-style recurrent backbone; the *Investigator* is the **router** that scores every position pair and selects top-k positions; the *Council* is standard multi-head attention **restricted to the selected positions**, followed by an FFN, then a prediction head.
- **What is routed:** tokens (positions) to the sparse attention layer. "A router decides which tokens get attention" (Fig. 1 caption, p. 2). Routing precision = whether the Investigator's top-k selection contains the correct answer position (for MQAR: "Investigator selects the correct key position", Table 1 caption, p. 10). It is not MoE expert routing, not memory-slot routing, not token-to-head routing. It is closest to **retrieval of context positions** (which the paper itself relates to RAG/DPR/ColBERT/BM25, p. 4).
- **The question studied:** "what representations the router needs to function" (p. 2). Everything except the representation fed to the Investigator is held fixed: "All experiments share the identical Investigator, Council, prediction head, and training procedure … Only the representations fed to the Investigator differ." (p. 5)

### 1.2 Tasks, model sizes, data (p. 4–5, p. 14)

- **Distant Evidence Retrieval (synthetic, main task).** Verbatim: "Each sequence (L=512) contains a query key token kq at position q and a matching (key, value) pair placed far away (distance ≥ 200 tokens), with plausible distractor pairs placed nearby. All tokens share the same vocabulary range [1, 256) to prevent range-based shortcuts. A 4-layer Transformer achieves 100% accuracy when the answer is near but only 1.9% when far (chance = 1.6%), confirming the task isolates long-range content matching." (p. 4). What makes a distractor "plausible" is **not specified** (see §6).
- **MQAR** [22]: "N=16 key-value pairs placed in a sequence of length 256, followed by a query key." (p. 4)
- **HotpotQA** [33]: sentence-level retrieval precision only ("at least one supporting sentence appears in retrieved segments", selecting 2 of 16 segments; random = 12.5%). Only BM25 is run on it. No end-to-end QA accuracy.
- **Sizes:** "multiple scales (200K to 1.4B parameters)" (p. 1); the core synthetic model is **486K parameters** ("exact token matching at 486K parameters", p. 14); routing projection width d = 128 (inferred from "34 of 128 dimensions", p. 6). Pre-trained frozen backbones: Pythia-1B (causal Transformer), Mamba-370M, Mamba-1.4B.
- **Data/training:** "8000 sequences, batch size 32, 40 epochs, AdamW with OneCycleLR, routing loss weight decayed from 1.0 to 0.1" (p. 5). "Key results (the phase transition and contrastive failure) were verified across 3 random seeds with <2% variance in routing precision; … 1-layer routing: 98.4% ± 0.3% across runs" (p. 5).

### 1.3 The components, in the paper's notation

**Flow (recurrent backbone), p. 5:**
> "A Mamba-style selective SSM with input-dependent state transitions: ht = Āt ht−1 + B̄t xt , yt = Ct ht . Each block includes depthwise convolution, SiLU gating, and selective scan."

i.e. h_t = Ā_t h_{t−1} + B̄_t x_t, y_t = C_t h_t (standard Mamba; no further detail).

**Investigator (router), Eq. (1), p. 5.** The extraction gives the fragments `1 X (Wqh xi)⊤ (Wkh xj)` / `sij = ... p` / `H d/H` / `h=1`. **Reconstruction** (consistent with the abstract's "sij = qi⊤ kj"):

    s_ij = (1/H) · Σ_{h=1..H} ( (W_q^h x_i)^T (W_k^h x_j) ) / sqrt(d/H)        (1)

> "Multi-head dot-product scoring across all position pairs … Top-k selection with neighbor expansion (selecting j also selects j+1, because the task places value tokens immediately after their keys). An auxiliary routing loss Lroute = CE(sq,: , a) directly supervises routing." (p. 5)

So L_route = CE(s_{q,:}, a): a softmax-cross-entropy over all n positions for the query row, with the true answer position a as label. "When we refer to Wq, Wk without head superscripts in the analysis sections, we mean the combined (head-averaged) routing projection." (p. 5)

**Rank-1 router (the O(n) variant), p. 10:**
> "replaces the full Investigator (O(n2) pairwise scoring across all position pairs) with a rank-1 pairwise projection: each token gets a scalar fingerprint si = v⊤hi, and routing scores are si·sj (rank-1 in the query-key product). This reduces inference-time routing from O(n2) to O(n)"

and p. 12: "compute a scalar fingerprint si = v⊤hi per token, then select top-k by query-key fingerprint product." Training still "materializes the full O(n2) score matrix during training (for the auxiliary routing loss)" (p. 12).

**Council:** "Standard multi-head Transformer attention restricted to the positions selected by the Investigator, followed by a feed-forward network." (p. 5)

**Worked example (p. 5):** query token 42 at position 51, answer (42, 17) at positions 350–351, distractors near the query. "With Transformer preprocessing, position 51's representation encodes (via value aggregation) that position 350 matched its content. The Investigator's learned projections extract this signal: s51,350 is highest … Without Transformer preprocessing, x51 contains no information about position 350, so s51,350 is indistinguishable from noise — routing fails."

No equations are given for the bidirectional Mamba, the Perceiver hubs, the segment router, the bandits, the "memory banks", the DOL loop, or the MF-OFUL controller — all are prose only.

### 1.4 Training details that matter

- Routing is **supervised** everywhere (L_route with label a), weight annealed 1.0 → 0.1 over training. There is no label-free routing experiment in the paper.
- End-to-end ("E2E") vs. frozen backbone is a major axis: frozen Pythia-1B / Mamba give 22–35%; the same frozen Pythia with one trainable bidirectional attention layer inserted ("bridge") gives 99.4%.
- Contrastive pretraining of the projections (InfoNCE) was tried as an alternative training signal: 1.6% (frozen projections) / 2.2% (finetuned).
- "2 training signals" and "2 granularities" (p. 2): the granularities are token-level vs. 32-token-segment routing; the two training signals are most plausibly routing-CE vs. InfoNCE (not stated explicitly — inference).

**Verification of the claim we were given ("pooled/causal-summary routers reach only 1–29% and a cheap pairwise preprocessing recovers it"):** the numbers check out, with one correction of framing. The 1–29% cluster is: abstract p. 1 "recurrent models (Mamba-1.4B: 29%), memory banks (12%), bandits (0.7–3.6%), contrastive pre-training (1.6%), and 12 other approaches all cluster at 1–29%"; §4.3 p. 6 "Every learned approach that avoids pairwise token comparison — regardless of representation (Flow, embeddings, bidirectional Flow), summary method (mean-pool, max-pool), or scoring function (linear attention [9], segment-level dot product) — clusters between 9–29%, with most approaches near 24%." Causal (unidirectional) recurrent summaries: 2.2% when trained E2E, 22.5–28.7% when frozen pretrained. Pooled summaries: global mean 1.9%, segment mean/max pool ≈ 24–26%. The correction: **the recovery is not only "pairwise preprocessing"**. In the best configurations (bidirectional Mamba 99.5%/99.7%, Perceiver M=1 98.8%) the preprocessing contains **no** pairwise token–token computation; what is constant across all successes is (a) a mixing step that puts context into each token's vector and (b) the **pairwise dot-product router** trained with the supervised routing loss. One causal attention layer also works (98.9%) — so "attention before the router" is sufficient but not necessary, and "bidirectional" is not strictly necessary either when the preprocessing is attention (§6 discusses this tension in the paper's own narrative).

### 1.6 The "pairwise preprocessing" fix, precisely

There are two separate pairwise stages and the paper is explicit that they are different (Table 2 caption, p. 11: "systems with attention preprocessing AND pairwise routing have pairwise computation at two stages"):

1. **In the router:** Eq. (1), s_ij over all pairs (i, j), the query row s_{q,:} supervised by CE against the answer position; top-k with neighbor expansion. Cost O(n²·d) (training and full-Investigator inference). The rank-1 version: scalar fingerprint s_i = v^T h_i, score s_i·s_j, O(n·d) at inference. So yes — it compares the **current (query) token with every candidate context token**.
2. **Before the router (preprocessing that "writes relational information into per-token representations", p. 8):** any one of: one attention layer (full; causal or bidirectional; more layers do not help), sparse bidirectional attention (window 32 + 16 random global tokens, O(n·w)), bidirectional Mamba (forward + backward selective scans, O(n)), Perceiver inducing points (M learned hub vectors cross-attend to all tokens then broadcast back, O(Mn); M = 1 suffices). It is a *short attention* in the sense of one layer; it is **not** a convolution (Fourier/global convolution fails at 0.9%, and the Mamba blocks' depthwise conv does not rescue unidirectional Flow at 2.2%).

What fails as preprocessing: nothing (raw embeddings, 1.2%), unidirectional recurrence (2.2%), global mean + broadcast (1.9%), Fourier mixing (0.9%), frozen features not trained with the router (22–35%).

Observation (mine, not the paper's): with the rank-1 router the score s_q·s_j ranks candidates j by s_j alone up to the sign of s_q. So in the paper's best configuration the "pairwise comparison in the router" is nearly vacuous; the bidirectional preprocessing has already computed, per token, a scalar "I am the matching token" flag (the backward scan carries the query identity to the answer position). The paper half-acknowledges this: "one dimension of bidirectional information captures nearly all routing signal" (p. 10). This matters for how we read "pairwise comparison is inescapable" — the honest reading is: *the match between query and candidate must be computed somewhere and written into the candidate's (or query's) representation before a cheap router reads it.*

### 1.7 Theory / intuition for why pooled or causal summaries fail

There is **no formal theory**: no theorem, no rank bound, no softmax-bottleneck or gradient-signal analysis. What is offered:

- **Information loss by compression** (p. 3): "at position t, the recurrent state ht is a fixed-dimensional compressed summary of positions 1 . . . t. Individual token identities are progressively overwritten. This unidirectional compression is what makes content-based routing fail: position q has no information about future position a > q."
- **Asymmetric (missing future) context** (p. 13): "The issue is asymmetric context: at position t, the recurrent state encodes positions 1 . . . t but nothing about t+1 . . . n. The router compares position q to position a > q, but q's representation has no information about a, producing indiscriminate scores."
- **Pooling destroys per-token discriminability** (p. 11): "Global mean pooling collapses all tokens into a single vector, destroying per-token discriminability. Fourier mixing applies a global spectral transform but does not create relational structure — it preserves frequency information, not token-pair relevance." And segment routing "compares query representations to segment summaries — a coarse, non-pairwise operation." (p. 7)
- **The match must be written into the representation** (p. 8): "contrastive loss teaches which tokens match but does not update representations to encode these matches. The match result must become part of the representation, not something the router must independently discover."
- **The signal is latent and linear-access-only** (p. 6): matching tokens have a *negative* cosine gap (−0.154); random W_q, W_k drop 98.4% → 2.6%; W_q W_k^T has 90% of its energy in 34 of 128 dimensions. "The content-matching signal occupies roughly a quarter of the representation space — invisible to full-space cosine similarity but accessible to learned linear projections."
- **Not the optimizer** (p. 7): "The routing bottleneck is not the learning algorithm — it is the quality of the representations."
- Nearest thing to a rank statement: rank-1 routing suffices (98.8–99.7%), "The routing signal is essentially one-dimensional." (p. 12)

### 1.8 Learning dynamics the paper reports

- **Phase transition / grokking-like plateau** (p. 5): "routing precision stays near chance for 9 epochs, then jumps from 2.8% to 99.4% in a single epoch (epoch 10), followed by task accuracy climbing from 4.7% to 74.5% over the next few epochs." "No other condition shows any phase transition — all remain flat at chance throughout training." On MQAR the transition is at epoch 5; the Pythia bridge reaches 95% by epoch 6 and ≈99% by epoch 29. Note the order: **routing is learned first, task accuracy follows** — but routing has its own direct supervision here, so this order is not evidence about label-free discovery.
- **Instability near a budget threshold** (p. 7): MF-OFUL at 50% budget "oscillates between 0% and 90%+ across epochs before eventually stabilizing"; at 25% "routing collapses to 1.6% permanently, indicating a sharp threshold between sufficient and insufficient pairwise coverage."
- **Supervision schedule:** routing loss weight decayed 1.0 → 0.1; OneCycleLR.
- **Shortcut awareness in task design:** "All tokens share the same vocabulary range [1, 256) to prevent range-based shortcuts" (p. 4); neighbor expansion (j → j+1) bakes the key-then-value layout into the router.
- Not discussed at all: MoE-style collapse to one route, load balancing (only mentioned as what MoE "often relies on", p. 4), merges/splits, curricula, straight-through estimators, the router learning position/key identity instead of content.

## 3. Relevance to BDH-CQ reconstruction

Essentially none; nothing matches Pathway's wording.

- The only state-update equation is Mamba's h_t = Ā_t h_{t−1} + B̄_t x_t (p. 5). It is a *linear correction on a vector state* with input-dependent coefficients — formally of the shape S_t = U(S_{t−1}, D_t), but it is just a selective SSM, not an outer-product/associative memory, and the paper says nothing about it beyond that line.
- The one iterative-refinement mechanism, "Decision-Optimal Learning (DOL) — where routing is refined over 2–3 rounds using execution feedback from the Council" (p. 8), **failed** (1.7%). It refines a routing *decision*, not a latent reasoning state over a fixed memory, so it is not an analogue of H_{r+1} = F_θ(H_r, S_K); at most it is weak evidence that iterating a cheap router does not substitute for the missing computation.
- The Perceiver inducing-point hub (M learned vectors cross-attend to the whole sequence and broadcast back; p. 10) is the closest structural cousin of "a latent H that reads a memory S" — a single learned read-out vector reading the whole context — but it is a preprocessing step, not a reasoning loop, and there is no recurrence over it.
- Nothing on Sudoku/ARC-style reasoning, nothing on halting or R-step loops.

## 4. Relevance to distant context cues

**What is distant in this paper is the target, not the cue.** In Distant Evidence Retrieval the *cue* is the query token itself at position q (local, raw-embedding-identifiable); what is ≥ 200 tokens away is the matching key–value pair. The router must compare the query's content with every far candidate. This is the MQAR/associative-recall family, not our header layout (one CTX token at block start determining the routing of the following 2P tokens). **The paper does not study a header/boundary cue that must be carried forward across a block**, and none of its router variants is a "latch".

**How context is carried across distance, and by what:**
- *Attention (1 layer, causal or bidirectional):* instantaneous, no time scale; "value aggregation … writes the match results back into each position's representation" (p. 8). Causal 1L E2E: 98.9%.
- *Bidirectional Mamba:* forward + backward selective scans; input-dependent (learned) decay, so the time scale is content-dependent, not fixed; 99.5%. The paper's unidirectional-recurrence failure is specifically about **future** context ("position q has no information about future position a > q", p. 3) — not about a recurrence's ability to carry a *past* token forward.
- *Perceiver hub (M=1):* one learned global summary vector built by cross-attention, broadcast to all tokens; 98.8%. Contrast with the global mean (1.9%): a content-selective global summary works where a uniform average does not.
- *Sparse attention with 16 random global tokens:* the global tokens act as relays (99.7%).

**Given or inferred?** The cue is given implicitly (the query token is in the input); the *route* is given explicitly as a label through L_route = CE(s_{q,:}, a) in every experiment. The representation that encodes "I match the query" is learned, with that supervision plus the task loss, through the preprocessing layer. Frozen representations trained without the routing objective fail (Pythia 35%) even though "pre-trained causal representations already contain the information routing needs" (p. 12).

**Mapping to our header layout.** In our task the cue (CTX_s) lies in the *past* of every token that needs it (writes at VAL, up to 2P tokens later; reads at the query KEY with CTX one back). So the paper's bidirectionality argument does not apply as an objection to a causal design. The applicable parts are: (i) the router must read a representation into which the cue has already been *written* by an upstream mixing step (our window gate reads 3 raw embeddings — the paper's "No preproc + pairwise: 1.2%" regime once the cue is >2 back); (ii) uniform pooled summaries dilute the cue (segment mean/max 24–26%, global mean 1.9%, our multi-scale EMA gates 0/10); (iii) a *content-selective* summary (Perceiver M=1; input-dependent Mamba decay) can work at O(n). Our own "5% labelled nudge → 10/10" result is the small-scale analogue of the paper's regime (supervised routing on an architecture that can express it); the paper never leaves that regime.

## 5. Relevance to our gate

First, the correspondence. Our score (x_t·x_s)(g_t·g_s)decay^(t−s) already contains the paper's ingredient (2): g_t·g_s is a rank-k bilinear *pairwise* comparison between tokens t and s. What our gate lacks for the header layout is ingredient (1): a per-token input that carries the stream identity. The paper's whole result set says that this input must come from a mixing layer trained together with the router, and must not be a uniform pool.

**(1) Slow EMA / integrator state feeding the gate — the paper warns against it.** An EMA is a recency-weighted, content-blind pool; every such summary in the paper fails (global mean 1.9%, segment mean/max pool ≈ 24–26%, compressed recurrent state 2.2% E2E / 22–29% frozen; quotes 5, 11, 13, 20). Our multi-scale EMA result (0/10) is consistent. Mechanism (inference, consistent with p. 11): in a block [CTX, K, V, …] the header is 1 of 2P+1 tokens; an EMA mixes it with K/V identities that vary within the block, so the gate sees mostly key/value content — exactly the "key split" shortcut we observe. If an integrator is kept, make it **content-selective** (see (3)), not uniform.

**(2) Per-layer gate over the residual stream — the paper's strongest support.** This is literally the paper's prescription: an upstream layer writes context into each token's vector; the router reads that vector; everything is trained end-to-end. Quotes 15, 16, 23, 25; numbers: causal 1L E2E 98.9–99.2%, bidir Mamba 99.5%. Concretely:
- g_t^{(ℓ)} = softmax(W_g^{(ℓ)} φ(r_t^{(ℓ)})) with r_t^{(ℓ)} the residual entering layer ℓ (so it contains layer ℓ−1's retrieval) and φ a small *trainable* nonlinearity. The bridge result (frozen Pythia 35% → 99.4% with one trainable layer in between) says a bare linear read-out of features not shaped for routing is not enough; give the gate at least one trainable hidden layer and let gradients flow into layer ℓ−1.
- Keep the window gate at layer 1 (local cues only) and use the residual gate from layer 2 on; this also avoids circularity (the gate at ℓ depends on the retrieval at ℓ−1, not ℓ).
- Two caveats the paper itself forces: (a) in the paper the upstream layer is trained with the *supervised* routing CE; ours gets gradient only through the task loss via the memory read, which is weaker and could stay on the plateau (p. 5: zero-layer conditions "remain flat at chance throughout training"); (b) for layer 1 to copy CTX_s into K/V positions, our content-addressed read needs x_K·x_CTX ≠ 0 — a learned shared "header-seeking" component in the embeddings (my inference; the paper has no equivalent because attention's QK^T can learn arbitrary query→key maps).
- **Diagnostic to run before building it** (the paper's own tool, linear probing [35], p. 6): train the current model on the header layout, then fit a linear probe from r_t^{(2)} at K/V positions to the true stream. If the probe fails, no gate on the residual can succeed and the embedding/decay must change first; if it succeeds, the per-layer gate is viable. Do **not** diagnose with cosine similarity of stream-mates — the paper shows the routing signal can be in a ~34-dim subspace with *negative* cosine gap (quotes 4, 10).

**(3) Boundary-latched register — supported by analogy, untested in the paper.** The closest evidence is the Perceiver M=1 hub (98.8%) versus global mean (1.9%): one learned vector that *selects* what to summarise works; a uniform average does not. A causal latch c_t = (1 − m_t) c_{t−1} + m_t W v_t with m_t = σ(w_m·v_t + b) is the forward-only, input-dependent-decay version of the paper's Flow (Ā_t, B̄_t input-dependent) and of the M=1 hub, and the forward direction suffices for a past cue (§4). Initialization suggestion (mine): b negative so the register starts mostly closed (avoids EMA-like dilution from step 0); the register should be a separate low-dimensional state (the paper's rank-1 finding says one or a few dimensions carry the routing signal). Learning *when* to latch label-free is the part the paper does not address at all.

**(4) Routing by what the memory retrieved — supported in spirit; it is the paper's "step 3".** "Value aggregation (·V): writes the match results back into each position's representation" (p. 8) is the mechanism that made routing possible; our memory read y_t is exactly such an aggregation. g_t = softmax(W_g φ([v_t; y_t^{(1)}])) — with y_t^{(1)} the previous layer's read (or a dedicated gate-free auxiliary read with a slower decay, e.g. a single learned query vector u reading Σ_{s<t}(u·x_s)decay'^(t−s) v_s — the causal analogue of the M=1 hub, content-selective rather than uniform). Designs (2) and (4) are nearly the same proposal; (4) just makes the retrieval the explicit gate input.

**What the paper supports / contradicts / warns about in our existing results:**
- Supports: the window gate working for the grouped layout (cue within 3 tokens) and failing for the header layout — raw embeddings "lack any contextual information" (Table 2 footnote, p. 11).
- Supports: our plateau-then-jump experience and plateau-triggered interventions. The paper's successful runs sit at chance for 9 epochs before a one-epoch jump (quote 9); failing conditions are flat forever. Train long enough to distinguish the two.
- Supports (weakly): instability near thresholds — MF-OFUL oscillating 0–90% at 50% budget rhymes with our eight-stream recurrent-gate instability.
- Does not support over-reading "unidirectional recurrence is a dead end" against our recurrent gate: that result is about missing *future* context (quote 26), which our task does not need. The relevant warning for a recurrent gate is overwriting/dilution (quote 5), which we did observe (position counting, key splits).
- Contradicts nothing we have measured. The paper's 98%+ numbers are all **with full routing supervision**; its negative results are therefore *stronger* for us (if a pooled or causal-summary router cannot learn routing even with labels, it will not discover it label-free), but its positive results are *weaker* for us (they may not transfer without labels).
- Pitfalls it adds: do not evaluate gate inputs by geometry (cosine); keep the gate's projection learned (random projections: 2.6%); expect all-or-nothing behaviour rather than gradual improvement; a representation can contain the information yet be unusable by a linear router (Pythia 35%) — add trainable depth between residual and softmax.
- If we ever accept labels: the paper's schedule is strong routing supervision early (weight 1.0) annealed to 0.1 — the analogue of our "5% nudge" would be a decaying nudge, not a constant one.
- Forget gate / horizon: the paper's backbone is a selective SSM with input-dependent Ā_t (p. 5) and its task needs ≥ 200-token retrieval, which a fixed decay 0.95 (half-life ≈ 14) could never do; the paper gives no results on horizon, but its only recurrence is a learned, input-dependent one.

## 6. Loose threads

1. **No appendices, no code, no figures in the text.** Figure 4 ("all 20 approaches") is the only place the full landscape is listed; we have just its caption.
2. **Routing is supervised in every experiment** (L_route = CE(s_{q,:}, a), weight 1.0 → 0.1). The paper never tests label-free discovery of routing. This is the single biggest limit on transfer to our question.
3. **Internal numerical inconsistencies.** 1-layer attention is 98.4% (§4.1), 98.9%/99.2% (§4.6 table: bidir/causal), 99.1%/98.9% (Table 2 and ablation: bidir/causal), i.e. the causal/bidir labels are swapped between the §4.6 table and Table 2. Two different rank-1 numbers (98.8% "Rank-1 bidir projection", Table 2; 99.7% "Bidir Mamba + rank-1 router", §4.6/Table 3) with the relation between them never stated. All within a few points, but it suggests tables assembled from different runs.
4. **"Memory banks (12%)"** appear only in the abstract and conclusion; never described.
5. **"Rank" column** in Table 2 is never defined (presumably mean rank of the answer position among scores; 1.5–1.6 for successes, 240 ≈ random over 512 for raw embeddings).
6. **Task ambiguities.** "Plausible distractor pairs" is undefined; if distractors do not share the query token, the 1.2% of raw-embedding + pairwise router is hard to explain (token-identity matching should find the key). The baseline "4-layer Transformer … only 1.9% when far" is also surprising for a full-attention model on a 512-token sequence; positional encoding and training of that baseline are not given. Chance = 1.6% is stated but not derived.
7. **Narrative tension the paper does not resolve:** it insists on "bidirectional context" (abstract, conclusion: "Bidirectionality in preprocessing is necessary") yet causal attention 1L gives 98.9–99.2% and Table 2's caption says "The divide is not causal-vs-bidirectional but pairwise-vs-compressed." For us this is good news (a causal design is not ruled out), but it means the paper's own explanation for *why* causal attention works ("router's pairwise comparison + E2E gradients suffice", Table 2 footnote) is thin.
8. **Rank-1 scoring is almost not pairwise** (my inference, §1.6): s_q·s_j ranks by s_j up to sign. The real work in the best configuration is done by the bidirectional preprocessing. Likewise, the segment-routing failure (25.6%) could partly be a supervision-granularity effect (CE over 16 segments vs. 512 positions) rather than a representational impossibility; the paper attributes it entirely to "lacks pairwise precision".
9. **Routing ≠ task accuracy.** Even at 100% routing, MQAR accuracy is 55.6%; synthetic accuracy tops out ≈ 75%; bidir Mamba routes at 99.5% but reasons at 32.2% vs. Perceiver M=16 at 73.0% ("Routing needs only bidirectional context (even compressed); reasoning benefits from richer relational structure", p. 11). For us: a gate that routes correctly is necessary but the memory read must still carry the value — keep the oracle-gate ceiling as the reference.
10. **Semantic matching is open:** 0.6–11% when the match is by meaning rather than token identity (p. 14) — a "possible third ingredient".
11. **Adaptive budget:** MF-OFUL 50% → 91.2% with oscillation, 25% → permanent collapse at 1.6%; "sharp threshold between sufficient and insufficient pairwise coverage" (p. 7).
12. **Limitations (p. 14):** Python sequential scan (so small scale only); no comparison with Based/GLA/HGRN2; InfoNCE only; "architectures with cheaper routing (e.g., MoE gating) may behave differently"; rank-1/sparse bridges untested at scale; O(n²) training cost for the aux loss.
13. **Missing citations:** Perceiver / Set-Transformer inducing points are used but not cited; ref [36] (Yun et al., universal approximation) is listed but never cited in the text.
14. **Provenance:** single-author preprint, strong rhetoric ("exhaustively", "inescapable") relative to one synthetic task family at 486K params plus frozen-backbone probes. Treat the qualitative pattern as solid (it matches our own data) and the specific percentages as indicative.

## 7. Verdict

This paper does not touch label-free discovery, header/boundary cues, latches, channel routing, or anything BDH-CQ-shaped; its routing is supervised throughout and its "distant" element is the target, not the cue. Its transferable lesson is nonetheless sharp and matches our own data: a router (our gate) cannot extract a context it is not given — raw embeddings and uniform pooled or compressed summaries fail even with direct supervision (0.9–29%), and what works is reading per-token representations into which an upstream, jointly-trained mixing step has already written the relevant context (98–99.7%), with the signal living in a low-dimensional learned subspace invisible to cosine geometry. That argues concretely for our designs (2) per-layer residual gate and (4) routing by what the memory retrieved (they are the same idea; add a trainable nonlinearity between residual and softmax, gate at layer ℓ from layer ℓ−1's output, and probe the residual for stream identity before building), argues against (1) a uniform EMA integrator (consistent with our 0/10), and gives analogical support for (3) a content-selective latch (Perceiver M=1 98.8% vs. global mean 1.9%; input-dependent decay). The bidirectionality warnings do not apply to our past-cue task. Confidence: fairly high that the qualitative direction is right (it is corroborated by our own grouped-vs-header results), low on quantitative transfer (different task, full routing supervision, small single-author study with inconsistent tables), and the real open problem — getting the task loss alone to create the pressure that the paper's L_route supplies — remains untouched by this paper.
