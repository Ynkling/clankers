# Flesch, Nagy, Saxe & Summerfield — "Modelling continual learning in humans with Hebbian context gating and exponentially decaying task signals" (arXiv 2203.11560 v2)

Source read: `2203.11560v2.txt` (48 PDF pages; page numbers below are the PDF pages recovered from the form-feed breaks in the text). Equations in the extraction lost all sub/superscripts, so every equation below is a **reconstruction from the surrounding prose plus the authors' released code** (`github.com/summerfieldlab/Flesch_Nagy_etal_HebbCL`, files `hebbcl/trainer.py`, `hebbcl/model.py`, `hebbcl/parameters.py`, `utils/data.py`, `runner.sh`, `sluggish_runs.py`, `run_diff_neps.py`, fetched 2026-10-08). Where the code and the paper text disagree I say so. Anything labelled "code" is not in the paper text.

**One-paragraph summary.** A one-hidden-layer ReLU MLP (25 blob pixels + 2 one-hot context units → 100 ReLU → 1 sigmoid output) is trained on two orthogonal categorisation rules either blocked or interleaved. Vanilla SGD forgets catastrophically under blocked training and learns context-gated orthogonal representations under interleaved training. Two "algorithmic motifs" flip this to the human pattern: (i) **"sluggish" task units** — the explicit context cue fed to the network is an exponential moving average over trials, `x̃_t = (1−α) x_t + α x̃_{t−1}`, which blurs the cue under interleaving (switch cost → the network learns one shared "diagonal" rule) and is harmless under blocking; (ii) a **Hebbian (Oja's rule) step after every SGD step** on the input→hidden weights, which drives each hidden unit's context weights to ±(first principal component of the mean-centred input), i.e. to anti-correlated signs across the two contexts, so the ReLU partitions the hidden layer into two context-specific subpopulations — an *learned* version of hand-set context gating (XdG-style). The context is **given** on every trial as an input; nothing about the context is inferred from the data except (in the main blobs model) *which input dimensions carry it*, via PCA, and that only works because the cue was scaled to be the dominant variance direction. The model is fitted to humans (200 trials/task) and reproduces blocked > interleaved accuracy, the congruency effect and the angular-bias decomposition. Two tasks only; feedforward only; the cue is never absent.

## 1. What the paper actually does

### 1.1 Task and inputs (pp. 6–8, 24)
- Stimuli: 5×5 grid of Gaussian "blobs" (25-pixel grayscale images; code: each blob normalised to max 1, pixels in [0,1]). Task 1: category boundary on the x-position; task 2: on the y-position. Reward R ∈ {−2,−1,0,1,2} for "accept"; "reject" = 0 (p. 25).
- "In all simulations, the rules are explicitly cued by a contextual signal (which we also refer to as 'task signal'), and fully supervised feedback is provided based on the context (task) and stimuli [59]." (p. 6)
- Curricula: blocked = all of task A then all of task B; interleaved = random shuffle. 10,000 trials total, 5,000 per task (Methods p. 24 says "all 500 trials from one task" — typo for 5000; code: 200 episodes × 25 trials per task). Human-fit runs: 200 trials per task (p. 28; code `n_episodes=8`). Evaluation: 50 test trials (2 tasks × 5 × 5), no learning, 50 independent runs per condition.

### 1.2 Architecture and how the cue enters (p. 24; code `model.py`)
- "a feed-forward neural network with 25 input units (for the flattened and downscaled grayscale images) and two additional task units, a hidden layer with 100 Rectified Linear Unit (ReLU) non-linearities and a sigmoidal output unit." (p. 24)
- The cue enters **at the input layer, as two extra input units concatenated to the 25 pixels**, so it reaches the hidden layer only through the input→hidden weight matrix, i.e. as an **additive, weighted bias on each hidden unit's pre-activation**:

  ```
  x_h = x · W_h + b_h          (x ∈ R^27 = [25 pixels, 2 context units];  W_h ∈ R^{27×100})
  y_h = ReLU(x_h)
  y   = y_h · W_o + b_o        (training loss uses sigmoid(y); see 1.5)
  ```
  (reconstructed from p. 24 and `Nnet.forward`). There is **no multiplicative gate**: gating is purely "context-dependent deactivation of units" by pushing the ReLU input negative (p. 8: "the context signal acts as additive bias to filter out irrelevant dimensions via context-dependent deactivation of units that encode task-irrelevant information [15]").
- Context code: one-hot, "e.g. [0 1] for task 1 and [1 0] for task 2" (p. 7), multiplied by a **"context offset"/`ctx_scaling`** (code default 2; runner uses 1–6 depending on run; trees supplement c = 4, p. 40), then **mean-centred** (p. 27: "the one-hot inputs [1,0] were converted to [0.5, −0.5]"). Code: `StandardScaler(with_std=False)` over the whole training set, then for the blocked curriculum "remove info about 2nd task during training on 1st task" by zeroing the second context unit on task-A trials. So during block A the cue is [+c/2, 0], during block B it is [−c/2, +c/2] — matching p. 27: "we used a one-hot signal for the first task and introduced a mean-centred signal for the second task during training."
- Initialisation (p. 24): input→hidden weights Gaussian, "variance σ = 0.01" (Results p. 7 says σ = 0.001 — inconsistent; code `weight_init = 1e-2`, so 0.01 is right, used as a std multiplier on `randn`). Readout weights: the extraction shows "σ = [blank] / √" — reconstruction: **σ = 1/√n_hidden = 0.1**, confirmed by code (`randn(n_hidden, n_out) * 1/np.sqrt(n_hidden)`). "All biases were initialised to zero" (p. 24) — code: hidden bias is a constant 0.1 and, because of how it is constructed (`nn.Parameter(zeros) + 0.1` yields a plain tensor), is **not trained**. Small weights = "rich" regime (see 1.7).
- Deeper variant (supplement p. 40): 24×24×3 = 1728 tree-image pixels + 2 task units → 100 ReLU → 100 ReLU → sigmoid; the cue enters only the first hidden layer (code has an unreported `ctx_twice` option feeding the cue to both hidden layers, "similar to Musslick et al - style architectures").

### 1.3 The "sluggish" task signal — exact update (pp. 10, 25, 28; code `utils/data.py`)
Paper's recursive definition (sub/superscripts lost; reconstructed — this is the only reading consistent with "Setting α = 0 is equivalent to the vanilla SGD network" p. 10 and "the weight on previous trials controlled by a single parameter, α"):

```
x̃_t = x_t                         for t = 1
x̃_t = (1 − α) x_t + α x̃_{t−1}      for t > 1
```
where x_t is the (centred, scaled) **two-dimensional context cue only**: "an Exponentially Moving Average (EMA), which was applied to the task units on each trial" (p. 25); "On each trial, The task signal received by the network was mixed with the signal carried over from previous trials" (p. 28). The 25 pixel inputs are **not** smoothed.

Facts that matter and that the paper does not spell out but the code does:
- The EMA is **pre-computed over the training sequence as data preprocessing** (`pandas .ewm(alpha=…, adjust=False)` on the two context columns of `x_train`). No gradient flows through it; the network just sees a blurred cue.
- It is applied **only to training inputs**; test inputs carry the clean, un-smoothed cue. So the interleaved deficit measured at test is a deficit in the learned weights, not test-time cue blur.
- Parameterisation: pandas' `alpha` is the weight on the *current* observation, so code `ctx_avg_alpha = 1 − α_paper`. The sweep `np.linspace(0.05, 1, 20)` in the code is the paper's "20 α values ranging from 0 to 0.95" (p. 25). The trees supplement's "sluggishness values ranging from α = 0.05 to α = 1.00 in 30 steps" (p. 40) is therefore in the **code's** convention (α_supp = 1 − α_main): a notation inconsistency between main text and supplement.
- Time scale: in the paper's convention the cue's influence decays as α^k after k trials; half-life ln2/(−ln α) ≈ 13.5 trials at α = 0.95, 1 trial at α = 0.5. In the human-fit experiment α and the test-time decision temperature T were chosen by **grid search** to match human choice patterns (p. 28: "we performed a grid search over a range of values for the α and T parameters … and chose those values that produced outputs which closely resembled the choices made by human participants"). **The fitted α is not reported anywhere in the text** (nor is T).
- Code also contains an unreported simple-moving-average option (`ctx_avg_type="sma"`, window 50).

What sluggishness does (pp. 10–11, Fig. 3): accuracy at test falls monotonically with α (Fig. 3B; no numbers in text); psychometric slope on the irrelevant dimension rises; "As α increases, the model moves from learning a factorised solution with one boundary per task to a linear solution with a single category boundary (Fig. 3e)"; a congruency effect appears (better on trials with the same response in both tasks); the proportion of task-selective hidden units falls (Fig. 3g).

### 1.4 The Hebbian context-gating step — exact rule (pp. 12–13, 26–28; code `trainer.py`)
Derivation given in the paper (pp. 26–27), reconstructed: linear unit y_j(x) = Σ_i w_ji x_i = w_j^T x; plain Hebb Δw_ji = η x_i y_j; Oja's rule with decay

```
Δw_j = η y_j (x − w_j y_j)                      (Oja; per unit j)
```
whose fixed point satisfies C w = ⟨y²⟩ w with C = ⟨x xᵀ⟩, "such that w will converge to the largest principal component of the input data" (p. 27). Implemented procedure, per trial t (p. 27):

```
1.  W ← W − ε ∇_W J(x_t, θ)                      (SGD on ALL parameters, loss J = −sigmoid(f(x,θ))·R)
2.  w_j ← w_j + η y_j (x_t − w_j y_j)   for every hidden unit j,
        y_j = w_jᵀ x_t = the j-th hidden unit's linear pre-activation (no bias, no ReLU)
```
Which weights step 2 touches — **the paper is internally inconsistent and the code settles it**:
- Methods p. 27: "a Hebbian update to the weights from the task units to the hidden layer, where y corresponds to the hidden layer activation of the j-th hidden unit prior to the non-linearity and each w corresponds to a vector of weights from all task-units to the j-th hidden unit".
- But Discussion p. 20 and Fig. S4 (p. 44) say the main version applied Oja to *all* inputs ("the mechanism still protects against catastrophic forgetting if the Hebbian updates are only applied to task units (instead of all inputs)") and that discovering the context among the inputs "requires that the context/task signal is the largest principal component in the dataset."
- Code (`runner.sh`, "revisions" block): the runs whose learning rates match the paper's reported ε = 0.0377, η = 0.00021 (Fig. 5) and ε = 0.0906/0.0926, η = 0.00258/0.000328 (human fit) use `--gating=oja`, i.e. `_oja_update`: Oja applied to the **entire 27×100 input→hidden matrix**, with y_j the full linear pre-activation from pixels + context. The context-only variant `oja_ctx` (y_j computed from the 2 context inputs alone, only the 2×100 context rows updated) is what the arXiv v1 preprint used, what Fig. S4 shows, and what the **trees** runs use ("To stabilise training of the Hebbian network, we had to restrict Hebbian weight updates to the connections from the two context units to the hidden layer", p. 40).
- So: **main blobs results = Oja on all input weights (context discovered as top PC); trees results and Fig. S4 = Oja on context weights only (context identity assumed known).**

How this produces gating (pp. 12–13, 27; inference marked):
- Because the cue is mean-centred and scaled, "the direction of largest variance in the mean-centred input space of our Gaussian blob dataset is spanned by the two task signals (Fig. 5a, b)" (p. 12). Oja drives every unit's weight vector toward ±that PC — the sign is set by the unit's random initial projection — so "weights from the task units to some of the hidden units are positive for one task and negative for the other, while the opposite is true for other units" (p. 27). "Thus, applying a ReLU nonlinearity partitions a portion of the hidden layer into task A and task B selective units." (p. 13)
- [Inference from the equations/code] Oja normalises each unit's weight vector to unit norm, so the context weights grow to O(1) while image weights stay O(0.01): the cue drive dominates the sign of the pre-activation, which is why an *additive* bias behaves like a hard gate.
- Continuous, not one-shot: "we alternated the supervised SGD update and the Hebbian update on each training step" (p. 13); confirmed by `Optimiser.step()`. No block boundary is signalled or used.
- Hand-crafted control (Fig. 4, p. 25): fixed context weights w_j = [1, −1] for odd j, [−1, 1] for even j, SGD on the rest (ε = 0.01) → no forgetting. Code: these are initial values and actually remain trainable (minor code/paper discrepancy).
- Unreported in the paper but present in the code: `_gha_update` (Sanger's generalised Hebbian algorithm, `ΔW = η (Y xᵀ − tril(Y Yᵀ) W)/normaliser`) and `_sla_update` (Oja's subspace rule) — multi-component variants. No results for them anywhere.

### 1.5 Training details that matter (pp. 24–28, 40; code)
- Loss: "J(θ) = −f(x, θ) R" (p. 25), i.e. minus (sigmoid output × reward); boundary stimuli (R = 0) give zero gradient. Code loss type `"reward"`: `-sigmoid(y_hat)ᵀ @ reward`.
- Learning rates (all per-trial, batch size 1): vanilla ε = 0.2 interleaved, 0.03 blocked (p. 25); manual gating ε = 0.01; Hebbian gating (5000 trials/task) ε = 0.0377, η = 0.00021 (η/ε ≈ 0.6%); human-fit sluggish Hebbian (200 trials/task) ε = 0.0905 / η = 0.0026 blocked (η/ε ≈ 2.9%), ε = 0.0926 / η = 0.000327 interleaved (≈ 0.35%) (p. 28); trees: ε = 0.001968, η = 0.000849, context offset c = 4 (p. 40). Hyperparameters found with RayTune/BOHB (code), chosen so networks "reliably reach ceiling performance" (p. 28).
- "We note that in practice, the solution is somewhat sensitive to the length of the training block and requires a carefully tuned balance between the learning rates for the supervised and Hebbian updates. When we repeated the simulations and systematically increased the length of the training blocks, whilst keeping all other parameters constant, the network forgot more about the previous task the longer the training blocks were (Fig. S1a). However, even when we doubled the block length, its performance was still superior to the baseline model trained without the Hebbian updates (Fig. S1b)." (p. 13). Code: block lengths swept 100–500 episodes (2,500–12,500 trials per block).
- Context scaling: code `ctx_scaling` ∈ {1,…,6} across runs; trees needed c = 4: "context, signalled by one-hot units, was no longer the largest direction of variance, unless we multiplied it with a very large scalar weight. Even then, the training process remained quite unstable." (p. 22)
- Decision noise at test for the human fit: sigmoid with temperature T (p. 28; extraction shows "1 − exp(−x/T)" — almost certainly 1 + exp), 10,000 sampled choices per input.

### 1.6 Headline results (numbers as given)
- Vanilla SGD: interleaved → "quickly reached 100% training accuracy on both tasks" (Fig. 2D caption, p. 8); blocked → first task overwritten, "the network applied the category boundary of the second task to the first task, ignoring the task signal" (p. 8). Interleaved: "20% of units in the hidden layer became task-selective" (p. 8), and context weights for the two tasks become anti-correlated (Fig. 2H); blocked: no task-selective units, no anti-correlation.
- Sluggish SGD (interleaved, α ∈ [0, 0.95]): monotonic accuracy decline with α; factorised → linear solution; congruency effect; fewer task-selective units (Fig. 3; no numeric values in text).
- Manual gating (blocked): "This network no longer forgot how to perform the first task" (p. 12).
- Hebbian gating (blocked): "The performance of the network on the first task remained at ceiling, even after training on the second task (Fig. 5d)"; anti-correlated task weights "even for blocked training (Fig. 5f)"; orthogonal, irrelevant-dimension-compressed hidden geometry (Fig. 5h) (p. 13).
- Human data vs models (pp. 15–16): humans blocked > interleaved T(93) = 2.32, p = 0.022; vanilla net the opposite T(98) = −95.94; sluggish Hebbian net blocked > interleaved T(98) = 5.71, p < 0.0001. Congruency × curriculum: humans T(93) = −2.74; model T(98) = −5.07. Irrelevant-dimension slope: humans T(93) = −2.77; model T(98) = −7.32. Factorised model fits better under blocked: humans T(93) = 3.07; model T(98) = 3.03. Psychophysical decomposition (pp. 17–18): humans — angular bias T(93) = −2.54, p = 0.0127; slope T(93) = 2.88; lapse and offset n.s.; model — bias T(98) = −3.91, lapse T(98) = −3.44 (significant in the model, not in humans), slope T(98) = 2.27, offset n.s.
- Very sluggish + interleaved geometry (p. 18–19): orthogonal RDM wins under blocked (grid vs orthogonal T(49) = −347.62; orthogonal vs diagonal T(49) = 178.67); **diagonal** (congruent-stimulus) RDM wins under interleaved (orthogonal vs diagonal T(49) = −73.89). Task-selective units: 41.3% blocked; task-agnostic units: 99.4% interleaved. Readout weights from task-agnostic units significantly larger under interleaving (T(49) = 5.52, 5.58).
- Trees replication (pp. 22–23, 45–47): same qualitative pattern with the deeper net and context-only Oja; e.g. EMA+Hebb blocked > interleaved T(98) = 3.81; baseline blocked < interleaved T(98) = 73.94 (p. 46). Geometry: "orthogonal representations in the first hidden layer … and parallel representations in its second layer … obtained by rotating one of the task manifolds from the previous layer by 90 degrees, to bring both into the frame of reference of the response" (p. 45).

### 1.7 "Rich vs lazy" and the initial weight scale
The paper contains exactly one sentence on this: "We initialized the network with small random weights (σ=0.001), placing the network in the 'rich' learning regime [15]." (p. 7). There is **no lazy-regime ablation** in this paper; the rich/lazy analysis of this task is in [15] (Flesch, Juechems, Dumbalska, Saxe & Summerfield, Neuron 2022). The small-init choice is what makes the vanilla interleaved network form low-dimensional, axis-aligned, context-gated manifolds in the first place (pp. 8–9, citing [15]); the Hebbian step then recreates those under blocking. [Inference] Small image weights are also what lets O(1) context weights act as a hard gate (1.4).

### 1.8 What is GIVEN vs what is INFERRED (the crux)
- **Given on every trial:** the context, as a one-hot (scaled, centred, possibly EMA-blurred) input vector. The cue is never absent and never has to be remembered across a gap; no block-boundary signal exists and none is needed.
- **Inferred, unsupervised:** (a) in the main blobs model, *which input dimensions are the context* — Oja/PCA finds the dominant variance direction, which is the context only because of the scaling/centring choices; (b) the *gating weights* from context units to hidden units (sign-split). The supervised loss plays no role in (a) or (b) beyond shaping which hidden units are useful.
- **Not inferred, and acknowledged:** "A possible limitation of our approach is that it requires that the largest principal component of the input space is the task/context signal." … "An alternative formulation of the problem would leave the context discovery to another mechanism." … "This begs the question of how the context could be identified if it was not the largest principle component. One possibility is that attentional mechanisms serve as gain modulation that scales up neural activity coding for parts of the visual input that represents the context." (pp. 20–21). When the context was not the top PC (trees), they had to tell the Hebbian step where the context units were.

## 3. Relevance to BDH-CQ reconstruction

Low. Nothing here describes a matrix memory, a latent-refinement loop, or anything Pathway-like. Two formal points only:
- The EMA `x̃_t = α x̃_{t−1} + (1−α) x_t` is a *linear* state update `S_t = U(S_{t−1}, D_t)` on a 2-vector, and is of the pure additive-with-decay type (`S_t = αS_{t−1} + (1−α)D_t`). It is the same form as BDH's decaying linear-attention state, but applied to an input cue, not to a key–value outer-product memory. It does not inform what U_θ is.
- Oja's rule `w ← w + η y (x − w y)`, y = wᵀx, is a Hebbian outer-product accumulation `η x xᵀ w` plus a state-dependent, norm-preserving decay `−η (wᵀ x xᵀ w) w`. The decay term depends on the state, so Oja is an example of `S_t = U(S_{t−1}, D_t)` that is **not** of the special additive form `S_t = S_{t−1} + U(D_t)`. If BDH-CQ's "linear correction rules on S" include self-normalising Hebbian updates, Oja/Sanger are the canonical textbook instances (and the code shows the authors implemented GHA/Sanger and the Oja subspace rule as well). No latent reasoning loop `H_{r+1} = F(H_r, S_K)` of any kind.

## 4. Relevance to distant context cues

**Which component carries context across distance, and how far.** The EMA on the task units is the only thing that carries anything across trials; the network itself is feedforward and memoryless. The cue's contribution decays geometrically, α per trial: half-life ≈ 13.5 trials at α = 0.95 (the largest value swept), ≈ 6.6 at α = 0.9, 1 at α = 0.5. The swept range was α ∈ [0, 0.95] in 20 steps (p. 25) and, for the human fit, [0, 0.95] in 30 steps (code; the supplement states this range in the complementary convention). The fitted human α is not reported.

**Given or inferred?** Given, every trial. The paper never tests a cue that is absent on some trials. The EMA therefore never has to *bridge* a gap in the paper's experiments; it only *mixes* consecutive cues.

**How that component is trained.** It isn't. α is a fixed hyperparameter (swept or grid-searched against human data); the EMA is applied to the data stream before training, no gradient passes through it, and at test it is switched off (code). The authors' own future-work item is to make it adaptive to environmental volatility (quote 13).

**What the model implies about a cue presented ONCE at the start of a block (our header layout) — our extrapolation, not tested in the paper.** With x_t = cue at t = 1 and x_t = 0 afterwards, the paper's EMA gives x̃_t = α^{t−1}·cue: the signal survives but shrinks geometrically. To keep ≥ 50% amplitude over the 2P = 8 tokens of a P = 4 block needs α ≥ 0.917; over 16 tokens (P = 8), α ≥ 0.958. The paper's closest statement is quote 13: active maintenance "would ensure ongoing task performance under blocked curricula, even if the task signal could not be read out or was mislabelled on a subset of trials." This is the only textual support for "a decaying trace stands in for a missing cue", and it is a conjecture in the Discussion, not a result. Note also that in the paper the EMA's input is *zero* on non-cue dimensions by construction (only the two task units are smoothed); if the integrator instead received every token (keys, values), those would accumulate into the state and the decaying cue would have to be decoded against that accumulated content. That is exactly the problem our fading-memory EMA gates (0/10 on header) hit, and the paper avoids it by construction rather than solving it.

**What the model says about two contexts interleaved (our grouped layout and interleaved streams) — paper-supported.** This is the paper's central negative result: with a slow integrator, consecutive conflicting cues blur into a mixture; the network then "ignores the contextual cue" and learns one shared/diagonal rule optimised for congruent trials; the hidden layer becomes 99.4% task-agnostic (p. 18) and the readout leans on those shared units. For us: a slow integrator read by the gate will, on interleaved streams, produce a *mixed* g_t for every token and the channels will merge — the paper's "linear solution" is the exact analogue of our router-collapse/merge pathology. The paper also says the time scale should match the environment's switch rate (quote 13): our grouped layout switches context every 3 tokens, so it needs α near 0 (the window gate is the α → 0 limit and is the one that works there), while the header layout needs α near 0.92–0.96. **No single fixed α serves both layouts**; the paper's own suggestion is a volatility-adaptive window, i.e. a forget gate.

**One more relevant finding (quote 4).** Under blocked training, the supervised loss provides no pressure to use the cue, because within a block the cue is constant and uninformative; vanilla SGD simply ignores the task units. This is a clean statement of why, in our header layout, nothing in the loss rewards *routing by stream* during a block, why a single channel suffices at P = 4, and why the gate settles for key splits. The paper's remedy is an unsupervised side-objective (Hebbian/PCA) that does not depend on the loss.

## 5. Relevance to our gate — translation and concrete proposals

Notation: our gate g_t = softmax(W_g h_t) ∈ Δ^k; token embedding v_t; stream count S; channels k.

### 5.1 The slow integrator (directly supported, with one critical caveat)
Paper's EMA ⇒ our `c_t = α c_{t−1} + (1−α) u(x_t)` is exactly the paper's equation with u(x_t) = the explicit cue. The caveat is **what u is**: in the paper u(x) = 0 on everything except the context channel. For us u must be learned to (i) respond to CTX tokens and (ii) be ≈ 0 (or orthogonal to the gate's readout) on KEY/VAL tokens, otherwise content accumulates and swamps the decaying cue. Concretely:
- `c_t = α ⊙ c_{t−1} + (1 − α) ⊙ u(v_t)`, u(v) = P v with P ∈ R^{d_c×D} (small d_c, e.g. 4–8), per-dimension α, initialised at α ≈ 0.93 (half-life ≈ 10 tokens) for header-style data; **make α learnable or token-conditioned** (`α_t = σ(a·v_t + b)`, so a CTX token can reset the integrator: α_t → 0 on CTX, → 1 otherwise). The paper does not do this, but its Discussion names exactly this adaptivity as the missing piece (quote 13). A resettable integrator also reconciles grouped (switch every 3 tokens) and header (switch every 2P+1 tokens) layouts, which a fixed α cannot (section 4).
- Gate: `g_t = softmax(W_g [c_t ; h_t])` or simply `softmax(W_g c_t)` for the write at VAL positions. Keep the window gate's local term for the grouped layout if desired; the paper has no opinion on combining them.
- Mean-centre c_t before anything Hebbian reads it (running mean subtraction): the paper's whole sign-split mechanism relies on a zero-mean context code ([0.5, −0.5]), quote 22.

### 5.2 Learning u without labels: Oja/PCA on the integrated state (paper-supported in spirit; the slow-feature step is our extrapolation)
The paper's answer to "which inputs are the context" is: run Oja and take the top PC, which works iff the context dominates the variance. In token streams the context token does not dominate raw embedding variance. But **after temporal averaging it does**: an EMA with carry-over α shrinks zero-mean fast-varying components by a factor ≈ sqrt((1−α)/(1+α)) (≈ 0.16 at α = 0.95) while leaving a slowly varying (block-constant) component intact. So Oja/Sanger on `c̄_t` (centred EMA of embeddings) recovers the *slow* directions — in a blocked layout, the stream identity. Proposal: `P ← P + η (c̄_t c̄_tᵀ P − P tril(Pᵀ c̄_t c̄_tᵀ P))`-style Sanger update (the code's `_gha_update`) for d_c components, run after each SGD step, with SGD also allowed to shape P (the paper alternates SGD and Hebb on the same weights). This is the paper's "temporal clustering of contextual information" (quote 14) made literal. **Caveat:** in the grouped layout there is no slow feature — context, key and value all change every token or every three tokens — so an EMA-then-PCA detector has nothing to lock onto. This only helps header-style data; the paper's result that sluggishness on interleaved data yields a *shared* representation predicts it would actively hurt on grouped data.

### 5.3 Hebbian orthogonalisation of channel use by context (supported for k = 2; our extrapolation for k > 2)
Paper mechanism: Oja on each hidden unit's context weights → all units at ±(first PC) → ReLU partitions units into two context pools. Translation to the gate rows: after each SGD step,
```
z_k = w_kᵀ c̄_t                          (channel k's pre-softmax logit from the context state)
w_k ← w_k + η z_k (c̄_t − w_k z_k)        for each channel k           (Oja per row)
```
drives each row of W_g to ±PC1 of c̄_t. For k = 2 that is exactly a sign-split: one channel's logit is +PC1·c̄, the other's −PC1·c̄, and softmax gives a hard 2-way partition by context — the paper's gating in our notation, with random initial signs deciding which channel gets which stream (the paper's "some of the hidden units are positive for one task and negative for the other"). For k = S > 2 a single component cannot separate S streams; use Sanger/GHA so rows converge to the first k orthogonal PCs of c̄_t (then softmax over k orthogonal projections ≈ assignment by nearest principal axis), or a competitive variant. The paper only has two tasks and only says the scheme "in principle might work in richer settings" (quote 14); the authors wrote GHA/SLA code but reported nothing. Treat k > 2 as untested.

### 5.4 Training recipe and balance (supported)
- Alternate: SGD step on everything, then the Hebbian step on the gate's context weights, every token/sample. Hebbian rate ≈ 0.4–3% of the SGD rate in the paper (η/ε = 0.0057 at 5,000 trials/block; 0.029 blocked / 0.0035 interleaved at 200 trials/block). Our "slow memory lr / fast gate lr" recipe is a different lever but the same spirit: the paper's explicit warning is that the Hebbian gating "requires a carefully tuned balance between the learning rates" and degrades with longer blocks (Fig. S1).
- Scale of the cue matters: the paper needed `ctx_scaling` 2–6 (code) and c = 4 for trees for the context to be discoverable; for us this says the CTX embedding (or P·CTX) must have norm comparable to or larger than content tokens' projection, else the Hebbian detector locks onto content. An alternative to scaling is the EMA-as-slow-feature argument in 5.2.
- Initialise W_g rows small and zero-mean (paper: σ = 0.01 inputs, rich regime); Oja then grows the context rows to unit norm — the growth itself is the gate "turning on". Our channel-split heuristic (copy busiest row to emptiest + noise) is a crude version of the sign-split; the paper's version is label-free and continuous.

### 5.5 Per-layer residual gate (our leading idea)
The paper offers one relevant data point: in the two-hidden-layer trees network the task-orthogonal geometry forms in layer 1 and layer 2 *rotates* the two manifolds into a shared response frame (p. 45). The context signal is only injected at layer 1 in the reported runs; the code has an unreported option to inject it at every layer (`ctx_twice`, "Musslick et al - style"). Nothing here tests whether a later layer can recover a header cue from earlier positions — that is an attention capability the MLP does not have. Neutral.

### 5.6 Forget gate / memory horizon
Direct support for making the integration window adaptive (quote 13) and for the diagnosis that too-long integration collapses interleaved contexts (section 4). The paper's α is per-trial on a single 2-D signal; a per-channel learned α_k on the memory itself is our extrapolation. Note the numerical coincidence: our memory decay 0.95 (half-life ≈ 14 tokens) equals the paper's largest swept α (half-life ≈ 13.5 trials) — the paper's data say that at this sluggishness an interleaved curriculum is already badly degraded (Fig. 3B), so a memory decay of 0.95 inside a gate integrator would be wrong for grouped data.

### 5.7 Beliefs supported, contradicted, pitfalls
- Supported: context must be carried by a slow state the gate can read (recurrent/integrator), not by a width-3 window; slow integration + interleaving ⇒ merged channels; label-free partition is possible via Hebbian statistics *if the context is a dominant/slow input direction*; loss alone gives no routing pressure inside a block (quote 4).
- Contradicted / qualified: our premise that the gate can discover the partition "from the loss alone" — the paper's position is that the supervised loss does not do this under blocking; discovery was done by an unsupervised rule, and even that required the context to dominate the variance. Our recurrent gate's "position counting" is consistent with this: with no signal in the loss to favour stream identity, any correlated feature (position, key) is picked.
- Pitfalls the paper flags: Hebbian step destabilises training when applied to content weights with a non-dominant context (quote 16) — restrict it to the context pathway; sensitivity to block length and lr ratio (quote 11); gating alone is insufficient as the number of tasks grows — Masse et al. needed synaptic stabilisation on top (quote 15); additive-bias gating may be inferior to multiplicative output gating (quote 18); the ±PC1 trick is intrinsically binary. No straight-through estimators or pooled summaries appear in the paper.

## 7. Verdict

This paper is the cleanest existing statement of the two ingredients our header-layout gate is missing, but it supplies them only under conditions we do not have. It confirms (with human fits) that a leaky integrator of the context cue, `c_t = α c_{t−1} + (1−α) u(x_t)`, is the right object for carrying context across trials, and it is explicit that the integrator must receive *only the cue*: its "sluggish" EMA is applied to the two task units and nothing else, and it is a fixed preprocessing step, never learned and never tested with a missing cue. It also shows that a label-free hard partition of hidden units by context can be learned with Oja's rule, but only because the context was made the dominant variance direction (scaled, mean-centred one-hot) and only for two contexts (±PC1). The strongest transferable lessons are negative and diagnostic: under blocking the supervised loss gives no pressure to use the cue (so our loss-only gate finding key splits is expected, not a bug), and a slow integrator read by a gate *will* merge interleaved streams (the paper's "linear solution" is our router collapse), so the integration constant must be reset/adaptive, not fixed — the authors say so themselves as future work. What to do next: build the integrator gate with a token-conditioned (resettable) α and a low-dimensional learned u, centre its state, and add a Sanger/GHA Hebbian side-step on the gate rows as the label-free partitioner; evaluate on header and grouped layouts separately, expecting the fixed-α version to fail on grouped data. Confidence: high on what the paper does and does not show (text plus code checked); medium on the translation, because the paper is a two-task, feedforward, always-cued MLP and every claim about one-shot cues, k > 2 channels and token streams is extrapolation.
