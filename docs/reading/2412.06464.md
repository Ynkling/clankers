## 1. What the paper actually does

### 1.1 The three update rules, in the paper's notation (p.2–4)

Linear attention (p.2): "S_t = S_{t−1} + v_t k_tᵀ ∈ R^{d_v×d_k}, o_t = S_t q_t ∈ R^{d_v}", with the parallel form "O = (QKᵀ ⊙ M)V ∈ R^{L×d_v}", M the causal mask ("M_ij = 0 when i < j, and 1 otherwise").

Mamba2 (p.2): "S_t = α_t S_{t−1} + v_t k_tᵀ, o_t = S_t q_t where α_t ∈ (0, 1) is a data-dependent scalar-valued decay term". With γ_j = ∏_{i=1}^{j} α_i: "o_t = Σ_{i=1}^{t} (γ_t/γ_i) v_i k_iᵀ q_t, O = ((QKᵀ) ⊙ Γ)V", "Γ_ij = γ_i/γ_j if i ≥ j and Γ_ij = 0 otherwise" (p.3).

Delta rule / DeltaNet (p.3), copied:

    S_t = S_{t−1} − (S_{t−1} k_t) k_tᵀ + (β_t v_t + (1 − β_t) S_{t−1} k_t) k_tᵀ = S_{t−1}(I − β_t k_t k_tᵀ) + β_t v_t k_tᵀ
              └── v_t^old ──┘   └──────── v_t^new ────────┘

"The delta update rule (Widrow et al., 1960; Schlag et al., 2021b) dynamically erases the value (v_t^old) associated with the current input key (k_t) and writes a new value (v_t^new), which is a linear combination of the current input value and the old value based on the 'writing strength' β_t ∈ (0, 1)." Footnote 2: "It is possible to set β_t ∈ (0, 2) to allow negative eigenvalue to unlock the state tracking abilities of DeltaNet (Grazzi et al., 2024; Siems et al., 2025)." "DeltaNet implements a first-order linear recurrence with generalized Householder transition matrices (I − β_t k_t k_tᵀ)" (p.4).

**Gated delta rule, Eq. (10), p.4 — verified exact form:**

    S_t = S_{t−1} (α_t (I − β_t k_t k_tᵀ)) + β_t v_t k_tᵀ                              (10)

"where the data-dependent gating term α_t ∈ (0, 1) controls state decay." α_t sits *inside the transition*, multiplying the Householder factor; the new write β_t v_t k_tᵀ is **not** decayed. Since α_t is a scalar this equals α_t S_{t−1} − α_t β_t (S_{t−1} k_t) k_tᵀ + β_t v_t k_tᵀ, i.e. the old value is read from the *decayed* state before being erased (Table 1's objective makes this explicit: the correction target is v_t − α_t S_{t−1} k_t).

Output (same as the other rules; p.2 and Eqs. 8–9): o_t = S_t q_t. S ∈ R^{d_v×d_k}, right-multiplied by the transition (the transition acts on the key index).

**Table 1 (p.5), online-learning view (Liu et al. 2024 framework), rows copied** (the extraction displaced the ᵀ superscripts; the forms below are the obvious intended ones):

| Method | Online objective | Update |
|---|---|---|
| LA | ‖S_t − S_{t−1}‖²_F − 2⟨S_t k_t, v_t⟩ | S_t = S_{t−1} + v_t k_tᵀ |
| Mamba2 | ‖S_t − α_t S_{t−1}‖²_F − 2⟨S_t k_t, v_t⟩ | S_t = α_t S_{t−1} + v_t k_tᵀ |
| Longhorn | ‖S_t − S_{t−1}‖²_F − β_t ‖S_t k_t − v_t‖² | S_t = S_{t−1}(I − ε_t k_t k_tᵀ) + ε_t v_t k_tᵀ, ε_t = β_t/(1 + β_t k_tᵀ k_t) |
| DeltaNet | ‖S_t − S_{t−1}‖²_F − 2⟨S_t k_t, β_t(v_t − S_{t−1} k_t)⟩ | S_t = S_{t−1}(I − β_t k_t k_tᵀ) + β_t v_t k_tᵀ |
| Gated DeltaNet | ‖S_t − α_t S_{t−1}‖²_F − 2⟨S_t k_t, β_t(v_t − α_t S_{t−1} k_t)⟩ | S_t = S_{t−1}(α_t(I − β_t k_t k_tᵀ)) + β_t v_t k_tᵀ |

(Caption: "For convenience, we simplify Longhorn's vector-valued β to scalar β.") I checked the GDN row: setting the gradient of the objective to zero gives S = α S_{t−1} + β(v − α S_{t−1}k)kᵀ, which is Eq. 10.

Test-time-SGD view (p.5), copied: "the hidden state S can be interpreted as a (fast) weight matrix, with the delta rule optimizing the online regression objective L(S_t) = ½‖S_t k_t − v_t‖² via test-time stochastic gradient descent (SGD): S_{t+1} = S_t − β_t ∇L(S_t) = S_t − β_t(S_t k_t − v_t)k_tᵀ = S_t(I − β_t k_t k_tᵀ) + β_t v_t k_tᵀ where β_t represents the (adaptive) learning rate. From this perspective, the gated delta rule can be viewed as incorporating an adaptive weight decay term α_t into the SGD update". (Note the index slip S_{t+1} vs Eq. 10's S_t; harmless.)

### 1.2 Parameterization of α_t, β_t and the block (p.6 [paper] + official code [code])

[paper] §3.4: "queries, keys and values {q, k, v} are generated through linear projection, short convolution and SiLU, with L2 normalization applied to q, k for training stability. α, β use linear projection only.⁴ Following Sun et al. (2023a), the output is processed through normalization and gating before applying output projection." Fig. 1 caption: "query/key paths consist of linear proj., shortconv., SiLU and L2 norm; value path includes linear proj., shortconv. and SiLU; alpha/beta use linear proj.; and output gate applies linear proj. with SiLU." Macro architecture: "follows Llama's macro architecture, stacking token mixer layers with SwiGLU MLP layers". Head dim 128 chosen (Table S.1: 64 → 28.31 ppl, 128 → 27.35, 256 → 27.13).

[code] `lit_gpt/gated_delta_net.py` (NVlabs), per head (both projections output `num_heads` scalars):

    self.gk_proj = nn.Linear(hidden_size, self.num_heads, bias= not use_mamba_gate)
    self.b_proj  = nn.Linear(hidden_size, self.num_heads, bias=True)
    A = torch.empty(self.num_heads).uniform_(0, 16);  A_log = torch.log(A)      # learnable, no weight decay
    dt_min=0.001, dt_max=0.1, dt_init_floor=1e-4
    dt = exp(rand*(log dt_max − log dt_min) + log dt_min), clamped ≥ 1e-4       # log-uniform in [0.001, 0.1]
    inv_dt = dt + torch.log(-torch.expm1(-dt));  self.dt_bias = nn.Parameter(inv_dt)   # softplus⁻¹(dt), no weight decay
    # forward
    beta = self.b_proj(hidden_states).float().sigmoid()                           # β_t = σ(W_b x_t + b_b) ∈ (0,1)
    gk   = -self.A_log.float().exp() * F.softplus(gk + self.dt_bias)              # log α_t = −A · softplus(W_a x_t + b_Δ)

So **α_t = exp(−A_h · Δ_{h,t}), Δ_{h,t} = softplus(w_{a,h}·x_t + b_{Δ,h})**, A_h = exp(A_log_h) > 0 learnable, one scalar per head per token. (Alternative in code when `use_mamba_gate=False`: GLA-style `gk = F.logsigmoid(gk)/gate_logit_normalizer`.) Inputs to both projections are the layer's residual-stream input (`hidden_states`), *not* the conv output and *not* the previous state. `A_log`, `dt_bias` (and a `D` parameter not described in the paper) carry `_no_weight_decay = True`. Short conv: `conv_size = 4`, applied separately to q, k, v, followed by SiLU; q, k then L2-normalized (`l2_norm_fn`). Output: RMSNorm on o then swish gate `o * swish(g_proj(x))` (fused). Defaults in that file: expand_k 0.75, expand_v 1.5, 9 heads at hidden 1024.

Half-life arithmetic (mine, from the above): α = exp(−AΔ) ⇒ half-life t_½ = ln2/(AΔ) tokens. At init Δ ≈ dt ∈ [0.001, 0.1] (W_a small), A ∈ (0,16) ⇒ AΔ ∈ (0, 1.6) ⇒ α ∈ (0.20, 1), t_½ from ≈0.4 tokens to effectively unbounded; the log-uniform dt init spreads heads across time scales. Our fixed decay 0.95 corresponds to AΔ = −ln 0.95 ≈ 0.0513, t_½ ≈ 13.5 tokens (e.g. A = 1, Δ ≈ 0.051).

### 1.3 Chunkwise parallel algorithm (WY representation / UT transform), equations copied

Notation (p.3): chunk size C; Q_[t] := q_{tC+1:(t+1)C+1}; q^r_[t] := q_{tC+r}; S_[t] := S^0_[t] = S^C_[t−1]. Footnote 1: γ within a chunk is the cumulative product "starting with the first position of each chunk separately". Arrow notation, Eq. (2), p.3:

    ←q^r_[t] = γ^r_[t] q^r_[t]              decaying each vector to the first position of chunk t
    →k^r_[t] = (γ^C_[t]/γ^r_[t]) k^r_[t]    decaying each vector to the last position of chunk t
    →S_[t]   = γ^C_[t] S_[t]                decaying the state matrix over the entire chunk t     (2)

Mamba2 chunkwise, Eq. (1), p.3: S_[t+1] = →S_[t] + V_[t]ᵀ →K_[t] ∈ R^{d_v×d_k}, O_[t] = ←Q_[t] S_[t]ᵀ + (Q_[t]K_[t]ᵀ ⊙ Γ_[t]) V_[t] ∈ R^{C×d_v}, (Γ_[t])_ij = γ^i_[t]/γ^j_[t].

DeltaNet chunk expansion, Eq. (3), p.4 (reconstructed from the garbled two-line layout; structure is unambiguous):

    S^r_[t] = S_[t] ∏_{i=1}^{r}(I − β^i_[t] k^i_[t] k^{iᵀ}_[t])  +  Σ_{i=1}^{r} β^i_[t] v^i_[t] k^{iᵀ}_[t] ∏_{j=i+1}^{r}(I − β^j_[t] k^j_[t] k^{jᵀ}_[t])     (3)
              └──────────── := P^r_[t] ────────────┘   └──────────────────────── := H^r_[t] ────────────────────────┘

WY representation (Bischof & Van Loan 1985), Eqs. (4)–(5):

    P^r_[t] = I − Σ_{i=1}^{r} w^i_[t] k^{iᵀ}_[t] ∈ R^{d_k×d_k},   w^r_[t] = β^r_[t]( k^r_[t] − Σ_{i=1}^{r−1} w^i_[t] (k^{iᵀ}_[t] k^r_[t]) ) ∈ R^{d_k}     (4)
    H^r_[t] = Σ_{i=1}^{r} u^i_[t] k^{iᵀ}_[t] ∈ R^{d_v×d_k},       u^r_[t] = β^r_[t]( v^r_[t] − Σ_{i=1}^{r−1} u^i_[t] (k^{iᵀ}_[t] k^r_[t]) ) ∈ R^{d_v}     (5)

Matrix form: P_[t] = I − W_[t]ᵀ K_[t], H_[t] = U_[t]ᵀ K_[t]. UT transform (Joffrain et al. 2006), Eqs. (6)–(7):

    T_[t] = [ I + strictLower( diag(β_[t]) K_[t] K_[t]ᵀ ) ]^{−1} diag(β_[t]) ∈ R^{C×C}                 (6)
    W_[t] = T_[t] K_[t] ∈ R^{C×d_k},   U_[t] = T_[t] V_[t] ∈ R^{C×d_v}                                   (7)

DeltaNet chunk recurrence, Eqs. (8)–(9):

    S_[t+1] = S_[t] P_[t] + H_[t] = S_[t] + (U_[t] − W_[t] S_[t]ᵀ)ᵀ K_[t] ∈ R^{d_v×d_k}                   (8)
    O_[t]   = Q_[t] S_[t]ᵀ + (Q_[t] K_[t]ᵀ ⊙ M)(U_[t] − W_[t] S_[t]ᵀ) ∈ R^{C×d_v}                        (9)

**Gated DeltaNet chunkwise (§3.3, p.6, unnumbered)**, expanding Eq. 10:

    S^r_[t] = S_[t] ∏_{i=1}^{r} α^i_[t](I − β^i_[t] k^i_[t] k^{iᵀ}_[t])  +  Σ_{i=1}^{r} β^i_[t] v^i_[t] k^{iᵀ}_[t] ∏_{j=i+1}^{r} α^j_[t](I − β^j_[t] k^j_[t] k^{jᵀ}_[t])
              └──────────────── := F^r_[t] ────────────────┘   └──────────────────────────── := G^r_[t] ────────────────────────────┘

"It is easy to see that F^r_[t] = γ^r_[t] P^r_[t] = ←P^r_[t]." For G, Eq. 5 is adapted:

    G^r_[t] = Σ_{i=1}^{r} (γ^r_[t]/γ^i_[t]) ũ^i_[t] k^{iᵀ}_[t] ∈ R^{d_v×d_k},
    ũ^r_[t] = β^r_[t]( v^r_[t] − Σ_{i=1}^{r−1} ũ^i_[t] ( (γ^r_[t]/γ^i_[t]) k^{iᵀ}_[t] k^r_[t] ) ) ∈ R^{d_v}      (proof: §A)

UT-transform matrix form: Ũ_[t] = [ I + strictLower( diag(β_[t]) (Γ_[t] ⊙ K_[t] K_[t]ᵀ) ) ]^{−1} diag(β_[t]) V_[t] ∈ R^{C×d_v}.

Final algorithm as extracted (arrows reconstructed from their positions in the layout):

    S_[t+1] = →S_[t] + ( Ũ_[t] − ←W_[t] S_[t]ᵀ )ᵀ →K_[t]      ∈ R^{d_v×d_k}
    O_[t]   = ←Q_[t] S_[t]ᵀ + ( Q_[t] K_[t]ᵀ ⊙ M )( Ũ_[t] − ←W_[t] S_[t]ᵀ )     ∈ R^{C×d_v}

"where ←q^r_[t] = γ^r_[t] q^r_[t], ←w^r_[t] = γ^r_[t] w^r_[t], →k^r_[t] = (γ^C_[t]/γ^r_[t]) k^r_[t], and →S_[t] = γ^C_[t] S_[t] like we defined in Eq. 2."

Flag: I re-derived the output equation. From S^r = γ^r S P^r + G^r one gets o^r = S ←q^r + Σ_{i≤r} (γ^r/γ^i)(k^{iᵀ}q^r)(ũ^i − S ←w^i), i.e. the intra-chunk mask must be the decay-aware Γ_[t], not the plain M. The state update line checks out exactly as written. Either the paper has a typo there or the extraction lost a decoration on M; the FLA kernel is the ground truth. The appendix-A identity (first chunk) is: S_t = Σ_{i=1}^{t} (γ_t/γ_i) u_i k_iᵀ, u_t = β_t( v_t − Σ_{i=1}^{t−1} (γ_t/γ_i) u_i k_iᵀ k_t ), proved by induction (p.21).

Cost: "the proposed gated delta rule introduces only marginal overhead compared to the original delta rule, with Gated DeltaNet achieving essentially the same throughput as DeltaNet. Both are slightly slower than Mamba2 (2-3K tokens/sec) due to their more expressive transition matrices." (p.8; Fig. 3 is 1.3B models on one H100; axis 25–60 Kt/s.)

### 1.4 Hybrids (p.6, Fig. 1)

"Linear transformers have limitations in modeling local shifts and comparisons, and their fixed state size makes it hard for retrieval tasks (Arora et al., 2024a). Following recent hybrid architectures like Griffin (De et al., 2024) and Samba (Ren et al., 2024), we combine linear recurrent layers with sliding window attention (SWA), resulting in GatedDeltaNet-H1. We also stack Mamba2, GatedDeltaNet and SWA, resulting in GatedDeltaNet-H2." Each unit is [token mixer + MLP]; H1 repeats (GDN, SWA), H2 repeats (Mamba2, GDN, SWA). SWA window 2K with 4K training length. Table S.2 (500M/15B): ordering matters — Mamba2+GDN+SWA avg acc 48.73 / Wiki 23.54 / LMB 24.11, vs GDN+SWA+Mamba2 47.88, GDN+Mamba2+SWA 47.54, Mamba2+SWA+GDN 47.92. "the combination of Mamba2, Gated DeltaNet, and SWA in this specific order produces superior results."

### 1.5 Training details (p.6–7)

"all models are trained under identical conditions with 1.3B parameters on 100B tokens sampled from the FineWeb-Edu dataset (Penedo et al., 2024). We use the AdamW optimizer with a peak learning rate of 4e-4, weight decay of 0.1, and gradient clipping of 1.0. The learning rate follows a cosine annealing schedule with a 1B token warm-up period and batch size of 0.5M tokens. All models employ the Llama2 tokenizer with a vocabulary size of 32,000. For sequence modeling, we set the training length to 4K tokens, with Samba and our hybrid models using a sliding window size of 2K." Ablations: 400M / 15B tokens (Table S.1), 500M / 15B (Table S.2), lm-evaluation-harness. No separate learning rate for gate parameters is reported; [code] only excludes A_log/dt_bias/D from weight decay. Hardware: only "a single H100 GPU" for the throughput figure; the README says the 0.4B H1 / 15B-token run "requires 4 nodes and can be finished in approximately 4 hours" (GPU type not stated).

**What fails / where GDN loses:**
- S-NIAH-1 at 2K: GDN 88.4 < DeltaNet 96.8 and Mamba2 98.8; at 4K/8K GDN (91.4/91.8) is well below ungated DeltaNet (99.0/98.8) — the forget gate costs retention of a lone needle.
- S-NIAH-2 at 8K and S-NIAH-3 at 4K: everything collapses (GDN 29.6 and 27.6 are the best of a bad set). Note training length is 4K, so 8K is 2× extrapolation.
- Real-world recall: pure recurrent models are far below attention (Avg 30.6 vs 37.0; FDA 23.7 vs 52.2); Mamba2 beats GDN on FDA (25.3 vs 23.7) and TQA (61.0 vs 60.0). Authors blame "instruction-unaligned small language models being prone to repetition errors" for the compressed margins.
- Table 3: Mamba2 > GDN on ARC-e (72.47 vs 71.21); H2 is worse than H1 on LMB ppl (12.55 vs 12.12) and Avg (56.18 vs 56.40).
- LongBench: GDN < Mamba2 on Musique (5.8 vs 6.7) and 2WikiMQA (14.4 vs 15.1; RetNet 18.0).
- Fig. 2: explicitly "mixed results in length extrapolation".
- Throughput: GDN/DeltaNet slower than Mamba2; hybrids beat the pure mixer because 2K-window FlashAttention-2 is fast.

## 2. Verbatim quotes that matter

Capacity / collisions (p.1): "linear Transformers can be interpreted as implementing an outer-product-based key-value association memory, reminiscent of tensor product representation (Smolensky, 1990). However, the number of orthogonal key-value pairs they can store is bounded by the model's dimensionality. When the sequence length exceeds this dimension, 'memory collisions' become inevitable, hindering exact retrieval (Schlag et al., 2021a)."

Why uniform decay is the wrong tool (p.1–2): "Mamba2 addresses this limitation by introducing a simple gated update rule, S_t = α_t S_{t−1} + v_t k_tᵀ, which uniformly decays all key-value associations at each time step by a dynamic ratio, α_t ∈ (0, 1). However, this approach does not account for the varying importance of different key-value associations, potentially leading to inefficient memory utilization. If the model needs to forget a specific key-value association, all key-value associations are equally forgotten, making the process less targeted and efficient."

Why the delta rule alone fails — context switches (p.2): "the linear Transformer with the delta rule (Widrow et al., 1960), known as DeltaNet (Schlag et al., 2021a; Yang et al., 2024b), selectively updates memory by (softly) replacing an old key-value pair with the incoming one in a sequential manner. This method has demonstrated impressive performance in synthetic benchmarks for in-context retrieval. However, since this process only modifies a single key-value pair at a time, the model lacks the ability to rapidly clear outdated or irrelevant information, especially during context switches where previous data needs to be erased. Consequently, DeltaNet has been found to perform moderately on real-world tasks (Yang et al., 2024b), likely due to the absence of a robust memory-clearing mechanism."

The two knobs (p.2): "This unified rule enables flexible memory control: it can promptly clear memory by setting α_t → 0, while selectively updating specific content without affecting other information by setting α_t → 1 (effectively switching to the pure delta rule)."

Overwrite semantics — the sentence that settles the "same key, second binding" question (p.3): "The delta update rule ... dynamically erases the value (v_t^old) associated with the current input key (k_t) and writes a new value (v_t^new), which is a linear combination of the current input value and the old value based on the 'writing strength' β_t ∈ (0, 1)."

Superposition / saturation (p.4): "Recent linear RNN architectures typically incorporate a regularization term in their online learning objective to prevent state divergence from previous values, thereby enabling memory retention. However, this retention mechanism becomes problematic when the state becomes saturated with information. In such cases, each state would encode a superposition of multiple information pieces, making precise retrieval challenging. To address this limitation, Mamba2 and Gated DeltaNet introduce an adaptive scaling factor α_t that relaxes the regularization term, allowing controlled deviations between S_t and S_{t−1}. This modification enables dynamic memory management through selective forgetting, which could be useful in filtering out irrelevant information".

Objective view (p.5): "Linear Attention (LA) and Mamba2 use a simple negative inner-product loss −⟨S_t k_t, v_t⟩, while Longhorn (Liu et al., 2024) uses a more expressive online regression objective ‖S_t k_t − v_t‖² for better modeling of key-value associations. The resulting Longhorn's update rule closely resembles the delta update rule, suggesting the superiority of the (gated) delta rule over Mamba2 in in-context associative recall." Footnote 3: "Longhorn uses implicit online learning (Kulis & Bartlett, 2010) to derive closed-form globally optimal updates, while DeltaNet optimizes the same objective through one-step explicit gradient descent".

S-NIAH lessons (p.5–6): "Decay hurts memory retention." / "Gating facilitates filtering. ... With fixed state size, lack of clearance causes memory collision—information becomes superimposed and indistinguishable." / "Delta rule helps memorization."

Stability (p.6): "with L2 normalization applied to q, k for training stability." (p.22): "we found L2 normalization to be essential for optimal performance".

Gate design (p.9): "Modern forget gates differ from traditional designs like those in LSTM by removing the dependency on the previous hidden state, relying solely on input data. This modification enables efficient parallelism across sequence lengths (Martin & Cundy, 2018; Qin et al., 2023b). The absence of a forget gate has been a notable limitation in DeltaNet, and our gated extension addresses this gap in a natural, effective, and hardware-efficient way."

RWKV-7 (p.10): "a recent concurrent work RWKV-7 using a similar idea, but with a more relaxable formalism using diagonal-plus-low-rank transitions: S_t = S_{t−1}(diag(d_t) − a_t b_tᵀ) + v_t k_tᵀ where d_t, a_t, b_t ∈ R^{d_k}."

Delta vs Hebbian capacity (p.10): "The delta learning rule demonstrates superior memory capacity compared to Hebbian learning (Gardner, 1988; Prados & Kak, 1989), an advantage DeltaNet leverages while linear transformers rely on Hebbian-like rules." "DeltaNet's data-dependent identity-plus-low-rank structure (I − β_t k_t k_tᵀ) offers greater flexibility than Mamba2's data-dependent diagonal matrices (α_t I). This structural advantage could enable complex reasoning, including regular language recognition (Fan et al., 2024; Grazzi et al., 2024) and state-tracking beyond TC0 complexity (Merrill et al., 2024)".

Limits / extensions (p.10): "Despite these significant advantages, the delta rule faces theoretical limitations (Irie et al., 2023) and shows only moderate performance on real-world datasets (Yang et al., 2024b)". "alternative formulations could further extend expressiveness: nonlinear regression (L(S_t) = ½‖f_{S_t}(k_t) − v_t‖²) as in TTT (Sun et al., 2024a) and Titans (Behrouz et al., 2024), where f_S is a nonlinear function parameterized by S; or regression considering the entire history (L(S_t) = ½Σ_{i=1}^{t}‖S_t k_i − v_i‖²) as in Mesa layer (von Oswald et al., 2024)—analogous to the difference between Least Mean Square and Recursive Least Square algorithms. However, these more expressive variants introduce nonlinear recurrence and require workarounds, such as performing nonlinear updates only after processing entire chunks (as in TTT and Titans)".

Conclusion (p.10): "Gated DeltaNet, which enables better key-value association learning compared to Mamba2 and more adaptive memory clearance than DeltaNet".

## 3. Relevance to BDH-CQ reconstruction

**The affine form.** The paper never writes "S_t = A_t S_{t−1} + B_t", but Eq. 10 is exactly that with right-multiplication (S ∈ R^{d_v×d_k}, transition on the key index):

    S_t = S_{t−1} A_t + B_t,   A_t = α_t (I − β_t k_t k_tᵀ) ∈ R^{d_k×d_k},   B_t = β_t v_t k_tᵀ ∈ R^{d_v×d_k}.

A_t is symmetric; with ‖k_t‖₂ = 1 its eigenvalues are α_t (multiplicity d_k − 1) and α_t(1 − β_t) (eigenvector k_t) — a contraction, hence stable. If one stores Sᵀ (keys × values, Pathway-style left action) the same A_t multiplies on the left. Data dependence: α_t, β_t, k_t, v_t are all functions of the current input only (plus the width-4 short conv), never of S_{t−1}.

**Match to "linear correction rules on S".** Writing Eq. 10 as a correction, S_t = S_{t−1} + U(S_{t−1}, D_t) with D_t = (k_t, v_t, α_t, β_t):

    U(S, D_t) = (α_t − 1) S + β_t ( v_t − α_t S k_t ) k_tᵀ,

which is *linear in S* and *not* of the special form U(D_t) alone — the correction reads the state (S k_t) before writing. Pathway's sentence ("linear attention being the conceptually simplest standalone realization of linear correction rules on S, capturing the special case S_t = S_{t−1} + U_θ(D_t)") describes exactly the LA row of Table 1; the delta and gated-delta rows are the next two members of the same family (Table 1 lays out the ladder LA → Mamba2 → Longhorn → DeltaNet → Gated DeltaNet as online-learning problems). So GDN is a concrete, published, hardware-efficient instance of a "linear correction rule on S" that is *more* than the special case, and it is my best guess for the kind of rule BDH-CQ means — with the caveat that this is an inference from wording, not evidence. The paper's own framing — S is a fast-weight matrix updated by test-time SGD on ½‖S k_t − v_t‖² with weight decay α_t (p.5) — is the same framing as Wang/Shi/Fox's test-time regression (2501.12352, already in our notes), which generalizes the family.

**No match for the latent refinement loop.** GDN reads the state once: o_t = S_t q_t. Nothing in the paper iterates H_{r+1} = F(H_r, S_K) over a frozen state. The nearest pointers are in Related Work (p.10): TTT/Titans (nonlinear f_S, updates "only after processing entire chunks") and the Mesa layer (full-history least squares, RLS). If BDH-CQ's F_θ(H_r, S_K) is "apply the fast-weight matrix S_K to a latent and refine", that is the fast-weight-programmer reading (Irie et al. 2022a/b cited here), but the paper gives no such construction. What this paper does settle: a state built by a (gated) delta rule is a *regression solution* (least-squares fit of values to keys), so reading it with o = S q is already an inference step; iterating would mean something like solving with the stored associations as constraints. Speculation beyond the text — marked as such.

## 4. Relevance to distant context cues

**Which component carries context across distance.** Only the matrix state S (one d_v×d_k matrix per head per layer) carries information beyond the short conv's 4-token window; in hybrids, SWA adds exact access within 2K tokens. The time scale of S is set by α_t, a *data-dependent scalar per head per token*: α_t = exp(−A_h · softplus(w_a·x_t + b_Δ)) [code]. A head can hold indefinitely (α → 1) or clear instantly (α → 0). Init spreads heads over half-lives from < 1 token to effectively unbounded [code: dt log-uniform in 0.001–0.1, A uniform in 0–16]. The delta rule adds a second, *content-addressed* time scale: an association persists until the same key is rewritten, independent of how many unrelated tokens intervene — the paper's S-NIAH-1 result is precisely this (DeltaNet 98.8 at 8K with no decay; GDN 91.8; Mamba2 30.4).

**Is the context given or inferred?** Inferred, end-to-end, from the LM loss only. There are no segment labels, task ids or boundary tokens; the paper's notion of "context switch" (p.2) is an emergent event where α_t → 0 is learned to be useful. There is no auxiliary loss, no gate-specific learning rate, no recipe — just AdamW 4e-4 / wd 0.1 / clip 1.0 / cosine / 1B-token warm-up, and (code) weight decay switched off for A_log and dt_bias.

**How the gates see context.** α_t and β_t are linear in the *residual-stream input to that layer* (`hidden_states`) — the gate does not see the previous state, and at layer ℓ > 1 it sees whatever lower layers wrote into the residual stream. This is the "per-layer gate over the residual stream" that our project has on its list, and here it is simply the standard design (paper p.9: "relying solely on input data"). The paper does not analyse what the gates learn.

**The short conv as a local "window gate" on keys (inference).** k_t, q_t, v_t pass through a causal conv of width 4 before L2 norm, so the key written at a position is a function of the current and previous 3 tokens. In our grouped layout [CTX_s, KEY_i, VAL] that means GDN's key at VAL and query at KEY can both carry CTX_s — the same key token gets a *different, context-dependent key vector*, so conflicting bindings do not collide at all, without any routing. This is a second mechanism for our problem (contextualize the key) alongside ours (route to a different channel). It fails for the header layout for exactly the reason our LOCAL3 gate fails: the conv cannot see CTX more than 3 tokens back. The paper gives the conv 1.6 ppl of value (Table S.1) but offers no analysis of why.

**What the paper says fails at distance.** The learned forget gate is tuned to the training distribution and *erases* lone distant facts: "Decay hurts memory retention" (Mamba2 65.4/30.4 at 4K/8K on pass-key). Pure delta without gating retains but saturates ("memory collision") on busy contexts. For our header task the lesson is double-edged: a learned per-channel forget gate can learn to hold a header for 2P tokens, but if trained on data where most things should be forgotten it will tend to forget the header too, and the paper's fix for that (delta-rule persistence) requires separate k/v and a read-before-write.

## 5. Relevance to our gate

### 5.1 Beliefs supported / contradicted / pitfalls

Supported:
- *A single shared Hebbian memory collides when the same key must hold several values* — the paper states it in capacity terms (p.1 quote) and attributes DeltaNet's advantage to delta-rule capacity > Hebbian capacity (Gardner 1988; Prados & Kak 1989).
- *A per-layer gate reading the residual stream is reasonable* — it is exactly how α_t, β_t are computed here, per layer, with no extra machinery.
- *A learned forget gate is worth having* — strongest single ablation: no gate (naive delta) costs 3.5 ppl at 400M; gating is "a classical concept ... whose significance has been consistently reaffirmed" (p.9).
- *Width-3 windows are fundamentally limited at distance* — implied by the conv-4 design plus the need for S (and SWA in hybrids).

Contradicted / nuanced:
- The paper's answer to "the same key in different contexts" is **not coexistence**: the delta rule *overwrites* ("erases the value associated with the current input key and writes a new value"), and gating *clears* at context switches. The paper's whole memory model is one value per key direction per head, with contexts handled sequentially (erase and rewrite), not in parallel. Nothing in the paper discusses heads as separate memories, routing tokens to subsets of heads, or context-dependent read/write selection. Our k-channel coexistence question is therefore *untouched* here, and the paper's own mechanism would actively destroy the first binding when the second arrives (β_t → 1), rather than superpose it as Hebbian writing does.
- Our softmax gate forces competition between channels. GDN's per-head β_{h,t} = σ(·) is an *independent* per-head write strength (no normalization across heads), and there is no read gate at all (o_h = S_h q_h for every head, then one SiLU output gate on the concatenation). If one reads heads as channels, GDN "routes" by independent sigmoids on writes only.

Pitfalls the paper warns of (explicitly or by ablation):
- L2-normalize keys (and queries) — "for training stability" and "essential"; L1 variants cost ≈ 3 ppl. With ‖k‖ = 1 the Householder factor has eigenvalue 1 − β ∈ (0,1); without normalization 1 − β‖k‖² can be < −1 and the recurrence explodes (my inference; the paper just says "stability").
- Keep β ∈ (0,1) unless you want negative eigenvalues deliberately (footnote 2; Grazzi 2024, Siems 2025 — expressivity for state tracking, at the cost of contraction).
- Do not run a delta rule without a forget gate on long, busy streams: "memory collision", S-NIAH-2 45.6 → 14.4 for DeltaNet.
- Do not expect a forget gate to keep lone distant facts: S-NIAH-1 Mamba2 numbers.
- Output gate and short conv are each worth ≈ 1.6–1.8 ppl; output norm ≈ 0.2.
- Nothing on straight-through estimators, pooled summaries, router collapse, or splitting — none of these concepts appear.

### 5.2 Concrete, implementable ideas

(a) **Delta-rule write per channel** (direct transplant of Eq. 10 into our k-channel memory; our gate g_t ∈ Δ^k scales both the write strength and the erase):

    S^c_t = S^c_{t−1} ( α^c_t ( I − g^c_t β_t k_t k_tᵀ ) ) + g^c_t β_t v_t k_tᵀ,   c = 1..k,   ‖k_t‖₂ = 1
    o_t   = Σ_c g^c_t S^c_t q_t          (read gate as now)

Equivalently S^c_t = α^c_t S^c_{t−1} + g^c_t β_t ( v_t − α^c_t S^c_{t−1} k_t ) k_tᵀ: the write is the per-channel *prediction error*. Consequences for BindTask (my inference): (i) in a single channel the second value for KEY_i overwrites the first — the single-channel baseline fails *harder and cleaner* than with Hebbian superposition, which would make "binding = evidence of routing" sharper, including in the header layout at P = 4 where a single Hebbian channel currently muddles the comparison; (ii) within a correctly routed channel, non-orthogonal keys no longer cross-talk (the delta rule fits the least-squares map), so the number of keys per channel can exceed what Hebbian writes tolerate at D = 32 — this should raise the oracle ceiling at P = 8. Cost: a read S^c_{t−1} k_t per channel per token (k small matrix-vector products), identical to the read already needed.

(b) **A "current-context register" via the delta rule with a constant key** (my construction, motivated by the paper's overwrite semantics and by our per-layer idea). Give layer 1 one channel whose key is a learned constant direction k₀ for header tokens, β ≈ 1: each header overwrites the previous one (S k₀ = latest header's value), and every later token's query component along k₀ reads back the *current block's header* into the residual stream. Layer 2's gate (reading the residual stream, as GDN's α/β do) then has the stream identity at every position of the block, regardless of P. A Hebbian write with decay cannot do this cleanly: it superposes all headers with weights decay^(Δt), so the latest header dominates only if decay is strong, which conflicts with holding anything else for long. This is the one place where the paper's mechanism bears directly on the UNSOLVED header problem: overwrite semantics give an exact, length-independent "last value seen" operation.

(c) **Forget gate, GDN-style, per channel** (the only form the paper endorses; details from the code, so verify against the repo):

    α^c_t = exp( − A_c · softplus( w_a^c · x_t + b_Δ^c ) ),   A_c = exp(A_log_c) > 0 learnable
    init: A_c ~ U(0, 16) (Mamba2 uses U(1, 16)), b_Δ^c = softplus⁻¹(dt_c), dt_c log-uniform in [0.001, 0.1], floor 1e-4
    no weight decay on A_log, b_Δ; w_a from the layer's residual input (not from raw embeddings); same lr as everything else

The decay is a scalar per channel/head per token, not per dimension (RWKV-7's diag(d_t) is mentioned as the per-dimension alternative, GLA's outer-product decay as the matrix-valued one). Half-life ln2/(A·Δ): to start near our 0.95, set A·softplus(b_Δ) ≈ 0.05; to let channels discover their own horizons, keep the paper's spread. For "human-like long memory" the paper's evidence says: rely on delta-rule persistence (content-addressed) rather than on α → 1 alone, because a learned α is pulled toward forgetting by the bulk of the data.

(d) **Write strength β_t = σ(w_b·x_t + b_b)** per channel/head, (0,1), default init ⇒ β ≈ 0.5 (inferred from code; not stated). This is a *second gate* the paper has and we don't: it lets a token decline to write at all (β → 0) without touching the routing gate. For us it would let a CTX or KEY token write nothing while VAL writes — currently our g_t has to do that job and routing at the same time.

(e) **Short conv on k/q/v (width 4) + L2 norm on k/q** — cheap, and the conv is a mechanism that makes keys context-dependent locally. If we keep our window gate, the paper suggests putting the window on the *keys* as well as on the gate.

(f) **Output gate** o ← RMSNorm(o) ⊙ SiLU(W_g x_t): consistently helpful here (1.8 ppl); we have LayerNorm after attention but no multiplicative output gate.

(g) **Error-driven routing (speculative, enabled by (a))**: the per-channel prediction error e^c_t = v_t − α^c_t S^c_{t−1} k_t tells which channel already holds a *consistent* binding for k_t (small error) and which holds a *conflicting* one (large error). A write gate that prefers channels with small error, or that avoids channels where the key is already bound to something else, would separate conflicting bindings from the conflicts themselves, without seeing CTX — but the read still has to be routed by CTX_q, so this only helps the write side. Not in the paper.

Training-recipe notes: the paper uses one lr for everything (4e-4 peak at 1.3B), long warm-up (1B tokens = 2000 steps at 0.5M tokens), cosine decay, wd 0.1 except on the decay parameters. There is no analogue of our slow-memory lr, hinge penalty, or channel split, and no report of instability other than the need for L2 normalization.

## 7. Verdict

This paper does not address our question (coexisting conflicting bindings discovered label-free) and its memory model is the opposite answer: one value per key per head, with the delta rule overwriting and the gate clearing at context switches. But it changes two things for us. First, it hands us a cheap, stable, well-tested write rule — S_t = S_{t−1}(α_t(I − β_t k_t k_tᵀ)) + β_t v_t k_tᵀ with L2-normalized keys and a sigmoid β — whose overwrite semantics make the single-channel failure on BindTask sharp (the second binding erases the first) and whose least-squares semantics should raise the oracle ceiling per channel; and the same overwrite semantics give an exact "latest header" register in layer 1, which is the most concrete route I have seen to the unsolved header layout, in combination with the per-layer residual-stream gate that this paper uses as a matter of course. Second, it gives a ready parameterization and initialization for a per-channel forget gate (α = exp(−A·softplus(·)), log-uniform time-scale init, no weight decay on A_log/dt_bias), together with a clear warning that a learned forget gate erases rare distant facts unless persistence is content-addressed. For the BDH-CQ reconstruction it is strong circumstantial support that "linear correction rules on S" means the Table-1 family (LA → Mamba2 → delta → gated delta), and no support at all for the latent refinement loop. Confidence: high on what the paper says and on the equations (one output-mask symbol flagged); medium on the transplant ideas (a)–(d), which are straightforward but untested in our setting; the register idea (b) is my construction and should be treated as a hypothesis to test, not a result.
