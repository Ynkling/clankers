## 1. What the paper actually does

### 1.1 One-paragraph summary

A position-plus-architecture paper. The "Nested Learning" (NL) thesis is that every component of a trained model — the architecture's layers, the recurrent memory of modern RNNs, *and the optimizer itself* (SGD, momentum, Adam, Muon) — is an **associative memory** that compresses its own "context flow" (tokens for layers, gradients for optimizers) by **gradient descent on an inner objective**, and that components can be ordered into **levels by update frequency**. Three concrete artefacts: (a) "more expressive optimizers" derived by changing the inner objective/memory of momentum (Delta Momentum, Deep Momentum GD, Delta Gradient Descent, Multi-scale Momentum Muon = M3); (b) a **Continuum Memory System (CMS)**: a chain of MLP blocks, each updated at test time by gradient steps on the task loss every C^(ℓ) tokens, with different C^(ℓ) per block; (c) **self-modifying (self-referential) Titans**: a Titans-style fast-weight memory in which the key/value/learning-rate/forget-gate projections are themselves fast-weight memories that generate their own target values. **HOPE** = self-modifying Titans followed by a CMS (plus "Hope-Attention" = softmax attention followed by a CMS). Results: LM/common-sense at 760M and 1.3B (Hope avg 52.28 / 58.04 vs Titans 51.68 / 56.82 vs Transformer++ 50.11 / 53.38), RULER NIAH to 16K (Hope best among attention-free models, far below Transformers on multi-key/query/value), BABILong (figure only; "maintains its good performance even for 10M"), continual learning with Llama-3 backbones whose MLPs are converted to CMS (figures only), MAD, in-context recall, formal languages (perfect scores), ablations (Table 6), and M3 on ViT/ImageNet-21K (figure only).

### 1.2 The Nested Learning formalism (§3, pp.7–14; Appendix A, p.50)

**Associative memory (Definition 1, p.7).** "Given a set of keys K ⊆ R^{d_k} and values V ⊆ R^{d_v}, associative memory is an operator M(·) that maps the set of keys K to values V. To learn such mapping from the data, an objective L̃(·;·) measures the quality of the mapping and M can be computed by:
  M* = arg min_M L̃(M(K); V).   (6)"
Keys and values "can be any arbitrary event ... keys and values might be tokens, gradients, sub-sequences, etc." (p.8).

**Terminology box (p.7):** "Memory is a neural update caused by an input, and learning is the process for acquiring effective and useful memory."

**Gradient descent on a linear layer as an associative memory (p.8).** With y_{t+1} = W x_{t+1}:
  W_{t+1} = W_t − η_{t+1} ∇_W L(W_t; x_{t+1}) = W_t − η_{t+1} ∇_{y_{t+1}} L(W_t; x_{t+1}) ⊗ x_{t+1}   (8)
("Surprise" = ∇_W L; "Surprise in the Output" = ∇_y L, the "Local Surprise Signal (LSS)"). Proximal/associative form, with u_{t+1} = ∇_{y_{t+1}} L(W_t; x_{t+1}):
  W_{t+1} = arg min_W ⟨W x_{t+1}, u_{t+1}⟩ + (1/(2η_{t+1})) ∥W − W_t∥²_2   (9)
Box (p.8): "A linear layer trained with backpropagation learns from data by memorizing how surprising their predicted outputs are; i.e., backpropagation can be viewed as an associative memory that maps each data sample to the error of its corresponding prediction."

**Momentum as a 2-level memory (p.9).**
  W_{t+1} = W_t − m_{t+1},   m_{t+1} = m_t + η_{t+1} ∇_W L(W_t; x_{t+1}) = m_t + η_{t+1} ∇_{y_{t+1}} L ⊗ x_{t+1}   (10–11)
  m_{t+1} = arg min_m −⟨m, ∇_{W_t} L(W_t; x_{t+1})⟩ + (1/(2η_{t+1}))∥m − m_t∥²_2 = arg min_m −⟨m x_{t+1}, ∇_{y_{t+1}} L⟩ + (1/(2η_{t+1}))∥m − m_t∥²_2   (12–13)
"the momentum term [is] either: (1) a value-less associative memory that compress the gradients into its parameters, or (2) an associative memory that learns how to map data points to their corresponding LSS-value. ... gradient descent with momentum can be viewed as a two-level optimization procedure, where the memory is optimized by simple gradient descent" (p.9).

**Linear attention as GD on a dot-product objective (p.9).** Eq. (14)–(16): k_t = W_k x_t, v_t = W_v x_t, q_t = W_q x_t; M_t = M_{t−1} + v_t k_t^⊤; y_t = M_t q_t. With L̃(M_{t−1}; k_t, v_t) := −⟨M_{t−1} k_t, v_t⟩, ∇L̃ = −v_t k_t^⊤, η = 1:
  M_{t+1} = arg min_M −⟨M k_{t+1}, v_{t+1}⟩ + ½∥M − M_t∥²_2 ⇒ M_{t+1} = M_t + v_{t+1} k_{t+1}^⊤   (17–18)
"training a linear attention with gradient descent can be seen as a two-level optimization process, where the outer-loop ... optimizes the projection layers with gradient descent, while the inner-loop optimizes the inner memory of M_t with gradient descent" (p.9). With momentum on the outer loop the paper still calls it "a 2-level optimization problem" but notes that momentum "itself can be viewed as a 2-level optimization process" (p.10) — implicitly a third level.

**Update frequency and levels (Definitions 2–4, pp.10–11).**
- Definition 2: "For any component of A, which can be a parametric component (e.g., learnable weights or momentum term ...) or a non-parametric component (e.g., attention block), we define its frequency, denoted by f_A, as its number of updates per unit of time" where "one update step over one data point [is] the unit of time."
- Ordering: A ≻ B if f_A > f_B, or f_A = f_B but B's state at time t requires A's state at time t; "components in the same level have the same frequency update, and ... the higher the level is, the lower its frequency." (p.11) Adam's two moments are given as the example of two same-level, independent components (p.51).
- Definition 3 (Nested System), each parameter updated by one GD step written as a proximal problem **[equation garbled; reconstruction of (19)]**:
  θ_i^{(k)}{}_{t+1} = arg min_{Φ_i^{(k)} ∈ Θ_i^{(k)}} ⟨Φ_i^{(k)} x_{t+1}, −∇L_i^{(k)}(θ_i^{(k)}{}_t; x_{t+1})⟩ + (1/(2η_i^{(k)}{}_{t+1})) ∥Φ_i^{(k)} − θ_i^{(k)}{}_t∥²_2,  x_{t+1} ∼ C_i^{(k)}.
  (Note the sign of the inner product is opposite to (9); the intent in both is one descent step. The inner product is dimensionally loose unless ∇L means the output gradient as in (9).)
- Definition 4 (Nested System of Associative Memories, NSAM): same with context C_i = {(k_j^{(i)}, v_j^{(i)})}, i.e. ⟨Φ k_{t+1}, −∇L(θ_t; k_{t+1}, v_{t+1})⟩ + prox (20). Appendix A (p.50) generalises to the full proximal step θ_{t+1} = arg min L(Φ; x_{t+1}) + (1/2η)∥Φ − θ_t∥² (98)–(99), i.e. implicit GD, which is what yields the Sherman–Morrison "Delta Gradient Descent" below.
- Non-parametric solutions are allowed for some "boxes" (softmax attention).

**Knowledge transfer between levels (§3.3, pp.13–14):** (i) direct parametric conditioning M^{(0)}(·) := M^{(0)}(·; Θ^{(1)}) (24) or on the output M^{(0)}(·; M^{(1)}(·)) (25) — e.g. FWP/linear Transformer forward pass y_t = M_t (x_t W_q) (26); (ii) non-parametric conditioning on the other level's context (27) — softmax attention; (iii) backpropagation across levels (same gradient flow, different frequencies) — used in CMS; (iv) initialisation (MAML): Θ_0^{(1)} = arg min_Φ E_{C∼C^{(0)}} ℓ(M^{(1)}(·; Φ), C) (28) — the "meta-learned initial memory state" of Titans/TTT; (v) generation (hypernetworks; and "the architecture generates the input for the optimizer", i.e. gradients). Design box (p.14): "two high-level design choices ...: (1) The design of optimization problems and their frequency ...; (2) The design of knowledge transfer between levels."

**MLP vs Linear Attention++ (p.11–12, Fig. 3).** Transformer block y_block = y_attn W_MLP vs "AdaTransformer" y_block = y_attn W_LinAttn with W_LinAttn updated in-context by M_t = M_{t−1} + v_t k_t^⊤ (21) and initial state M_0 = W_LinAttn^init meta-learned at level 1. "the only difference comes from the level of W_MLP and W_LinAttn weights." Hence the slogan (box, p.26) "Recurrent Models are Replacing MLP Blocks".

### 1.4 Deep / expressive optimizers (§4.3–4.5, pp.17–21; §7.2, p.29)

Motivation (p.18): with β = 0.9 "the last 6 gradients (resp. 43 gradients) are responsible for at least 50% (resp. 99%) of the cumulative contribution" so momentum "acts as a simple low-pass filter"; continual learning with orthogonal tasks loses "memory of the old gradient subspace".

- **Preconditioned momentum (value = P_i)** (p.18): min_m ⟨m ∇L(W_i; x_i)^⊤, P_i⟩ (46) ⇒ W_{i+1} = W_i + m_{i+1}, m_{i+1} = m_i − η_i P_i ∇L(W_i; x_i) (47). The text says "where we also included a forget gate α_{i+1}" but (47) as printed has no α.
- **Delta Momentum** (p.19): objective ∥m ∇L(W_i; x_i)^⊤ − P_i∥²_2 ⇒ **[garbled; reconstruction of (49)]** m_{i+1} = m_i (α_{i+1} − ∇L(W_i;x_i) ∇L(W_i;x_i)^⊤) − η_t P_i ∇L(W_i;x_i); W_{i+1} = W_i + m_{i+1} (48). "This update is based on delta-rule ... we may learn to forget some of the past gradients." (Dimensionally loose: m and ∇L are both W-shaped matrices.) Toy example (53), p.20: ψ(r,θ) = r² + k(r − θ + α sin(ωr))², start (−3.5, 2): "The delta momentum finds the solution faster, mainly due to its gradient-dependent weight decay that helps the momentum term to decay or stop when it is needed." (Fig. 4; no numbers.)
- **Deep Momentum GD (DMGD)** (p.19): W_{i+1} = W_i + m_{i+1}(u_i), m_{i+1} = α_{i+1} m_i − η_t ∇L^{(2)}(m_i; u_i, 1), u_i = ∇L(W_i; x_i), where m(·) is an MLP and L^{(2)} e.g. ⟨m(u_i^⊤), 1⟩ (50). Claim: "allows momentum to memorize more gradients". No experiment.
- **Higher-order feature maps**: m_{i+1} = α m_i − η P_i φ(∇L) (51). **Nonlinear output**: W_{i+1} = W_i + σ(m_{i+1}(u_i)) (52); with σ = Newton–Schulz and linear m this "resulting in Muon".
- **DGD** (56)–(57) and Appendix C (p.52): stationarity 2(W_{t+1}x_t − ∇_{y_t}L)x_t^⊤ + 2η_t(W_{t+1} − W_t) = 0 (114) ⇒ W_{t+1} = (∇_{y_t}L x_t^⊤ + η_t W_t)(x_t x_t^⊤ + η_t I)^{-1} (116); (x x^⊤ + η I)^{-1} = (1/η)(I − x x^⊤/(λ² + η)) (117); final form W_{t+1} = W_t(I − α_t x_t x_t^⊤) − β ∇_{y_t}L(W_t, x_t) x_t^⊤ (121) with α_t = β = 1/(λ² + η_t) **[my simplification of the garbled (119)–(120)]**. Note the appendix regresses onto +∇_yL (ascent sign) while the main text uses u_t = −∇_yL; and the appendix's η_t multiplies the proximal term (inverse step size) whereas the main text's η′_t = η_t/(1+η_t) treats η_t as a step size. Both give the same structure: **a key-side shrinkage (I − c x x^⊤) plus a rank-one write.**
- **M3 (Algorithm 1, p.29)**: inputs Θ_0, L, η, Newton–Schulz steps T, 1 > β₁, β₂, β₃, α ≥ 0, ε, frequency f. Per slow iteration k: slow memory M^{(2)}_t = M^{(2)}_{t−1} + β₃ Σ_{i=(k−1)f}^{kf} g_i; O^{(2)} ← NewtonSchulz_T(M^{(2)}); per inner step t: g_t = ∇L(Θ_t); M^{(1)}_t = M^{(1)}_{t−1} + β₁ g_t; V_t = V_{t−1} + β₂ g_t²; O^{(1)} ← NewtonSchulz_T(M^{(1)}); Θ_t ← Θ_{t−1} − η (O^{(1)}_t + α O^{(2)}_t)/(√V_t + ε). Eq. (75) prints the slow memory with a minus sign and β₂ (inconsistent with Algorithm 1's +β₃). "M3 is the combination of Adam, Muon, and our Continuum Memory System." "designed as a proof-of-concept ... might suffer from computational overhead" (p.29). Results: ViT 24M/86M on ImageNet-21K (patch 16, MLP dim 1536/3072): "Our M3 shows the best training/test loss compared to both AdamW and Muon" (Fig. 11, no numbers, p.40); LM 140M/1.3B: "relatively slower compare to the Muon optimizer, and show on par efficiency with AdaMuon" (Fig. 12, p.40). Related: Devan Selvaraj (2025) "Multiscale Muon" blog and AdEMAMix (Pagliardini et al., ICLR 2025) also use multiple momentum terms (p.29).

### 1.5 Continuum Memory System (§7, pp.27–30)

Framing (p.27): backbones have "(1) a working memory module (e.g., attention) ... and (2) a feed-forward layer (e.g., MLP) ... the persistent memory or knowledge storage of pre-training phase ... we extend the traditional view-point of long-term/short-term memory system and suggest a knowledge storage feed-forward for each level (frequency domain)."

**Definition (p.27).** "Continuum Memory System (CMS) is formalized as a chain of MLP blocks MLP^{(f_1)}(·), …, MLP^{(f_k)}(·), each of which associated with a chunk size of C^{(ℓ)} := (max_i f_i / f_ℓ)·C" **[the printed `max𝑓𝑖ℓ𝐶` is garbled; this reading — the base chunk C scaled by the frequency ratio, so the fastest block has chunk C and slower blocks have proportionally larger chunks — is a reconstruction]**. Forward pass (normalisations dropped):
  y_t = MLP^{(f_k)}(MLP^{(f_{k−1})}(⋯ MLP^{(f_1)}(x_t)))   (70)
Update **[garbled; reconstruction of (71)]**:
  θ^{(f_ℓ)}_{i+1} = θ^{(f_ℓ)}_i − Σ_{t=i−C^{(ℓ)}}^{i} η^{(ℓ)}_t f(θ^{(f_ℓ)}_t; x_t)   if i ≡ 0 (mod C^{(ℓ)}),   and θ^{(f_ℓ)}_{i+1} = θ^{(f_ℓ)}_i otherwise,
"Here η_t^{(ℓ)} are learning rates corresponds to θ^{(f_ℓ)}, and f(·) is the error component of an arbitrary optimizer (e.g., ∇L(θ_t^{(f_ℓ)}; x_t) in gradient descent). The conventional Transformer block ... is a special instance of this formulation, where k = 1 and frequency of update is zero. Note that the objective of L(·) is the objective of choice for the task at hand, e.g., for language modeling it is next token prediction objective." (p.27). Since θ is frozen inside a chunk, the sum is simply the batch gradient of the task loss over the chunk, applied once at the chunk boundary. **So a CMS block is test-time training of an MLP on the NTP loss with period C^{(ℓ)}.**

**Time scale = update period.** The only notion of time scale is the chunk length C^{(ℓ)} (Definition 2: updates per unit time). There is no forgetting inside a CMS block except by later gradient steps overwriting it; persistence is "how rarely it is updated", not "how fast it decays". This is a different notion from our exponential decay (and from the paper's own α_t retention gate in Titans).

**Variants (p.28).**
- *Nested CMS*: "the initial state of the MLP block in level s + 1 is meta-learned in level s ... each of the levels has its own context flow and re-initialized after the end of the context": θ_0^{(f_{s+1})} = arg min_Φ E_{T∼C^{(s)}} ℓ(Θ, T; Φ) (72); "after ⌈C^{(s)}/C^{(s+1)}⌉ steps the value of the memory will be re-initialized to θ_0^{(f_{s+1})}". (The index direction is confusing: if level s+1 is slower, that ratio is < 1.)
- *Sequential CMS*: blocks in a chain, "the initial state of MLP blocks are all connected through backpropagation in the lowest frequency level": θ_0^{(f_s)} = arg min_Φ E_{T∼C^{(1)}} ℓ(Θ, T; Φ) (73).
- *Independent (head-wise) CMS*: y_t = Agg(MLP^{(f_k)}(x_t), …, MLP^{(f_1)}(x_t)) (74), "one straightforward and simple design choice is to use a learnable weighted sum". (This is the variant used in M3.)

**Why it should help continual learning (verbatim, p.28):** "when updating an arbitrary block of MLP^{(f_s)}(·) for some 1 ≤ s ≤ k, the potentially forgotten knowledge from MLP^{(f_s)}(·) is still stored in other components such as MLP^{(f_{s′})}(·), where s′ < s. Also, in this case ... the knowledge transfer through backpropagation (for their initial state) can circle back the knowledge to MLP^{(f_s)}(·), resulting in a loop through time dimension, and so hardly forgetting important knowledge." Note that the "circle back" happens through the *initial-state* gradients, i.e. only during the outer (pre-)training level; at deployment there is no backprop into the init. **The paper has no explicit consolidation operator (no distillation or replay from fast to slow blocks); "consolidation" is realised only as slower blocks accumulating gradients over longer chunks, with the fast block's output as the slow block's input.** Offline/sleep consolidation is explicitly out of scope: "in this work, we focus on the first stage: memory consolidation as an online process." (p.3).

**Efficiency (pp.28–29):** updates restricted to blocks at their scheduled time; "unlocks the sequence parallelization for higher frequency levels ... when i ≢ 0 (mod C^{(ℓ)}) there is no sequential process inside the chunk"; training algorithm "the same as ... Sun et al. (2024) and Behrouz et al. (2025c)". Cost formula garbled (roughly O((1/f̂)·L_layer·d_in²/5) parameters updated on average with 4 levels).

**Ad-hoc level stacking (§7.3, p.29–30):** initialise CMS blocks with a pre-trained Transformer's MLPs, MLP_0^{(f_i)} = MLP^{pre-trained}_i; "setting η_t^{(ℓ)} → 0 keeps the updated memory blocks close to their initial states, resulting in directly using of pre-trained blocks, without adaption." Used with Llama-3 in §9.1.

### 1.6 Self-modifying Titans and HOPE (§8, pp.30–33)

Motivation (p.31): "given a 1-layer Transformer, the projection of each token is a function of the token itself and its position; therefore ... it can miss the diverse possible encodings of words whose meaning depend on the context, rather than the word itself." Short convolutions / canon layers mix locally but "still the models are fundamentally limited to adapt to the context and capture the global information beyond the local mixing."

**Parametric associative memory block (76)–(78):** k_t = x_t W_k, v_t = x_t W_v, q_t = x_t W_q, η_t = x_t W_η, α_t = x_t W_α; min_M L(M; k_t, v_t); y_t = M_t q_t.

**Fully adaptive (79)–(82):** k_t = M_{k,t−1}(x_t), v_t = M_{v,t−1}(x_t), q_t = M_{q,t−1}(x_t), η_t = M_{η,t−1}(x_t), α_t = M_{α,t−1}(x_t); each M_□ minimises L(M_□; □_t, v_t) (shared values); min L(M_mem; k_t, v_t); y_t = M_{mem,t}(q_t). Initial states M_{□,0} meta-learned.

**Self-modifying (self-generated values) (83)–(85), (86)–(88):**
  y_t = M_{memory,t−1}(q_t),  k_t = M_{k,t−1}(x_t),  v_t = M_{v,t−1}(x_t),  η_t = M_{η,t−1}(x_t),  α_t = M_{α,t−1}(x_t)   (86)

  **[reconstruction of (88), whose layout is split in the text]**  M_{□,t} = M_{□,t−1}(α_t I − η_t k_t k_t^⊤) − η_t ∇_{M_{□,t−1}} L(M_{□,t−1}; k_t, v̂_{□,t}),  □ ∈ {k, v, q, η, α, memory}

## 3. Relevance to BDH-CQ reconstruction

**What the paper gives us: a taxonomy of fast-weight update rules as "one GD step on an inner loss, plus a retention term", with the Hebbian rule as the state-independent special case.** The paper never uses the words "linear correction rule"; its dividing line is instead *state-independent* (Hebbian: "makes the update rule ... independent of its current state", p.19) vs *state-dependent* (delta/DGD/self-referential). Mapping to Pathway's wording:

- Pathway's special case S_t = S_{t−1} + U_θ(D_t) is exactly the paper's eq. (18)/(64) with α_t = 1: "M_{t+1} = M_t + v_{t+1} k_{t+1}^⊤ ... equivalent to the update rule of an unnormalized linear attention" (p.9). With decay it is (64): M_t = α_t M_{t−1} + η_t v_t φ(k_t)^⊤ — still U independent of S.
- **Rules that are linear (affine) in S but with an S-dependent correction** — what "linear correction rules on S" most plausibly means (inference) — are, in the paper's own list: the delta rule (65) S_t = S_{t−1}(I − η_t k_t k_t^⊤) + η_t v_t k_t^⊤ [DeltaNet, Longhorn, RWKV-7]; its gated/retention variants S_t = S_{t−1}(α_t I − η_t k_t k_t^⊤) + η_t v_t k_t^⊤ (the (88)/(93) operator; Gated DeltaNet is not cited but is this form); Oja (66) with the left-side shrinkage (I − η v v^⊤); DGD on a linear layer (57)/(121); the Omega rule (68) with L2 loss, whose optimum over a window is a ridge-regression linear map of S. All of these are S_t = A(D_t) S_{t−1} + B(D_t) — "linear in S" with input-dependent A, i.e. U_θ(S_{t−1}, D_t) = (A(D_t) − I) S_{t−1} + B(D_t).
- **Rules that are not linear in S:** softmax attention (non-parametric, unbounded state); Titans/TTT/Miras/Atlas with MLP memories (gradient is nonlinear in θ); the paper's self-modifying Titans (keys, values, η_t and α_t are *outputs of other fast weights*, so the joint state evolves by products of state components); CMS (gradient through an MLP).
- Momentum: Titans-style momentum (and the paper's Delta Momentum) keeps the system linear in the *augmented* state (S, m) for a linear memory and quadratic loss; Pathway's "S" could be such an augmented state.

**Most plausible reconstruction of BDH-CQ's U_θ consistent with this paper (inference, not in the paper):** a gated delta-type rule, S_t = S_{t−1}(α_t I − η_t k_t k_t^⊤) + η_t v_t k_t^⊤ with input-dependent scalars α_t, η_t (or per-neuron vectors), possibly with a momentum state. The paper's ablation (Table 6) shows exactly these ingredients — DGD term (−1.17 ppl when removed), weight decay (−1.47), momentum (−1.34) — are what separate a strong rule from plain Hebbian in a BDH-like matrix memory. Because the paper writes the shrinkage on the *key side* (M_{t−1}(αI − ηkk^⊤), eq. 88), the correction acts on the dimension that the query reads against; eq. (65)'s printed left-multiplication is a typo and should not be copied.

**Latent refinement H_{r+1} = F_θ(H_r, S_K): no match.** Nothing in the paper iterates a hidden state against a frozen memory at inference. The closest notions are (i) "latent computation (e.g., Loop Transformers)" named as one of the things "depth of computation" via levels "can itself be viewed as" (p.11), and (ii) the Newton–Schulz iterations reinterpreted as an inner optimisation (eqs. 42–44; "per each step of momentum update, we need k-steps of internal process", p.25). In NL language, Pathway's loop would be "a level whose parameters are the latent H, whose context is the fixed memory S_K, optimised for R steps" — a legitimate reading of Definition 3, but the paper does not instantiate it. The paper's general self-referential form (58)–(60), u_t = f_{W_t}(x_t), is the closest thing to a memory "generating" what is written from its own state, which is a different idea from iterative reading.

**One more pointer:** the paper's remark that output gating of linear attention "acts as a persistent memory and the initialization of the memory module" when M_0 is not meta-learned (p.23) suggests that E_θ(x*, S_K) in BDH-CQ may involve a learned persistent component mixed with the read from S_K; purely a hint.

## 4. Relevance to distant context cues

**Does any component carry a cue over long distances with a learned time scale?**

1. **Self-modifying Titans memory (eq. 86–88).** This is the only component with a *learned, data-dependent* time scale: the retention α_t = M_{α,t−1}(x_t) and learning rate η_t = M_{η,t−1}(x_t) are per-token scalars (or vectors — not specified) produced by fast-weight MLPs whose initial states are meta-learned and which are themselves written in-context. The "time scale" is continuous (how much of S survives per step), not frequency-based. The cue is INFERRED from data: nothing is labelled; the only training signal is NTP at the outer level and the inner L2 regression on self-generated values. However, in the chunked implementation (p.32) α_t, η_t, k_t, v_t for a whole chunk are computed from memory states frozen at the previous chunk boundary, so in-context adaptation of the projections has a latency of one chunk (size not given). At our sequence lengths (21–37 tokens) this would mean either chunk = 1 (fully recurrent, no parallelism) or no within-block adaptation at all.

2. **CMS (eq. 70–71).** Time scale = chunk period C^{(ℓ)}, a **fixed hyperparameter** (Fig. 7 uses lowest-frequency periods of 512 and 2K tokens; the base chunk and the number of levels in the from-scratch LM runs are unspecified). Updates fire at i ≡ 0 (mod C^{(ℓ)}): **purely positional, not learned, not data-dependent; no boundary detection of any kind.** The "context" each block compresses is whatever tokens fell in its chunk. The CMS blocks do carry information across arbitrarily long distances (a gradient step at token i changes the MLP for all later tokens, until overwritten), but what they carry is a gradient-compressed summary of the chunk, not a routing signal.

3. **Could frequencies be data-dependent?** The paper does not consider it. Definition 2 counts updates per unit time; §6 and §7 treat frequency as a design constant; Fig. 5's caption says "potential data-dependent components are removed for the sake of clarity" but refers to gates/normalisations, not to update schedules. The natural NL-consistent way to make a frequency data-dependent is the one the paper already has at the Titans level: α_t → 0 (reset) or η_t → 0 (freeze) chosen by the input. A CMS whose "i ≡ 0 (mod C)" condition is replaced by a learned boundary predictor would be a genuine extension, not something the paper does or tests.

4. **How the components are trained.** Outer level: NTP with AdamW on everything (projections, meta-learned initial states, the non-adaptive W_q, CMS initial states). Inner levels: the inner L2 loss (Titans memories, by DGD) and the task NTP loss (CMS, by any optimiser's error term). No auxiliary losses, no labels for context, no curriculum reported.

5. **Honest takeaway for the header-layout problem.** The paper offers no mechanism that infers block boundaries. Its two distance mechanisms are (a) an input-dependent forget gate on a fast-weight matrix (continuous time scale, learned via meta-learned init), and (b) periodic test-time gradient updates of MLPs (fixed time scale). (a) is the same family as our "selective gate" (0/10 so far); the paper's additional ingredients are that the gate values come from *fast weights with meta-learned initial states* rather than a fixed feed-forward map, and that the memory update also has a key-side shrinkage. (b) is positional and would only "solve" our header layout if chunks happened to align with blocks, which is not a solution.

## 5. Relevance to our gate (window gate, recurrent gate, per-layer residual gate, forget gate)

### 5.1 Concrete borrowable equations

**(a) Per-channel input-dependent forget gate, in the paper's form.** Our memory per channel c is Hebbian with fixed decay: S^c_t = λ S^c_{t−1} + g_{t,c} (write_t), λ = 0.95. The paper's retention gate (eq. 76/86) is α_t = x_t W_α (or α_t = M_{α,t−1}(x_t)), used as S_t = S_{t−1}·α_t + .... Borrow: α^c_t = σ(w^c_α · v_t + b^c_α) per channel, with **b^c_α initialised to logit(0.95) ≈ 2.94** so the model starts at our known-good half-life ≈ 14 tokens and can move per channel and per token. If you want a channel to be able to become persistent, allow α → 1 (the paper's Titans-style gate does); if you want resets, allow α → 0. Nothing in the paper fixes the parameterisation beyond "retention gate (forget gate or weight decay)"; the ablation says removing it costs 1.47 ppl in Hope (Table 6).

**(b) Key-side shrinkage (DGD/delta) instead of pure Hebbian writes.**
  S^c_t = S^c_{t−1}(α^c_t I − η_t g_{t,c} k̂_t k̂_t^⊤) + η_t g_{t,c} v_t k̂_t^⊤,  k̂_t = k_t/∥k_t∥  [paper's (88)/(93) with our per-channel write weight folded into the learning rate].
The paper's reason: dot-product/Hebbian rules "treat each data sample ... independent of the state", which is "restrictive for context with highly dependent elements (e.g., tokens in a sequence)" (p.20), and the Hebbian rule "has a limited capacity (Storkey 1997)" (p.19). The term −η k k^⊤ erases what the channel currently returns for key k before writing the new value.

**This directly addresses an open item in the brief ("a distant-cue task that a single channel provably cannot solve").** With a delta-rule channel at η = 1 and unit keys, a single channel stores *exactly one* value per key: writing (KEY_i → VAL_{i,2}) yields S k̂_i = v_{i,2} and the component along k̂_i that encoded VAL_{i,1} is gone. So in BindTask (grouped or header layout) a **single delta channel provably fails on all but the last-written stream**, whereas the oracle partition (one channel per stream) binds trivially — the clean negative control the brief asks for, without having to push P up to where even the oracle does not converge. (Caveat: cross-talk between distinct non-orthogonal keys remains; the *same-key* conflict is what is provably resolved.) Side effect: the pressure on the router becomes sharper, because superposition can no longer partially rescue a single channel the way it did at P = 4 (3/10, 7/10). Also note the write/read offset in our task (write at VAL with the key being the previous KEY token; read at the query's KEY) must be preserved: the key used in the shrinkage at write time must be the same vector that the query will present.

**(c) L2-normalise the keys/queries used by the memory.** "we also normalize q and k with L2 normalization" (p.33); the Sherman–Morrison derivation assumes ∥x_t∥ = λ (p.20, App. C). For us, with x_t · x_s as the content similarity, normalising the memory's key side makes (b) exact and bounds the memory's growth. Cheap; the paper gives no ablation for it.

**(d) Meta-learned initial memory state per channel (Linear Attention++).** "the initial state of M_0 = W_LinAttn^init is optimized in the first level" (p.12); "essential for both fast-adaption, training stability, robustness to noise" (p.31). For us: a learned S^c_0 (N×N per channel, or low-rank) gives each channel an a-priori "specialty". With λ = 0.95 it would decay away within ~60 tokens unless the forget gate (a) learns to retain it; with per-channel α near 1 for some channels it persists. The recurrent gate's h_0 can also be learned (trivial).

**(e) Time-scale diversity across channels ("continuum").** CMS's organising principle is that memories differ by *time scale*, not content: "higher-frequency neurons are responsible for fast adaption but store memories/knowledge for a short period of time, while lower frequency neurons are responsible for more persistent knowledge" (p.5). Transplanted: give the k channels fixed (or learned-scalar) decays log-spaced in half-life (e.g. 4, 14, 50, 200 tokens) in addition to, or instead of, content routing. The brief says multi-scale EMA *gate inputs* were tried (0/10); multi-scale *channel decays* appear untried. This is not a solution to routing by stream, but it changes what "channel" means and is cheap to test.

**(f) Lower-frequency (held) gate — CMS logic applied to the router.** Compute g once per chunk of C tokens and hold it: this is eq. (71)'s "i ≡ 0 (mod C)" applied to the gate. It is positional; it solves the header layout only when C is aligned with block boundaries (a cheat) and is otherwise useless. Mention only as a diagnostic (it tells you whether a *stable* routing within a block is sufficient for binding, independent of discovering the boundary).

**(g) Context-adaptive key projection instead of channel routing.** The paper's diagnosis of the 1-layer bottleneck (p.31: a token's projection "is a function of the token itself and its position" and so "can miss the diverse possible encodings of words whose meaning depend on the context") is exactly BindTask. Its fix is k_t = M_{k,t−1}(x_t): a *fast-weight key projection written by earlier tokens*, so KEY_i after CTX_s is projected differently from KEY_i after CTX_{s′}. That is an alternative to our partition: make the key stream-specific, then a single (delta) memory can hold S values of "the same" key because they are no longer the same key. In our setting this is equivalent in spirit to the per-layer-residual-gate idea (layer-1 attention copies the header into each position so the key carries the stream), which the paper's argument supports. The paper's ablation shows the k and v inner projections are its two most valuable components (removing them costs 1.53 and 1.66 ppl, Table 6), more than CMS (0.80).

### 5.2 What the paper supports, contradicts, or warns

**Supports**
- Local mixing cannot carry distant context: "fundamentally limited to adapt to the context and capture the global information beyond the local mixing" (p.31) — consistent with the window gate's 2-token horizon and its 2/10 (by key splits) on header layout.
- Routing/projection signals should be computed from a contextualised representation, not from the raw token (p.31 argument; the adaptive projections). This favours the per-layer gate over the residual stream.
- Hebbian superposition is capacity-limited and state-blind (p.19–20); retention and state-dependent corrections matter (Table 6).
- A strong slow level is prerequisite for fast in-context adaptation (p.25) — loosely consistent with our finding that the memory needs a slow learning rate early so that the gate can learn.

**Contradicts / complicates**
- The paper's thesis is that interference is fixed by a better *learning rule* (delta, DGD, self-generated values), not by partitioning the state into content-routed channels. In its taxonomy our k channels are the "Independent (head-wise)" variant (eq. 74, parallel memories combined by a learnable weighted sum) but indexed by content rather than by frequency; the paper never tests content routing, so it neither confirms nor refutes that an unsupervised router can discover streams.
- It gives no evidence that a learned forget gate discovers *boundaries*; its α_t is motivated by capacity and "weight decay", not by segmentation.

**Pitfalls the paper warns of (explicitly or implicitly)**
- Chunked adaptation lags by a chunk (p.32): any gate value computed from fast weights frozen at a chunk boundary cannot react within the chunk.
- Removing retention/weight decay hurts (Table 6), and the whole DGD derivation needs normalised keys (App. C): unnormalised Hebbian states with α = 1 grow without bound.
- "when the model is not well-trained, the higher-frequency level is on its own to learn from the context" (p.25) — the fast memory cannot rescue an under-trained slow part (our gate).
- The paper is silent on softmax-router collapse, straight-through estimators and pooled-summary gating; it uses no discrete routing at all. Nothing here about channel merges/splits.

### 5.3 Suggested training details (as specific as the paper allows)
- AdamW outer loop (as for all their models); tuned lr per model; no separate lr for the fast memory is mentioned (our "slow memory lr" recipe has no analogue in the paper).
- Initialise retention near our known decay (b_α = logit 0.95); initialise η_t small (the paper gives no value; Titans used a learnable per-token lr through a sigmoid). Meta-learn S_0.
- Normalise keys/queries (L2) before the Hebbian/delta update; keep LayerNorm after attention as we do.
- Local conv window 4 on the input (their default; our window gate uses 3).

**Claims that look overstated or unsupported**
- "Adam is the optimal associative memory" (pp.5, 51): the target P = sqrt(Σ g²) is chosen so that the closed-form solution reproduces Adam's shape; the sums are cumulative (AdaGrad-like), not EMAs, and ε/bias-correction are not derived. It is a re-description, not an optimality result.
- "in-context learning ... is not an emergent characteristic but a direct consequence of having multiple levels" (p.25): definitional.
- "Transformers are in fact linear layers with different frequency updates" (Fig. 1 caption): attention as "frequency ∞" is a stretch of Definition 2.
- NIAH: Hope's multi-key/query/value scores at 16K are 14.8 / 14.2 / 11.4 (Transformer 61.4 / 29.8 / 21.5); "best among attention-free" is true but weak, and Titans beats Hope on S-NIAH-3 at 4K (74.2 vs 73.2).
- Table 5: Hope solves parity/(aa)*/(abab)* with "parallel training ✓", but within a chunk the memory is frozen (p.32) so per-token nonlinear state tracking is impossible unless the chunk is 1; chunk size for this experiment is not stated. DeltaNet is reported at 0.0 on (aa)*/(abab)*, though Grazzi et al. 2025 (cited) show DeltaNet with negative eigenvalues handles such languages — the baseline is presumably the eigenvalue-in-[0,1] version.

## 7. Verdict

This is primarily a conceptual paper; the parts that matter to us are the rule taxonomy (§5), the self-modifying Titans update (eq. 86–93) and the CMS definition (eq. 70–71). It does **not** contain a mechanism that infers context boundaries, so it does not solve our distant-cue problem; its only data-dependent time scale is a per-token retention gate on a fast-weight matrix, the same family as our already-tried selective gate, and its multi-timescale memory (CMS) uses fixed positional periods. What it changes about what we should do next: (1) switch the channel memory from Hebbian to a (gated) delta rule with normalised keys — this gives us the provable "single channel cannot bind" control the brief asks for and sharpens the routing signal, at the cost of removing the superposition that let a single channel partially succeed at P = 4; (2) add a per-channel forget gate initialised at logit(0.95) with a learned initial state, which the paper's ablation says is worth real perplexity in its setting; (3) treat the paper's argument about the one-layer projection bottleneck as support for the per-layer residual-stream gate (or, alternatively, a context-adaptive key projection) over raw-embedding gates. For the BDH-CQ reconstruction, the paper strengthens the case that "linear correction rules on S" means the affine-in-S family S_t = A(D_t) S_{t−1} + B(D_t) with the gated delta rule as the canonical non-trivial member, and offers nothing on the latent-refinement loop. Confidence: high on the equations and taxonomy (modulo the typos listed), high that the paper has no boundary-inference mechanism, medium on the practical payoff of the delta-rule and forget-gate suggestions in our CPU-scale setting (the paper's evidence is at 760M–1.3B with unreported hyperparameters and several internal inconsistencies).
