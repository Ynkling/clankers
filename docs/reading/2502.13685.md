## 1. What the paper actually does

### 1.1 One-paragraph summary
A linear-attention / linear-RNN layer normally keeps one matrix-valued memory state M_t ∈ R^{d×d}. MoM keeps **M independent memory states plus one always-on "shared" memory**. A per-token, per-layer **router** (linear layer + softmax + top-k + renormalize) picks k of the M memories; **only those k memories are updated** by the token (each with its own K/V projections), the others are left untouched; the **read** is a router-weighted sum of the k selected memories (plus the shared memory) multiplied by a shared query. The memory update rule is pluggable; experiments use **Gated DeltaNet**. Main config: **M = 4 memories, k = 2 active, + 1 shared memory**, 24 layers, 380M (d=1024, 15B tokens) and 1.3B (d=2048, 100B tokens). Router is trained end-to-end with a **Switch-Transformer-style load-balancing auxiliary loss** (best weight 1e-3). Result: best linear model on six recall-intensive tasks (380M avg 28.16 vs Gated DeltaNet 24.78 vs Transformer++ 31.70; 1.3B avg 36.04 vs 32.30 vs 37.31), modest gains on commonsense/LongBench, and an ablation showing M separate memories beat one expanded memory of the same activated capacity.

### 1.2 Equations, in the paper's notation (copied; sub/superscripts reconstructed from the garbled layout)

**Preliminary (p.2).** Linear attention as a recurrent memory, Eq. (1)–(2):

> o_t = Σ_{i=1}^{n} φ(q_t)φ(k_i)^T v_i / Σ_{i=1}^{n} φ(q_t)φ(k_i)^T   (1)
> M_t = M_{t−1} + k_t^T v_t,   o_t = q_t M_t   (2)

"This indicates that linear attention can function as a linear recurrent layer with a matrix-valued hidden state M which we refer to as memory sate [sic] and the output is generated by querying the memory state M. This represents the ultimate compression of sequence information, condensing the entire sequence into a single memory state." (p.3). Row-vector convention: "bold lower-case letters for row vectors (e.g., q_t, k_t) ... q_t is the t-th row of Q" (p.2). The feature map φ and the denominator are dropped ("the feature map can utilize an identity function, which we omit for simplicity", p.2).

**Router, §3.2.1 (p.4).** Exact text and equations:

> "We use a router to assign inputs to different memory states. Utilizing the top-k concept, each token is routed to the top-k memories based on its importance scores. Specifically, we use a simple linear layer to generate these scores for each input token. After applying a softmax function, we select the top-k scores and normalize them."
>
> scores_t = TopK(softmax(x_t W_g)) ∈ R^k   (3)
> g_t = scores_t / Σ scores_t ∈ R^k   (4)
>
> "where x_t ∈ R^d, k is the top-k number, W_g ∈ R^{d×M} is learnable weight, g_t is the normalized importance scores of the input x_t."

So the router reads **x_t only** — the current token's input hidden vector at that layer (Figure 1 labels it "Input Hidden", p.3) — the *same* x_t that is projected to q, k, v. No recurrence, no window, no noise, no temperature, no bias. Softmax over all M logits, then top-k, then renormalize to sum to 1 over the k survivors.

**Per-memory update, §3.2.2 (p.4).**

> "After the router network, the input x_t is directed to top-k linear recurrent modules, meaning that the top-k memories are activated while the others remain inactive."
> "1. Key and Value Projections: We project the input x_t to k_t^m and v_t^m using W_k^m and W_v^m:
> k_t^m = x_t W_k^m,  v_t^m = x_t W_v^m ∈ R^d   (5)
> where W_k^m, W_v^m are learnable projection weights for kv of the m-th memory module.
> 2. Memory Update: We update the activated memory state using k_t^m, v_t^m:
> M_t^m = M_{t−1}^m + (k_t^m)^T v_t^m ∈ R^{d×d}   (6)
> The equation above represents the simplest form of memory update for clarity. Our approach is flexible and does not rely on a specific memory update mechanism. To enhance performance, we can incorporate mechanisms such as forget gates (Sun et al., 2023)."

Note what is **not** scaled: the write (k_t^m)^T v_t^m is **not multiplied by the router weight**. Routing on the write side is a hard 0/1 decision; the router weight is used only on the read side (Eq. 7).

**Table 1 "Memory Update Rules" (p.4)** — the pluggable rules ("a_t, b_t ∈ (0,1) are data-dependent scaler, a_t is data-dependent vector, and γ is a data-independent constant"):

| Method | Memory Update Rule |
|---|---|
| Linear Attn | M_t = M_{t−1} + k_t^T v_t |
| RetNet | M_t = γ M_{t−1} + k_t^T v_t |
| GLA | M_t = (a_t^T 1) M_{t−1} + k_t^T v_t |
| DeltaNet | M_t = (I − k_t^T k_t) M_{t−1} + b_t k_t^T v_t |
| G-DeltaNet | M_t = a_t (I − k_t^T k_t) M_{t−1} + b_t k_t^T v_t |
| TTT | M_t = M_{t−1} + b_t ∇l(M_{t−1}; k_t, v_t) |
| Titans | M_t = a_t M_{t−1} + b_t ∇_M l(M_{t−1}; k_t, v_t) |
| Mamba2 | M_t = a_t M_{t−1} + b_t k_t^T v_t |
| HGRN2 | M_t = (a_t^T 1) M_{t−1} + (1 − a_t)^T v_t |
| RWKV6 | M_t = a_t M_{t−1} + k_t^T v_t |
| RWKV7 | M_t = (a_t^T 1) M_{t−1} + b_t ∇l(M_{t−1}; k_t, v_t) |

(The extraction shows "(aTt 1)" = (a_t^T 1), an outer product of the per-channel decay vector with the ones vector, i.e. row-wise decay; "ktT kt" = k_t^T k_t.) **The experiments use the G-DeltaNet row**: "we employ the Gated DeltaNet (Yang et al., 2024) as the memory update mechanism in MoM" (§4.1, p.6).

**Memory mixing and read, Eq. (7)–(8) (p.4).**

> "After updating the activated memory states, we perform a weighted sum of these memory states using the importance scores obtained from Equation(4).
> M̃_t = Σ_m g_t^{(m)} M_t^m ∈ R^{d×d}   (7)
> where M_t^m is one activated memory and g_t^{(m)} is the importance score of M_t^m. We then obtain the output of the MoM by applying query vector q_t to the mixed memory M̃_t:
> o_t = q_t M̃_t ∈ R^d.   (8)
> Finally, the output of the MoM layer is computed by applying an activation function, normalization, and a linear transformation."

So the mix is a **convex combination (weights sum to 1 over the k activated memories)** of the memory *matrices*, then one query read. "Throughout the recurrent process, only a subset of memory states is activated and updated at each time step, while memory states that are not routed remain inactive and unchanged." (p.4)

**Shared memory (p.5).** Text only, **no equation**:

> "To enhance our model's ability to capture long-term dependencies, we introduce a shared memory mechanism. This shared memory has access to the entire sequence information, allowing it to effectively store and retrieve long-term information. By integrating shared memory into our model, we ensure that it can leverage the complete historical context, resulting in significant improvements in performance and robustness."

Figure 1 (p.3) shows "Shared KV Memory" with its own "KV Proj", fed by every token ("a continuously activated shared memory", caption), sitting beside Memory 1…N under the "Mixture of Memories" box before the output matmul. **How the shared memory's read is combined with the mixture (added with weight 1? included in the normalization?) is not stated anywhere in the paper.** (My recollection of the released code is that the shared memory's output is simply added to the routed mixture's output; I could not verify this from the text — treat as unverified.)

**Hardware-efficient reformulation, §3.3 (p.5–6).** The key identity, verbatim: "mixing memories before query multiplication is equivalent to multiplying each memory by the query and then mixing the results, allowing us to reuse efficient Triton-based operators from prior linear sequence models." I.e. q_t Σ_m g_t^{(m)} M_t^m = Σ_m g_t^{(m)} (q_t M_t^m). Then:

- "each token is routed to one or more memories m ∈ {1,…,M} with routing weights α_{b,t,m} ≥ 0 satisfying Σ_{m=1}^M α_{b,t,m} = 1."
- Per (batch b, memory m) the ordered index set I_{b,m} = (t_{b,m}(1), …, t_{b,m}(L_{b,m})), buckets indexed p = (b−1)M + m, cumulative boundaries s_0 = 0, s_p = Σ_{q≤p} L_q; flattened sequence x̃_{s_{p−1}+j} = x_{b, t_{b,m}(j)}, varlen representation (X̃, s).
- "queries share a projection matrix W_Q, while keys and values use memory-specific projections W_K^{(m)}, W_V^{(m)}": q̃_u = W_Q x̃_u, k̃_u = W_K^{(m)} x̃_u, ṽ_u = W_V^{(m)} x̃_u.
- "A memory-specific kernel F_m with parameters θ^{(m)} is applied independently to each segment": o_{s_{p−1}+1:s_p} = F_m(q̃, k̃, ṽ; θ^{(m)}).
- Map back: ô_{b, t_{b,m}(j), m} = o_{s_{p−1}+j}; final y_{b,t} = Σ_{m=1}^M α_{b,t,m} ô_{b,t,m}.

Figure 2 (p.5): "① Tokens are first split into groups according to memory routing results, ② then concatenated into a varlen input sequence, ③ processed by the Triton kernel, ④ the outputs are returned, ⑤ split back into their respective memories, and ⑥ finally restored to the original sequence order. For clarity, the illustration shows the top-1 routing case, and the qkv projection is omitted."

Two consequences the paper does not spell out but that follow from this implementation (my inference): (i) there is **no capacity factor and no token dropping** — every token lands in exactly k buckets of variable length L_{b,m}; (ii) because memory m's kernel sees *only its own tokens as a contiguous subsequence*, **the Gated DeltaNet decay a_t and erase (I − k^T k) act on memory m only at the steps routed to m** — a memory that receives few tokens does not decay in wall-clock time. Its clock ticks in "own tokens", not positions.

### 1.3 Where the router sits / per-layer routing
Each MoM layer has its own router over its own input hidden state: Figure 1 shows the Router inside the layer reading "Input Hidden"; §3.3 says the router consumes "input tokens x_{b,t} ∈ R^d" at the layer; Figures 5 and 9 report "Token Routing Distribution Across Layers and Memories" with 24 distinct per-layer columns L-1…L-24 — only possible if each layer routes independently. The paper never uses the words "residual stream", but x_t at layer ℓ is the layer-ℓ input (the hidden state after layer ℓ−1), so **yes, routing is per layer over the (normalized) residual-stream input of that layer**. Whether a pre-norm is applied before W_g is not stated (the model "follow[s] the training procedure described by Yang et al. (2023)" — GLA, which is pre-norm — but that is an inference).

### 1.4 Training details that matter (Appendix C, p.15; §4.1, p.6)
- Data: SlimPajama, "sampled with 100B tokens", Mistral tokenizer; 2K training context (§4.2.5).
- 380M: 24 layers, hidden 1024, 15B tokens, batch 0.5M tokens, "warmup tokens count is set to 0.25M" (almost certainly a typo for 0.25B — half a batch of warmup makes no sense), MLP "hidden ratio of our model to 3 to keep the activated parameter count approximately the same" (baselines presumably 4). 10 h on 32 A800s.
- 1.3B: 24 layers, hidden 2048, 100B tokens, batch 2M, warmup 1B tokens, ~6 days on 32 A800s. 1.3B baselines marked † "use open-source pretrained weights" from Zhang et al. 2024 (GSA).
- Optimizer: AdamW, **lr 3e-4, cosine schedule, weight decay 0.01, gradient clipping 1.0.** One learning rate for everything — **no separate router lr, no router warm-up, no router noise, no temperature, no z-loss, no initialization details of any kind.**
- Router regularizer: "auxiliary loss (following the formulation introduced in Switch Transformer Fedus et al. (2022))" (§4.2.6, p.8). The formula is not written out in MoM. From Fedus et al. (my reconstruction): L_aux = α · M · Σ_{m=1}^M f_m · P_m, with f_m = fraction of tokens dispatched to memory m, P_m = mean router softmax probability of memory m over the batch. Weight ablated at {1e-2, 5e-3, 1e-3, 0}; **1e-3 is the setting of the main model** (its numbers 28.16/41.97 are the main-table numbers).
- "we apply sparse activation only to the key and value projections, which results in a small increase in activated parameters" (p.6). Appendix G: equal-activated-parameter comparison with MLP hidden ratio 2 (both 400M activated).
- Loss curves (Fig 7) with "a fixed random seed of 42": "MoM consistently maintains the lowest loss throughout the entire training phase" (p.15–16). Figure content not recoverable from text.

## 1′. Direct answers to the paper-specific questions

**Q1. Router equations, what it reads, M and k, mixing.** Eqs. (3)–(4) above. It reads **x_t, the current token's layer-input hidden vector, and nothing else** — same x_t as the K/V projections. Softmax over M logits → keep top-k → renormalize to sum 1. **M = 4, k = 2, plus one shared memory active for every token** (§4.1, p.6: "The model is configured with four memory states, two of which are activated at each time step, along with a shared memory"). Figure 1 (p.3) labels "topk=2". Per-memory update: Eq. (5)–(6) in the simplest form; in experiments **Gated DeltaNet**: M_t = a_t (I − k_t^T k_t) M_{t−1} + b_t k_t^T v_t per activated memory, with memory-specific W_k^m, W_v^m and a **shared W_Q**. Mixing: **weighted sum of the k memory matrices with the renormalized router scores (Eq. 7, weights sum to 1), then one query read (Eq. 8)**; equivalently weighted sum of the k per-memory outputs (§3.3). The write is *not* scaled by the router score. The shared memory's combination is unspecified in the text.

**Q2. Router training, anti-collapse, collapse reports, specialization.**
- Training: end-to-end language-model loss; gradients reach W_g only through the renormalized scores g_t^{(m)} of the k *selected* memories (standard MoE top-k routing; **no straight-through estimator, no Gumbel, no noise** — Shazeer 2017's noisy top-k is cited as related work but not used; nothing about router initialization or a separate learning rate).
- Anti-collapse device: **only the Switch-Transformer load-balancing auxiliary loss**, weight 1e-3 (ablated in Table 6). No capacity factor, no expert dropout, no z-loss.
- Collapse: **yes, implicitly documented.** The text says only: "Due to the adoption of auxiliary loss, the memory segments in each layer are almost uniformly routed and activated." (p.8; Fig 5, ~300k tokens from ARC-easy, per-layer proportions 0.12–0.37 around the uniform 0.25). But **Figure 9 (p.18), "Token Routing Distribution Across Layers and Memories without Aux Loss"**, shows what happens without it. With top-2 of 4, a memory chosen by *every* token has proportion 0.50 and a dead memory 0.00. My count of the Fig 9 numbers: **21 of 24 layers have a memory at ≥ 0.48 (always selected); about 9 layers (L-3, 4, 5, 7, 10, 13, 18, 20, 23) are fully collapsed to a fixed pair** (e.g. L-5: 0.50 / 0.00 / 0.50 / 0.00; L-13: 0.01 / 0.50 / 0.49 / 0.00; L-20: 0.50 / 0.00 / 0.03 / 0.47), i.e. no routing at all — the layer degenerates into one 2×-expanded memory. Only L-1 (0.05/0.35/0.39/0.20), L-17 (0.07/0.14/0.44/0.36) and L-24 (0.17/0.18/0.42/0.23) look like genuine data-dependent routing. Despite this, the no-aux-loss model still scores 27.23 recall (vs 24.78 for GDN), which I read as: a few routing layers plus memory-specific K/V projections are already worth most of the gain. (Note the §4.2.6 text has a typo — it says Fig 9 is also "with auxiliary loss"; the Fig 9 caption says "without".)
- Specialization: **Table 5 (p.9), from "an intermediate layer"** (index not given, no quantitative token statistics): Memory 1 "Basic nouns/verbs/prepositions" → "Simplify semantic information/causal logic"; Memory 2 "Proper nouns/scientific terms" → "Specialized knowledge"; Memory 3 "Technical terms/adjectives" → "Detailed memory"; Memory 4 "Interrogative words/incomplete nouns" → "Fragmented/open information". Text: "unlike traditional MoE in FFN layers where experts often lack clear specialization and focus on syntactic punctuation (Jiang et al., 2023), MoM displays specialization among its memories." (p.8). **This is routing by token *type/content category*, not by context or by which "stream" a token belongs to.**

**Q3. Why multiple memories help** — see the quotes in §2 (Q3 block). In short: "limited memory capacity and memory interference" when one state is overwritten; Transformers avoid interference by "maintaining independent key-value caches for each token"; the hippocampal theta/gamma code "temporally separates different memory items, thus preventing interference"; and "Inputs that introduce new or orthogonal information may interfere with existing memory content when using a shared memory." **There is no formal analysis** (no capacity bound, no key-orthogonality argument, no synthetic recall experiment); the only empirical evidence for the interference claim is Table 4 (mixture > expanded single memory) and the statement "Assigning inputs specifically to different memories, combined with the use of a forget gate, proves to be a more effective approach for reducing interference than relying solely on a forget gate." (p.8).

**Q4. Results** — §1.5 above. Baselines are RetNet, HGRN2, GLA, GSA, Gated DeltaNet, Transformer++; **no Mamba2**. Sizes 380M/15B tokens and 1.3B/100B tokens. Ablations: memory count (Fig 6/8, numbers not in text), shared memory (+2.1 recall), aux-loss weight (Table 6), mixture vs expanded (Table 4), equal activated params (Table 9), hybrid with 3 attention layers (Table 8).

**Q5. Context-dependent routing, same-content-different-memory, hybrid routing, per-layer residual routing.** The paper says **nothing** about context-dependent routing, nothing about the same token needing different memories in different contexts, and nothing about "hybrid routing" (its only "hybrid" is Appendix F: interleaving Transformer layers). **It does route per layer over the layer's input hidden state** (§1.3 above; Figure 1 "Input Hidden" → "Router"; Figures 5/9 show 24 different per-layer distributions). Consequently, at layers ≥ 2 the router input is already contextualized by earlier layers' memory reads, so context-dependent routing is *possible in principle* in MoM — but the paper neither tests nor claims it, and its own specialization analysis (Table 5) shows a lexical/semantic partition.

**Q6. Efficiency, and would our soft k-channel gate be slower?** Their trick (§3.3) is: regroup tokens by memory, concatenate into a varlen sequence, run the existing single-memory Triton kernel once per bucket, scatter back, weighted-sum. Total kernel work ∝ (k + 1)·T token-steps (k routed + shared). A soft gate that puts every token into every channel means M·T token-steps, i.e. **M/k × their routed cost (2× for M=4, k=2)** — but then the regroup/scatter machinery is unnecessary: a soft gate is just **M parallel memories (heads) with gate-scaled writes and reads**, exactly standard multi-head linear attention with M heads. The paper does not discuss soft gating. One wrinkle for a soft gate with the delta rule: the erase term (I − k^T k) is quadratic in k, so "scaling the write by g" must be done through b_t (write strength β_t^{(m)} = g_t^{(m)} b_t) and a partial erase, not by scaling k. At our scale (N=256, D=32, k ≤ 16, CPU) none of this matters.

**Q7. Loose threads** — §6 below. Sparse State Expansion and Raven are **not cited** (Raven post-dates v4); the MoE and neuroscience references are listed there with IDs where the paper gives them.

## 2. Verbatim quotes that matter (with page)

Epigraph — p.1: "The enemy of memory isn't time; it's other memories." – David Eagleman

Problem statement — p.1 (abstract): "these methods typically compress the entire input sequence into a single fixed-size memory state, which leads to suboptimal performance on recall-intensive tasks."

p.1: "they face two main challenges: limited memory capacity and memory interference. When new information overwrites the single fixed-size memory state, previously stored representations may degrade, which negatively impacts its long-term memory performance on recall-intensive tasks."

p.1–2: "We argue that the strong performance of Transformer models on recall-intensive tasks arises from their ability to avoid memory interference by maintaining independent key-value caches for each token, thus offering virtually unlimited memory capacity. In contrast, linear sequence modeling relies on extreme compression, consolidating all the input information into a single fixed-size memory state ... This approach results in limited memory capacity and inherently leads to memory interference issues."

Hippocampus analogy — p.2: "Interestingly, the human brain has developed mechanisms that enable large memory capacity while reducing memory interference. Neuroscience studies show that in the hippocampus, theta oscillations (4∼8 Hz) and gamma oscillations (30∼100 Hz) work together to support a neural coding mechanism for multi-item memory (Buzsáki, 2002; Lisman & Jensen, 2013). Specifically, each theta cycle is subdivided into multiple gamma subcycles, and within each gamma subcycle, a distinct group of neurons is activated following the "E%-max" mechanism (de Almeida et al., 2009). This sequential activation temporally separates different memory items, thus preventing interference."

p.2: "MoM employs multiple independent memory states, with a router network that directs input tokens to specific memory states. The input sequence is divided into a predefined number of subsequences (phase-specific neural assemblies), which are processed in parallel and fed into the corresponding memory projections (dentate microcircuits) to generate key-value pairs. ... The final output is computed as a weighted sum of these memories, which we refer to as the mixture-of-memories. This approach expands memory capacity and eliminates memory interference".

Inputs that introduce new or orthogonal information may interfere with existing memory content when using a shared memory. Rather than discarding these inputs through gating mechanisms or overwriting the existing memory state, it may be more effective to consider alternative strategies that allow for the preservation of diverse information without interference."

## 3. Relevance to BDH-CQ reconstruction

What matches Pathway's wording:
- Pathway's "special case S_t = S_{t−1} + U_θ(D_t)" is **exactly MoM's Eq. (2)/(6)**: M_t = M_{t−1} + k_t^T v_t with D_t = (k_t, v_t). MoM calls this "the simplest form of memory update for clarity" and "the ultimate compression of sequence information".
- Pathway's general form S_t = U_θ(S_{t−1}, D_t) with "linear correction rules on S": **MoM's Table 1 is a ready-made catalogue of such rules**, all of the shape M_t = A(D_t)·M_{t−1} + B(D_t), affine in the previous state with data-dependent coefficients: scalar decay (RetNet, Mamba2, RWKV6), per-row decay (GLA, HGRN2, RWKV7), and the **delta/erase correction (I − k_t^T k_t) M_{t−1}** (DeltaNet, Gated DeltaNet). The TTT/Titans/RWKV7 rows write the same thing as a gradient step M_t = M_{t−1} + b_t ∇l(M_{t−1}; k_t, v_t), which for the squared loss l = ½‖k M − v‖² is again affine in M (it *is* the delta rule). If BDH-CQ's U_θ is a "linear correction rule" that goes beyond pure addition, the Gated DeltaNet row — a_t (I − k^T k) M_{t−1} + b_t k^T v — is the most plausible candidate in this family, and it is what MoM actually runs.
- MoM adds one structural idea Pathway's phrase does not exclude: **S may be a *collection* of states {M^1..M^M, M^shared}, with U applied only to a routed subset**, and reading = weighted sum. The identity q (Σ g_m M^m) = Σ g_m (q M^m) (p.5) is what makes a mixture of states cheap.

What does not match:
- **Nothing in MoM resembles the latent reasoning loop** H_0 = E_θ(x*, S_K), H_{r+1} = F_θ(H_r, S_K), ŷ = G_θ(H_R). MoM is a single forward pass; the memory is read once per layer and there is no iteration over a frozen S_K. MoM has no test-time compute scaling, no Sudoku/ARC-style tasks.
- MoM's state is per-head d×d matrices in a 24-layer stack; BDH's state is an N×N synaptic matrix over a sparse neuron space. MoM's "shared W_Q, memory-specific W_K/W_V" is a Transformer-style design with no Hebbian/neuron interpretation.

Net: MoM tells us what the *menu* of "linear correction rules on S" looks like and that the strongest practical member is the gated delta rule; it says nothing about the refinement loop.

## 4. Relevance to distant context cues

- **Which component carries context across distance?** Only the memory states themselves: the routed Gated DeltaNet memories (with data-dependent decay a_t, erase, write strength b_t — all learned, per token) and the always-on shared memory ("has access to the entire sequence information", p.5). The **router carries no context at all**: it is a memoryless function of the current token's layer input, with time scale zero.
- **Is the context GIVEN or INFERRED?** Inferred — there are no labels, segment ids, or boundary tokens. But what is inferred is a **token-type partition** (Table 5: function words / proper nouns / technical terms / interrogatives), not a stream or context partition. The paper offers no experiment in which a token's routing depends on something said earlier.
- **Time scale of the memories.** Governed by GDN's a_t ∈ (0,1) per token; per the varlen implementation, decay and erase on memory m happen *only at tokens routed to m*, so a seldom-used memory retains its content for long stretches of wall-clock time. This is a cheap way to get heterogeneous horizons without a separate forget-gate design: the horizon of a channel is "in its own tokens."
- **The only route to context-dependent routing in MoM is the per-layer residual input**: at layer ℓ ≥ 2, x_t already contains what layers < ℓ read from memory, so a header cue could in principle be copied into every position of its block by layer 1 and read by layer 2's router. The paper does not test this; it is exactly our untried "per-layer gate over the residual stream" idea, and MoM shows it is the default architecture at scale — but shows no evidence on whether it yields context routing.
- **How that component is trained.** Jointly with the LM loss, lr 3e-4 for everything, plus the Switch aux loss. Nothing else.

Bottom line for the header layout: MoM gives us no mechanism for the distant-cue problem beyond "stack layers and let the residual stream carry the cue"; its router is the pure content router that, in our terms, produces key splits.

## 5. Relevance to our gate — concrete, implementable

**5.1 What MoM supports in our beliefs/results**
- *Splitting the state into routed sub-memories beats one bigger memory of equal capacity* (Table 4; +1.8 recall for GDN with 106M fewer params). This is the large-scale version of "a single-channel Hebbian memory fails because the key's S values interfere; the oracle partition binds easily."
- *Routers collapse without an anti-collapse device.* Figure 9: without the aux loss, ~9/24 layers collapse to a fixed pair of memories and 21/24 have an always-selected memory. Our "two streams merge into one channel at k = S" is the same phenomenon.
- *Content-only routers specialize by token type.* Table 5. This is the generic outcome of a router that sees only x_t — i.e. our "key splits" in the header layout are what MoM's router would also do. The paper does not see this as a problem because in language, token type *is* a useful partition.
- *A shared always-on memory helps* (+2.1 recall, Table 6). We have no such channel.

**5.2 What it contradicts or qualifies**
- MoM needs **no special recipe**: one lr (3e-4) for router and everything else, no slow-memory phase, no hinge penalty, no noise, no split heuristic — just a 1e-3 Switch aux loss, and even without it the model trains (27.23 vs 28.16). This qualifies our belief that the gate needs a training recipe; but at 380M params / 15B tokens the signal-to-noise is incomparable to a 3-layer N=256 model on a synthetic task, so I would not read it as a contradiction.
- MoM's write is **hard** (unscaled, top-k), read is **soft**. Our gate is soft on both sides: score(t,s) = (x_t·x_s)(g_t·g_s)decay^{t−s}. MoM's effective pairwise weight (simplest rule) is Σ_m g_t^{(m)} · 1[s ∈ I_m] · (q_t · k_s^m). A soft write with g_s = (0.6, 0.4) still leaks 40% of a binding into the wrong channel; MoM's hard write guarantees "leaving non-activated memory states unchanged to avoid interference from current input" (Fig 1 caption). The paper's whole interference argument rests on hard writes.
- MoM reads the *current* token's own write (M_t includes k_t^T v_t before o_t = q_t M_t); ours is strictly causal. Irrelevant for the task but note when comparing equations.
- MoM gives each memory **its own key/value projections** ("unique key-value projection weights", p.15) so channels can re-encode the same token differently; our channels share x_t. Probably unnecessary at our scale, but it is a degree of freedom we have not used.

**5.3 Implementable ideas (with equations)**

(a) **Switch-style load-balancing loss instead of (or in addition to) the split heuristic.** With our soft g_t ∈ Δ^k over a batch of T tokens: P_c = (1/T) Σ_t g_t^{(c)}, f_c = (1/T) Σ_t 1[argmax g_t = c]; L_aux = α · k · Σ_c f_c P_c (Fedus et al. form, as MoM uses it); α ∈ {1e-3, 1e-2} (MoM's best 1e-3; Switch's default 1e-2). Gradient flows through P_c. This is continuous, cheap, and attacks exactly the merge failure. Caveat: uniform usage is neither necessary nor sufficient for stream routing (Fig 5 is uniform but Table 5 says it routes by token type); and in the grouped task the balanced solution and the stream solution coincide only when streams are equally frequent — fine for BindTask, not in general.

(b) **Hard top-k with renormalized softmax on the write side, soft on the read side** — MoM's Eq. (3)–(4): g_t = TopK(softmax(x_t W_g)) / Σ. For our task, top-1 write = "one channel per token", the oracle's form. Train through the selected weights only (MoM does this with no STE and it works at scale). Variant: anneal a temperature so the soft gate hardens over training; or use hard writes and soft reads separately (write gate = one-hot(argmax g_t), read gate = g_t) which keeps the gradient path through the read.

(c) **Shared always-on channel.** Add channel 0 with g_t^{(0)} ≡ 1 (not part of the softmax). In the grouped task this channel reproduces the failing single-channel memory, but it gives the model a place for everything that need not be partitioned (CTX and KEY tokens themselves) so the routed channels carry only the conflicting bindings. MoM: +2.1 recall. How to combine: add its read to the mixture read (unverified recollection of the code; the paper does not say).

(d) **Per-layer router over the residual stream** — MoM's default: x_t at layer ℓ is the layer-ℓ input, g_t^{(ℓ)} = softmax(x_t^{(ℓ)} W_g^{(ℓ)}) (one W_g per layer, d×k, no hidden layer). This is the only MoM component that can, in principle, make routing context-dependent (layer 1 copies the header into the block; layer 2 routes on it). MoM shows it is stable at 24 layers but gives no evidence it discovers context partitions.

(e) **Per-channel forget gate in the Gated DeltaNet form**: M_t^c = a_t (I − k_t^T k_t) M_{t−1}^c + b_t k_t^T v_t for the channels token t writes to, with a_t, b_t ∈ (0,1) data-dependent scalars computed from x_t by small linear maps (MoM only says "data-dependent scaler"; the exact parameterization is in Yang et al. 2412.06464, which is in our papers directory). Our current fixed decay 0.95 is the RetNet row (γ constant); a per-channel learned constant γ_c is the smallest step, a per-token a_t the next. Two warnings from our side: the delta/erase term *overwrites* a key's previous value inside a channel, which is exactly wrong for the grouped task unless routing already separates the streams — so the delta rule raises the stakes on the router; and MoM's decay acts only on routed steps, so if we want that property with soft gates use decay_c,t = decay^{g_t^{(c)}} (channel c's clock ticks in proportion to how much it is written).

(f) **Diagnostics MoM uses that we should copy**: the per-layer × per-channel token-proportion heatmap (Fig 5/9) with the 0.50/0.00 collapse signature, and a token-type table (Table 5) — in our case, a CTX/KEY/VAL × stream contingency table of g_t, which distinguishes key splits, position splits and stream splits at a glance.

**5.4 Pitfalls the paper warns of (explicitly or by its data)**
- Collapse to fixed memories without an aux loss (Fig 9). The aux-loss weight matters and is not monotonic (Table 6: 5e-3 is worse than 0).
- "Expanding the single memory" (bigger v) is the wrong fix for interference (Table 4) — but with GLA the mixture *hurt* FDA (9.90 vs 15.08), so the gain is not uniform across tasks/update rules.
- MoM's gains on recall are task-dependent: FDA remains far below the Transformer (22.98 vs 46.14 at 380M); only 3 attention layers close it (58.13). Multi-memory linear attention is not a substitute for exact retrieval.
- No STE needed for top-k routing — gradient through the selected renormalized weights suffices at scale (but note only the selected memories' logits get task gradient; the others get gradient only from the aux loss via the softmax coupling).

The claim "MoM displays specialization among its memories" rests on a qualitative table.
3. **Fig 9's collapse is undiscussed in the text** (and misdescribed by a typo as "with auxiliary loss"). ## 7. Verdict

MoM is the closest large-scale precedent for our architecture: a linear-attention memory split into routed sub-memories with a learned per-token, per-layer softmax router, plus an always-on shared memory, trained end-to-end with a Switch-style balance loss. It confirms three things we believed — separate routed memories beat one larger memory at equal capacity, routers collapse to fixed channels without an anti-collapse device (Fig 9), and a router that sees only the current token partitions by token type (our "key split") — and it offers four cheap things to try: (1) the Switch aux loss as a continuous alternative to our split heuristic, (2) hard top-1 writes with soft reads (MoM's write is unscaled and hard; the interference argument depends on it), (3) an always-on shared channel, (4) the per-layer router over the residual stream, which MoM runs by default and which remains the only place in MoM where context-dependent routing could arise. It changes nothing about the distant-cue problem: the paper never asks whether routing can depend on context, never reports it, and its own evidence (Table 5) says the router learned a lexical partition. It is irrelevant to the BDH-CQ reasoning loop but useful as a catalogue of "linear correction rules on S", with the gated delta rule as the strongest practical member. Confidence: high on what the paper says and shows (I read all 18 pages, including the unlabelled collapse in Fig 9); medium on transfer to a 3-layer, N=256 model on a synthetic task — MoM's "no special recipe needed" finding in particular may not survive the change of scale.
