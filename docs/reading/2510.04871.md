Notation dictionary (used throughout):

| HRM name | TRM name | role |
|---|---|---|
| `x = f_I(x̃)` | `x` | embedded input puzzle, shape [B, L, D]; **re-injected at every latent step** |
| `z_H` | `y` | current (embedded) proposed answer; decoded by `output_head`; carried across steps |
| `z_L` | `z` | latent "reasoning" feature; not decodable; carried across steps |
| `f_L` (4-layer net) | `net` (2-layer, shared) | updates `z` from `(x, y, z)` |
| `f_H` (4-layer net) | same `net` | updates `y` from `(y, z)` — no `x` |
| `n` | `n` | # latent (`z`) updates per recursion process: HRM 2, TRM 6 |
| `T` | `T` | # recursion processes per supervision step: HRM 2, TRM 3 |
| `N_sup` | `N_sup` | max deep-supervision steps per sample: 16 (both) |

## 1. What the paper actually does

### 1.1 Setting
Pure supervised learning on fixed-shape puzzles: input and output both have shape `[B, L]` ("when the shape differs, padding tokens can be added", p. 2), embedded to `[B, L, D]`. No autoregression, no CoT, no language. One deterministic answer per input ("Currently, recursive reasoning models such as HRM and TRM are supervised learning methods rather than generative models", p. 9). Benchmarks are exactly HRM's: Sudoku-Extreme, Maze-Hard, ARC-AGI-1, ARC-AGI-2.

### 1.2 HRM recap (as the paper presents it; Wang et al. 2025, arXiv 2506.21734)
Four learnable components: input embedding `f_I(·; θ_I)`, low-level recurrent network `f_L(·; θ_L)`, high-level recurrent network `f_H(·; θ_H)`, output head `f_O(·; θ_O)`. "Each network is a 4-layer Transformers architecture (Vaswani et al., 2017), with RMSNorm (Zhang & Sennrich, 2019), no bias (Chowdhery et al., 2023), rotary embeddings (Su et al., 2024), and SwiGLU activation function" (p. 2).

HRM forward pass with the authors' hyperparameters (n = 2 f_L steps, 1 f_H step, T = 2), copied verbatim (p. 2):

```
x   ← f_I(x̃)
z_L ← f_L(z_L + z_H + x)   # without gradients
z_L ← f_L(z_L + z_H + x)   # without gradients
z_H ← f_H(z_L + z_H)       # without gradients
z_L ← f_L(z_L + z_H + x)   # without gradients
z_L ← z_L.detach()
z_H ← z_H.detach()
z_L ← f_L(z_L + z_H + x)   # with gradients
z_H ← f_H(z_L + z_H)       # with gradients
ŷ   ← argmax(f_O(z_H))
```
"where ŷ is the predicted output answer, z_L and z_H are either initialized embeddings or the embeddings of the previous deep supervision step (after detaching them from the computational graph)" (p. 2). Note the inputs are **summed** (`z_L + z_H + x`), not concatenated. "a forward pass of HRM consists of applying 6 function evaluations, where the first 4 function evaluations are detached from the computational graph and are not back-propagated through" (p. 3).

Fixed-point justification (p. 3): "Assuming that (z_L, z_H) reaches a fixed-point (z*_L, z*_H) through recursing from both f_L and f_H,

    z*_L ≈ f_L(z*_L + z_H + x)
    z*_H ≈ f_H(z_L + z*_H),

the Implicit Function Theorem (Krantz & Parks, 2002) with the 1-step gradient approximation (Bai et al., 2019) is used to approximate the gradient by back-propagating only the last f_L and f_H steps."

Deep supervision (p. 3): the previous `(z_H, z_L)` are reused as initialization for the next forward pass; "At most N_sup = 16 supervision steps are used." Effective depth: "HRM effectively reasons over n_layers (n + 1) T N_sup = 4 ∗ (2 + 1) ∗ 2 ∗ 16 = 384 layers of effective depth" (p. 3).

ACT (p. 3): a Q-learning halting head on z_H with a halt loss and a continue loss; the continue loss needs a second full forward pass. "It is only used during training, while the full N_sup = 16 supervision steps are done at test time to maximize downstream performance. ACT greatly diminishes the time spent per example (on average spending less than 2 steps on the Sudoku-Extreme dataset rather than the full N_sup = 16 steps)" (p. 3).

HRM pseudocode, Figure 2 (p. 3), underscores restored:

```python
def hrm(z, x, n=2, T=2):  # hierarchical reasoning
    zH, zL = z
    with torch.no_grad():
        for i in range(n*T - 2):
            zL = L_net(zL, zH, x)
            if (i + 1) % T == 0:
                zH = H_net(zH, zL)
    # 1-step grad
    zL = L_net(zL, zH, x)
    zH = H_net(zH, zL)
    return (zH, zL), output_head(zH), Q_head(zH)

def ACT_halt(q, y_hat, y_true):
    target_halt = (y_hat == y_true)
    loss = 0.5 * binary_cross_entropy(q[0], target_halt)
    return loss

def ACT_continue(q, last_step):
    if last_step:
        target_continue = sigmoid(q[0])
    else:
        target_continue = sigmoid(max(q[0], q[1]))
    loss = 0.5 * binary_cross_entropy(q[1], target_continue)
    return loss

# Deep Supervision
for x_input, y_true in train_dataloader:
    z = z_init
    for step in range(N_sup):  # deep supervision
        x = input_embedding(x_input)
        z, y_pred, q = hrm(z, x)
        loss = softmax_cross_entropy(y_pred, y_true)
        # Adaptive computational time (ACT) using Q-learning
        loss += ACT_halt(q, y_pred, y_true)
        _, _, q_next = hrm(z, x)  # extra forward pass
        loss += ACT_continue(q_next, step == N_sup - 1)
        z = z.detach()
        loss.backward()
        opt.step()
        opt.zero_grad()
        if q[0] > q[1]:  # early-stopping
            break
```
(Inconsistency, my observation: with n = T = 2 this loop does 2 L-steps and 1 H-step under no-grad, i.e. 5 evaluations total, whereas the equations above list 6; `range(nT − 1)` with `% n` would reproduce the equations. Treat the equation block as authoritative.)

Prior evidence the paper leans on (p. 2): "An independent analysis on the ARC-AGI benchmark showed that deep supervision seems to be the primary driver of the performance gains (ARC Prize Foundation, 2025a). Using deep supervision doubled accuracy over single-step supervision (going from 19% to 39% accuracy), while recursive hierarchical reasoning only slightly improved accuracy over a regular model with a single forward pass (going from 35.7% to 39.0% accuracy)."

### 1.3 TRM: the exact recursion

**Full recursion process** (Sec. 4.1, p. 5), copied: "we define a full recursion process as containing n evaluations of f_L and 1 evaluation of f_H:

    z_L ← f_L(z_L + z_H + x)
    ...
    z_L ← f_L(z_L + z_H + x)
    z_H ← f_H(z_L + z_H).

Then, we simply back-propagate through the full recursion process."

In TRM's own notation (Sec. 4.3, p. 6): "since z ← f_L(x + y + z) contains x but y ← f_H(y + z) does not contains x, the task to achieve (iterating on z versus using z to update y) is directly specified by the inclusion or lack of x in the inputs." Both roles are played by **one** network. So:

- latent update, n = 6 times per recursion process: `z ← net(x + y + z)` — **x is added into the input at every one of the n steps**;
- answer update, once per recursion process: `y ← net(y + z)` — **no x**;
- T = 3 recursion processes per supervision step: the first T − 1 = 2 under `torch.no_grad()`, the last one back-propagated through all n + 1 = 7 network calls;
- N_sup = 16 supervision steps max per sample; `(y, z)` detached between supervision steps; a loss at every supervision step;
- decoding: `ŷ = argmax(output_head(y))` — only `y` is decoded, never `z`;
- halting: `q_hat = Q_head(y)`, trained with `binary_cross_entropy(q_hat, (y_hat == y_true))`; training-time early stop when `q_hat > 0` (i.e. P(correct) > 0.5). The Q-learning *continue* loss and its second forward pass are removed.
- EMA of weights with decay 0.999 (p. 11).

Per supervision step: T(n + 1) = 21 network calls, effective depth T(n + 1)·n_layers = 3·7·2 = 42 (Table 1 caption defines depth this way). Across a full 16-step solve at test time: 48 recursion processes, 336 network calls, 672 layer applications (my arithmetic; the paper only gives the HRM figure 384).

TRM pseudocode, Figure 3 (p. 5), underscores restored, otherwise verbatim:

```python
def latent_recursion(x, y, z, n=6):
    for i in range(n):  # latent reasoning
        z = net(x, y, z)
    y = net(y, z)  # refine output answer
    return y, z

def deep_recursion(x, y, z, n=6, T=3):
    # recursing T-1 times to improve y and z (no gradients needed)
    with torch.no_grad():
        for j in range(T-1):
            y, z = latent_recursion(x, y, z, n)
    # recursing once to improve y and z
    y, z = latent_recursion(x, y, z, n)
    return (y.detach(), z.detach()), output_head(y), Q_head(y)

# Deep Supervision
for x_input, y_true in train_dataloader:
    y, z = y_init, z_init
    for step in range(N_supervision):
        x = input_embedding(x_input)
        (y, z), y_hat, q_hat = deep_recursion(x, y, z)
        loss = softmax_cross_entropy(y_hat, y_true)
        loss += binary_cross_entropy(q_hat, (y_hat == y_true))
        loss.backward()
        opt.step()
        opt.zero_grad()
        if q_hat > 0:  # early-stopping
            break
```

Things the pseudocode settles: (i) `x = input_embedding(x_input)` is recomputed inside the supervision loop, so the embedding gets a gradient at every supervision step; (ii) gradient never crosses a supervision-step boundary (detach on return) nor reaches the first T − 1 recursion processes; (iii) the optimizer steps once per supervision step, so one mini-batch yields up to 16 optimizer steps; (iv) `(y_hat == y_true)` is the halting target — the paper does not say whether this is per-token or per-sequence (HRM's code uses whole-sequence correctness; my recollection, not in the paper); (v) `y_init, z_init` are "initialized embeddings" (p. 2) — whether learned or fixed is not stated.

Why T − 1 no-grad passes are legitimate (p. 5): "Through deep supervision, the models learns to take any (z_L, z_H) and improve it through a full recursion process, hopefully making z_H closer to the solution. This means that by the design of the deep supervision goal, running a few full recursion processes (even without gradients) is expected to bring us closer to the solution. We propose to run T − 1 recursion processes without gradient to improve (z_L, z_H) before running one recursion process with backpropagation."

Interpretation of the two carried states (Sec. 4.2, p. 6): "z_H is simply the current (embedded) solution. The embedding is reversed by applying the output head and rounding to the nearest token using the argmax operation. On the other hand, z_L is a latent feature that does not directly correspond to a solution". Figure 6 (p. 12) shows a tokenized `z_H` that equals the solved grid and a tokenized `z_L` that is garbage. Why exactly two: "If we were not passing the previous reasoning z, the model would forget how it got to the previous solution y (since z acts similarly as a chain-of-thought). If we were not passing the previous solution y, then the model would forget what solution it had and would be forced to store the solution y within z instead of using it for latent reasoning" (p. 6).

Note that the **two-rate schedule of HRM is retained**: n fast z-updates then one slow y-update. TRM drops the two networks, the hierarchy story and the fixed-point story — not the schedule.

### 1.4 What TRM removed/changed relative to HRM, with the ablation numbers

Table 1 (p. 5), Sudoku-Extreme, verbatim values. Depth = T(n + 1)·n_layers; NFP = forward passes per optimization step.

| Method | Acc (%) | Depth | NFP | # Params |
|---|---|---|---|---|
| HRM | 55.0 | 24 | 2 | 27M |
| **TRM (T = 3, n = 6)** | **87.4** | 42 | 1 | 5M |
| w/ ACT | 86.1 | 42 | 2 | 5M |
| w/ separate f_H, f_L | 82.4 | 42 | 1 | 10M |
| no EMA | 79.9 | 42 | 1 | 5M |
| w/ 4-layers, n = 3 | 79.5 | 48 | 1 | 10M |
| w/ self-attention | 74.7 | 42 | 1 | 7M |
| w/ T = 2, n = 2 | 73.7 | 12 | 1 | 5M |
| w/ 1-step gradient | 56.5 | 42 | 1 | 5M |

Change by change (all on Sudoku-Extreme, from Table 1 unless noted):

1. **1-step IFT gradient → full backprop through one recursion process (7 calls)**: 56.5 → 87.4. Reason: no fixed point is reached. "Most importantly, there is no guarantee that a fixed-point is reached. Deep equilibrium models normally do fixed-point iteration to solve for the fixed point z* = f(z*) (Bai et al., 2019). However, in the case of HRM, it is not iterating to the fixed-point but simply doing forward passes of f_L and f_H" (p. 4). From HRM's own n = T = 7 residual plot: "the residual for z_H is clearly well above 0 at every step", "z_L is very far from converged after one f_L evaluation at T cycles" (p. 4). Also, a DEQ-style actual fixed-point solve (TorchDEQ) made things worse: "This highlights the fact that converging to a fixed-point is not essential" (p. 11). And a compromise (gradient through only the last k = 4 of 7 steps) "did not help generalization in any way" (p. 11).
2. **Two networks → one shared network**: 82.4 → 87.4, params 10M → 5M. Reason: the two tasks are distinguished by whether `x` is in the input (quote above).
3. **4 layers (n = 3) → 2 layers (n = 6), depth held ≈ constant**: 79.5 → 87.4, params halved again. "Surprisingly, we found that adding layers decreased generalization due to overfitting" (p. 7).
4. **Q-learning ACT (halt + continue, 2 forward passes) → BCE halt loss only (1 forward pass)**: 86.1 → 87.4, "no significant difference in generalization" (p. 7). But removing learned halting entirely (stop when the solution is reached) "dropped significantly" (p. 11).
5. **Added EMA(0.999) of weights**: 79.9 → 87.4. "On small data (such as Sudoku-Extreme and Maze-Hard), HRM tends to overfit quickly and then diverge. … We find that it prevents sharp collapse" (p. 7).
6. **n = 2, T = 2 → n = 6, T = 3**: 73.7 → 87.4 (Table 1); full sweep in Table 3 below.
7. **Self-attention → MLP over the sequence axis** (Sudoku only): 74.7 → 87.4. "when focusing on tasks where L ≤ D, a linear layer is cheap, requiring only a matrix of [L, L] parameters. Taking inspiration from the MLP-Mixer (Tolstikhin et al., 2021), we can replace the self-attention layer with a multilayer perceptron (MLP) applied on the sequence length" (p. 7). Fails off-Sudoku (Table 4/5).
8. **Hierarchy / biology → reinterpretation (y, z)**: no algorithmic change by itself, but tested the number of carried features (Table 2, p. 6):

| Method | # of features | Acc (%) |
|---|---|---|
| TRM y, z (Ours) | 2 | 87.4 |
| TRM multi-scale z (one z_i per recursion step, Fig. 5) | n+1 = 7 | 77.6 |
| TRM single z (Fig. 4) | 1 | 71.9 |

### 1.5 Architecture sizes and the attention vs MLP variants
- Hidden size D = 512, 2 layers, SwiGLU, RMSNorm, no bias, RoPE (inherited from HRM; TRM-Att keeps self-attention).
- TRM-Att: 7M params on all tasks. TRM-MLP: 5M on Sudoku (L = 81), 19M on Maze and ARC (L = 900 for 30×30 grids — the [L, L] mixer is what inflates it; footnote 1, p. 8).
- Attention is not described as causal; the whole grid is visible (this is HRM's setup; the paper never mentions masking — my inference that it is bidirectional).
- Extra token: "Both HRM and TRM add an embedding of shape [0, 1, D] on Sudoku-Extreme and Maze-Hard to the input" (p. 11; "[0, 1, D]" is almost certainly a typo for a single extra token of width D — my inference, consistent with HRM's prepended "puzzle embedding"). For ARC: "each puzzle (containing 2-3 training examples and 1-2 test examples) at each data-augmentation is given a specific embedding of shape [0, 1, D]" (p. 11), trained with lr 1e-2.

### 1.6 Training details that matter (p. 11)
- AdamW, β1 = 0.9, **β2 = 0.95**, 2K-iteration lr warm-up, batch size 768, N_sup = 16, **stable-max loss** (Prieto et al., 2025, arXiv 2501.04697) "for improved stability".
- EMA 0.999 (TRM only).
- Sudoku-Extreme & Maze-Hard: 60k epochs, lr 1e-4, **weight decay 1.0**.
- ARC-AGI: 100k epochs, lr 1e-4 (**1e-2 for the embeddings**), weight decay 0.1.
- Data: Sudoku-Extreme 1K train / 423K test, "1000 shuffling (done without breaking the Sudoku rules) augmentations per data example"; Maze-Hard 1000 train / 1000 test 30×30 mazes with shortest path > 110 (Lehnert et al. 2024 generator), 8 dihedral augmentations; ARC-AGI-1 800 tasks, ARC-AGI-2 1120 tasks, plus 160 ConceptARC tasks, "1000 data augmentations (color permutation, dihedral-group, and translations transformations) per data example" (p. 8); public evaluation sets; ARC scored with "2 tries"; test-time "the most common answer out of the 1000 data augmentations is given as answer" (p. 11).
- Compute: Sudoku 1×L40S 40GB < 36 h; Maze 4×L40S < 24 h; ARC ~3 days on 4×H100 80GB. Table 3 OOMs occur at n = 12 (backprop through 13 calls × 2 layers at batch 768).

### 1.8 Failed ideas (p. 11) — all verbatim-level
- SwiGLU MoE instead of SwiGLU MLP: "generalization to decrease massively. MoEs clearly add too much unnecessary capacity, just like increasing the number of layers does."
- Gradient through only the last k of n + 1 recursions (e.g. k = 4 of 7): "did not help generalization in any way, and it made the approach more complicated."
- Removing ACT and stopping when the solution is reached: "generalization dropped significantly … the model is spending too much time on the same data samples rather than focusing on learning on a wide range of data samples."
- Weight-tying input embedding and output head: "too constraining and led to a massive generalization drop."
- TorchDEQ fixed-point iteration in place of plain recursion: slower and worse.

### 1.9 Stability, overfitting, size, test-time recursion, cost
- Instability mode: on small data HRM "tends to overfit quickly and then diverge"; EMA "prevents sharp collapse" (p. 7). Stable-max loss is used for stability; weight decay 1.0 on the small datasets.
- Size: 2 layers > 4 layers; single net > two nets; MoE hurts; "when data is too scarce and model size is large, there can be an overfitting penalty (Kaplan et al., 2020)" (p. 7); but "the question of why recursion helps so much compared to using a larger and deeper network remains to be explained; we suspect it has to do with overfitting, but we have no theory to back this explaination" (p. 9). Bai & Melas-Kyriazi (2024) also found 2 layers optimal for DEQ diffusion, but there bigger was merely equal, not worse (p. 7).
- Test-time recursion beyond training: **not tested**. "More recursions could be helpful for harder problems (we have not tested it, given our limited resources); however, increasing either T or n incurs massive slowdowns" (p. 7). Indirect evidence that running longer than trained is safe: at train time ACT halts early (HRM: "less than 2 steps" average on Sudoku) yet the full 16 supervision steps are run at test "to maximize downstream performance" (p. 3) — my inference from these two statements; TRM's own average halting step is not reported.
- Cost: 1 forward pass per optimizer step (HRM: 2); 21 network calls per supervision step, 7 with gradient; memory is the binding constraint (OOM at n = 12 on 40GB). "this memory cost is well worth its price in gold" (p. 7).

## 3. Relevance to the BDH-CQ reconstruction

BDH-CQ (per the brief): memory `S_t = U_θ(S_{t−1}, D_t)` (linear attention = special case `S_t = S_{t−1} + U_θ(D_t)`); latent reasoning `H_0 = E_θ(x*, S_K)`, `H_{r+1} = F_θ(H_r, S_K)`, `ŷ = G_θ(H_R)`.

**What matches**

| BDH-CQ | TRM counterpart | match quality |
|---|---|---|
| `H_r` | the carried pair `(y, z)`, each `[B, L, D]` (position-resolved, not pooled) | strong: a latent carried across refinement steps and decoded only at the end of each step |
| `F_θ(H_r, S_K)` | one full recursion process: `z ← net(x + y + z)` ×6, then `y ← net(y + z)`; `x` frozen | strong structurally: a learned map applied repeatedly to the latent with a frozen conditioning tensor added in at every inner step |
| `S_K` (frozen during reasoning) | `x`, the embedded puzzle (+ the one puzzle/task embedding token) | functional match only: both are the fixed conditioning re-injected at every refinement step; but x is raw input, not a memory built by writes |
| `G_θ(H_R)` | `argmax(output_head(y))` — reads only the `y` half of the state | strong; suggests BDH-CQ's G may also read a decodable sub-part of H |
| `R` | T·N_sup = 48 recursion processes (336 net calls) at test; gradient only through the last recursion process of each supervision step; 16 losses | TRM is 3-level nested where BDH-CQ writes one loop; if BDH-CQ trains with the HRM/TRM recipe, "R" hides a deep-supervision loop |
| `E_θ(x*, S_K)` | none: `H_0 = (y_init, z_init)` is input-independent; x enters via F | mismatch as written. Equivalent rewriting: `H_0 := latent_recursion(x, y_init, z_init)`, then F with x frozen |

**What does not match**
- TRM has **no S at all** — no memory state, no write/read, no decay, no "linear correction rule on S". Nothing in TRM corresponds to `S_t = U(S_{t−1}, D_t)`. The only "correction rule" is on the latent: each `net` call is a residual Transformer block (z_{i+1} = z_i + Block(z_i + y + x) in the residual sense — my inference from "Transformers architecture", the paper does not write the residual form).
- TRM's "demonstrations" are **not in context**. For ARC, the 2–3 demonstration pairs are *training examples* (the model is fit on them by gradient descent, puzzle by puzzle, with a learned per-(puzzle, augmentation) ID token at lr 1e-2); the test input is then solved conditioned on that ID token. So where BDH-CQ puts demonstrations into `S_K` by a memory update, TRM puts them into the weights and an ID embedding. There is no in-context learning in TRM.
- TRM re-injects `x` into the *latent* update only, never into the answer update. If BDH-CQ's F is TRM-like, expect `S_K` to enter the latent sub-update but maybe not the answer sub-update.

**Most plausible reconstruction (inference, medium confidence).** BDH-CQ reports exactly HRM/TRM's benchmarks (Sudoku-Extreme, ARC-AGI), postdates TRM (Aug 2026 vs Oct 2025), and uses an H_0/H_{r+1}/G notation isomorphic to HRM/TRM's z/y/output_head. The simplest consistent reading: BDH-CQ's reasoning loop is a TRM-style deep-supervised recursion in which the frozen conditioning is the synaptic state `S_K` built by the (Hebbian/learned) memory update over the demonstration tokens, probably with the query also folded in (either at E or by re-injection), trained with the HRM/TRM recipe (loss at each supervision step, detach between steps, T − 1 no-grad warm-up recursions, BCE halting, EMA). Which BDH-CQ ingredient is the Hebbian memory then becomes the question of whether `S` is *also* updated during reasoning (`S_{r+1} = U(S_r, H_r)` as a scratchpad) — TRM gives no evidence on that because its loop has no memory.

**What 97.4% on Sudoku-Extreme means.** On the HRM/TRM protocol (1K training puzzles with 1000 rule-preserving shufflings, 423K test puzzles; accuracy = fraction of test puzzles solved — the TRM paper itself just says "% Test accuracy"; that HRM counts a puzzle only if the whole grid is exact is my recollection of HRM, not stated here), the ladder is: Direct pred 0.0 → HRM default 55.0 → HRM best (T = 3, n = 6) 62.3 → TRM-Att 74.7 → TRM-MLP 87.4 → Pathway 97.4. The test set is large enough that these are precise; 87.4 → 97.4 is a cut of the failure rate from 12.6% to 2.6% (≈5×). Two facts from TRM frame it: (a) TRM's recursion sweep saturates around 84–87% (Table 3), so "TRM with more recursion" is unlikely to explain +10 points; (b) TRM's *attention* variant only reaches 74.7%, so an attention-like Hebbian architecture at 97.4% would be a 22.7-point gain over the closest TRM analogue — this points to a genuinely different ingredient (a relational/Hebbian memory over cells is a natural constraint-propagation device for Sudoku), **or** a protocol difference. Things to verify before treating 97.4 as a like-for-like win (outside this paper, my recollection): HRM's full Sudoku-Extreme pool is millions of puzzles and the 1K-train set is a subsample — if Pathway trained on more than 1K, the numbers are not comparable; whether they vote over augmentations at test time (TRM does so only for ARC); whether "accuracy" is grid-exact. For scale (again my recollection, not from this paper): Palm et al. 2018 (Recurrent Relational Networks, cited here only as a dataset source) reported ≈96–97% on the hardest 17-given Sudokus with a message-passing recurrent network trained on ~180K puzzles — i.e. mid-90s is achievable by relational recursion when data is not scarce.

## 4. Relevance to distant context cues

TRM does not face our problem at all, and it is worth being exact about why:

1. **Across sequence positions** the context carrier is bidirectional self-attention (TRM-Att) or a learned `[L, L]` mixing matrix (TRM-MLP). Both see the whole puzzle in one layer; "distance" is not an obstacle, there is no causal mask, no streaming, no Hebbian memory with interference. Time scale: the entire context (81 or 900 tokens) at once. Trained by ordinary backprop through the last recursion process (7 calls).
2. **Across refinement time** the carrier is the detached-and-carried `(y, z)` plus `x` re-injected at every latent step. Information persists across all 48 recursion processes of a solve; gradient spans only 7 network calls. The re-injection of `x` is what stops the latent from drifting away from the input over hundreds of calls — an explicit "keep the cue in front of the network at every step" design.
3. **Task/context identity is GIVEN, not inferred.** On ARC the puzzle identity is a *label*: a learned embedding token per (puzzle, augmentation), trained at 100× the base learning rate; the demonstration pairs are gradient-descent training data. On Sudoku/Maze a single shared embedding token is added. TRM never infers which "context" a token belongs to from co-occurring data. This is the exact analogue of our "5% labelled nudge → 10/10" regime, not of the label-free regime we are after.
4. The TRM-MLP result is a cautionary tale for fixed-layout synthetic tasks: a purely **positional** mixer (`[L, L]`, no content) is the *best* Sudoku solver (87.4) and a total failure where layout varies (Maze 0.0, ARC 29.6). In our header layout with fixed P and S, block membership is a deterministic function of position; a positional route can solve the write side without ever inferring stream identity. That is the same mechanism as our "position splits" pathology and the reason a single channel binds at P = 4.

Net: nothing in TRM carries a *latent* context across *causal* distance; its only inferred, carried quantity is the solution state itself, and that is carried across refinement steps, not tokens.

## 5. Relevance to our gate

What transfers is structural; everything below marked (ours) is our extrapolation, not the paper's claim.

**5.1 Carry a persistent "proposal" separately from the latent (ours, inspired by Table 2).** TRM's single clean quantitative lesson is that two carried states — a slow, decodable proposal `y` that persists unless changed, and a fast latent `z` — beat one latent (87.4 vs 71.9) and beat many latents (vs 77.6). The distant-cue problem is exactly "hold a routing proposal fixed over 2P tokens and change it at a CTX token". Recurrent-gate variant:

    h_t = tanh(W_in v_t + W_h h_{t−1} + W_p p_{t−1})          # latent; raw v_t re-injected every step (TRM's x)
    p_t = p_{t−1} + W_y h_t                                     # routing proposal, identity-persistent (TRM's y)
    g_t = softmax(p_t)

Init `W_y` small (p persists by default), `W_p` small, `p_0 = 0`; optionally `p_t = (1−σ(u·h_t)) p_{t−1} + σ(u·h_t) W_y h_t`. Caveat the paper forces on us: TRM's y persists because the *task loss through full backprop over the 7-call horizon* teaches it to; our selective gate (0/10) already had a persistence mechanism and still routed by key. TRM therefore supports the design but does not supply the missing discovery signal.

**5.2 Per-layer residual gate = TRM's recursion over layers (ours).** Map `x ↔ v_t` (raw embedding, re-injected), `z ↔ r^{(l)}_t` (residual stream entering layer l), `n ↔ 3 layers`, and use one shared gate network at every layer as TRM uses one `net`:

    g^{(l)}_t = softmax(W_g tanh(W_in v_t + W_r LN(r^{(l)}_t))),   l = 1, 2, 3, shared W_in, W_g, W_r.

Init `W_r = 0` so layer-1 behaviour equals the current token gate and the gate only gradually uses the residual (where layer-1 attention can have copied the block header). TRM's finding that a shared network copes with two roles when the inputs differ (p. 6) supports weight sharing across layers.

**5.3 Deep supervision across layers (ours).** TRM's biggest lever (and the ARC Prize analysis's: 19 → 39%) is a loss on the state at every refinement step with a shared head. For us: readout loss after each layer through the shared output head (equal weights). This gives layer-1 attention — and its gate — a direct gradient to already copy/bind, rather than relying on gradient through two more layers. Risk: forces layer 1 toward answering, which may conflict with a "copy the header" role.

**5.4 Gradient horizon.** TRM: full backprop through the 7-step horizon ≫ 1-step (87.4 vs 56.5); partial (last 4 of 7) no better than full. For our length-21 sequences we already have full BPTT, so this is not a change; it is a warning for any future long-sequence or implicit/fixed-point variant of the gate (and of a BDH-CQ-style `S_t = U(S_{t−1}, D_t)`): do not truncate or assume equilibrium; backprop through the whole short chain.

**5.5 Stability recipe (paper's, cheap to copy).** EMA 0.999 of weights for evaluation (prevents "sharp collapse" late in training — note EMA does not alter training dynamics unless used for targets, so it will not fix an unstable gate, only make evaluation robust to oscillation); AdamW β2 = 0.95; large weight decay (1.0 on Sudoku/Maze); stable-max loss (Prieto et al. 2025, "Grokking at the edge of numerical stability", arXiv 2501.04697). (ours) Prieto et al.'s thesis — softmax saturation kills gradients and causes plateaus — is a candidate explanation of our plateau-triggered-split behaviour: a gate softmax that saturates to one-hot stops learning; a temperature floor or stable-max-style gate logits is a one-line experiment. Weight decay on `W_g` pulls routing toward uniform, i.e. anti-collapse but also anti-commitment.

**5.6 Capacity.** TRM's "less is more" (2 layers > 4, single net > two, MoE "massively" worse) is a *tiny-data* finding; our data is unlimited synthetic, so overfitting is not our bottleneck and this should not be over-applied. The one transferable point: adding routed capacity (MoE) was harmful even when compute was constant.

**5.7 Task design (paper's TRM-MLP result → ours).** Make the distant-cue task layout-randomized (random P per block, random block lengths, random header position inside the block) so that a positional `[L, L]`-type solution cannot bind; otherwise single-channel/positional success is uninformative — exactly the P = 4 ambiguity we already have.

**Beliefs supported / contradicted / pitfalls.**
- Supported: re-inject the raw cue at every step; two carried states beat one or many (our multi-scale EMA gates failing is consistent with TRM's multi-scale z being worse); backprop through the full horizon; distrust fixed-point/implicit gradients; small models are fine; positional solutions win on fixed layouts (= our position-split pathology).
- Contradicted: nothing directly. Mild tension: TRM says intermediate-state supervision is the main driver, whereas our gate gets only an end-of-sequence loss.
- Pitfalls named: fixed-point assumption without convergence; extra capacity overfits; weight tying too constraining; halting that spends too long per sample hurts coverage; a positional mixer that works on one layout fails on another. No straight-through estimators anywhere in TRM (argmax is only for decoding and for the halting target; the `q_hat > 0` stop is a hard, non-differentiated decision). No pooled summaries: `y`, `z` are full `[B, L, D]`.

## 7. Verdict

TRM is the cleanest available template for the *reasoning-loop half* of BDH-CQ: a position-resolved latent `(y, z)` refined by one shared network with the fixed conditioning re-injected at every inner step, decoded from the `y` half, trained with a loss at each of up to 16 supervision steps, state detached between steps, T − 1 no-grad warm-up recursions, BCE halting, EMA, AdamW β2 = 0.95, stable-max, heavy augmentation. If Pathway followed the field, `S_K` sits where TRM's `x` sits and the memory update `U` is the part TRM has no counterpart for — so TRM tells us how F, G and the training loop most plausibly look, and nothing about U. For the distant-cue problem the paper changes little directly (its context is a given task-ID token, its attention is bidirectional), but it supports three concrete moves for our gate: a persistent routing proposal carried separately from the gate's latent, a per-layer shared gate with the raw embedding re-injected and the residual stream as the latent, and intermediate-layer supervision; plus a cheap stability kit (EMA, β2 = 0.95, stable-max/temperature floor on the gate softmax) and a task-design rule (randomize layout so positional solutions cannot bind). Confidence: high on what TRM does and its numbers; medium on the BDH-CQ mapping (structural isomorphism is strong, but E and U are unconstrained by this paper); low-to-medium that the gate ideas close the label-free gap, since TRM's own discovery signal is just the task loss through a short, fully back-propagated horizon — which we already have.
