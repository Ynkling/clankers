## 1. What the paper actually does

### 1.1 The idea
A stacked RNN (3 layers in all experiments) in which every layer except the top has a **binary boundary detector** z_t^ℓ ∈ {0,1}. Using the boundary of the layer below at the current step (z_t^{ℓ−1}) and the layer's own boundary at the previous step (z_{t−1}^ℓ), each layer picks one of three operations at each time step: **UPDATE**, **COPY**, **FLUSH**. The boundaries are latent variables learned only from the task loss (next-character NLL or handwriting MDN likelihood); no segmentation labels. Discrete variables are trained with the straight-through estimator (STE), plus a "slope annealing trick".

> "We propose for the first time an RNN model that can learn a latent hierarchical structure of a sequence without using explicit boundary information." (p. 2)

### 1.2 Equations (paper's notation; ℓ = layer, t = time)

**Eq. (1), p. 5** — the per-layer function:

    h_t^ℓ, c_t^ℓ, z_t^ℓ = f^ℓ_HM-LSTM( c_{t−1}^ℓ, h_{t−1}^ℓ, h_t^{ℓ−1}, h_{t−1}^{ℓ+1}, z_{t−1}^ℓ, z_t^{ℓ−1} )

**Eq. (2), p. 5** — cell update, selected by the two boundary states *(⊙ restored; the extraction printed "ft ct−1 + it gt")*:

    c_t^ℓ = f_t^ℓ ⊙ c_{t−1}^ℓ + i_t^ℓ ⊙ g_t^ℓ    if z_{t−1}^ℓ = 0 and z_t^{ℓ−1} = 1   (UPDATE)
    c_t^ℓ = c_{t−1}^ℓ                              if z_{t−1}^ℓ = 0 and z_t^{ℓ−1} = 0   (COPY)
    c_t^ℓ = i_t^ℓ ⊙ g_t^ℓ                          if z_{t−1}^ℓ = 1                       (FLUSH)

**Eq. (3), p. 5** — hidden state:

    h_t^ℓ = h_{t−1}^ℓ              if COPY,
    h_t^ℓ = o_t^ℓ ⊙ tanh(c_t^ℓ)    otherwise.

> "Here, (f, i, o) are forget, input, output gates, and g is a cell proposal vector. Note that unlike the LSTM, it is not necessary to compute these gates and cell proposal values at every time step. For example, in the case of the COPY operation, we do not need to compute any of these values and thus can save computations." (p. 5)

**Eq. (4), p. 5** — gates, proposal, and the boundary pre-activation come from ONE affine pre-activation *(reconstructed from the scattered column vector)*:

    [ f_t^ℓ ; i_t^ℓ ; o_t^ℓ ; g_t^ℓ ; z̃_t^ℓ ] = [ sigm ; sigm ; sigm ; tanh ; hard sigm ] f_slice( s_t^{recurrent(ℓ)} + s_t^{top-down(ℓ)} + s_t^{bottom-up(ℓ)} + b^{(ℓ)} )

**Eqs. (5)–(7), p. 5** — the three input streams:

    s_t^{recurrent(ℓ)} = U_ℓ^ℓ h_{t−1}^ℓ                       (5)
    s_t^{top-down(ℓ)}  = z_{t−1}^ℓ · U_{ℓ+1}^ℓ h_{t−1}^{ℓ+1}   (6)
    s_t^{bottom-up(ℓ)} = z_t^{ℓ−1} · W_{ℓ−1}^ℓ h_t^{ℓ−1}       (7)

> "Here, we use W_i^j ∈ R^{(4dim(h^ℓ)+1)×dim(h^{ℓ−1})}, U_i^j ∈ R^{(4dim(h^ℓ)+1)×dim(h^ℓ)} to denote state transition parameters from layer i to layer j, and b ∈ R^{4dim(h^ℓ)+1} is a bias term." (p. 5)

The "+1" row is the boundary detector: **z̃_t^ℓ is a scalar per layer per step**, produced by the same weight matrices as the LSTM gates.

> Footnote 2 (p. 5): "z̃_t^ℓ can also be implemented as a function of h_t^ℓ, e.g., z̃_t^ℓ = hard sigm(U h_t^ℓ)."

Boundary conditions (p. 6): "In the last layer L, the top-down connection is ignored, and we use h_t^0 = x_t. Since the input should not be omitted, we set z_t^0 = 1 for all t. Also, we do not use the boundary detector for the last layer."

Hard sigmoid (p. 6): **hard sigm(x) = max(0, min(1, (a·x + 1)/2))** "with a being the slope variable."

**Eqs. (8)–(9), p. 6** — binarization:

    z_t^ℓ = f_bound( z̃_t^ℓ )                                  (8)
    z_t^ℓ = 1 if z̃_t^ℓ > 0.5 ; 0 otherwise   (deterministic step function)   (9)
    or   z_t^ℓ ~ Bernoulli( z̃_t^ℓ )          (sampling variant)

**Output module, Eqs. (11)–(12), p. 7** — gated combination of all layers' states (L = 3), feeding a 2-layer feedforward output module (output-embedding layer + softmax):

    g_t^ℓ = sigm( w^ℓ [h_t^1 ; … ; h_t^L] ),   w^ℓ ∈ R^{Σ_ℓ dim(h^ℓ)}     (11)
    h_t^e = ReLU( Σ_{ℓ=1}^{L} g_t^ℓ W_ℓ^e h_t^ℓ )                             (12)

Each g_t^ℓ is a **scalar** gate per layer per step, computed from the concatenation of all layers' hidden states ("In order to adaptively control the importance of each layer at each time step", p. 7). Input embedding: 128-dim, "without using any non-linearity" (p. 7). Loss, Eq. (10), p. 7: min_θ −(1/N) Σ_n Σ_t log p(x_t^n | x_{<t}^n; θ).

### 1.3 Mechanics of the three operations (what the equations imply, step by step)
Within a time step, layers are evaluated bottom-up (layer ℓ at time t uses h_t^{ℓ−1}, Eq. 7); top-down uses the previous step (h_{t−1}^{ℓ+1}, Eq. 6), so there is no cycle.

- **COPY** (z_{t−1}^ℓ = 0 and z_t^{ℓ−1} = 0): "(c_t^ℓ, h_t^ℓ) ← (c_{t−1}^ℓ, h_{t−1}^ℓ) … implements the observation that an upper layer should keep its state unchanged until it receives the summarized input from the lower layer." (p. 5). No gates are computed. *[inference]* Hence z̃_t^ℓ is not computed during COPY either ("we do not need to compute any of these values"), so z_t^ℓ = 0 whenever the layer copies — a level-ℓ segment can only end at a step where a level-(ℓ−1) segment ends; the hierarchy is nested by construction. Forward and backward, COPY is the identity: the latch is lossless in both directions.
- **UPDATE** (z_{t−1}^ℓ = 0 and z_t^{ℓ−1} = 1): ordinary LSTM cell update, but its bottom-up input is the lower layer's state *at the boundary step* (Eq. 7 with z_t^{ℓ−1} = 1). "the UPDATE operation is executed sparsely unlike the standard RNNs where it is executed at every time step" (p. 5). Note the upper layer's absorption of the summary is **gated/leaky** (forget gate f), not a hard overwrite.
- **FLUSH** (z_{t−1}^ℓ = 1, regardless of z_t^{ℓ−1}): happens in layer ℓ at the step *after* its detector fired. "The FLUSH operation consists of two sub-operations: (a) EJECT to pass the current state to the upper layer and then (b) RESET to reinitialize the state before starting to read a new segment. This operation implicitly forces the upper layer to absorb the summary information of the lower layer segment, because otherwise it will be lost. Note that the FLUSH operation is a hard reset in the sense that it completely erases all the previous states of the same layer, which is different from the soft reset or soft forget operation in the GRU or LSTM." (p. 5). Reading the equations: EJECT is realized at step t by the layer above's bottom-up gate (Eq. 7 with z_t^ℓ = 1, so layer ℓ+1 UPDATEs or FLUSHes at the same step t); RESET is realized at step t+1 by c_{t+1}^ℓ = i ⊙ g (no f ⊙ c_t term). *[inference]* The reset erases the **cell** carry-over, but Eq. 5 is ungated, so h_t^ℓ (the ejected summary) still enters the gates and proposal of the flush step through U_ℓ^ℓ — "completely erases all the previous states" is slightly stronger than the equations.
- **Top-down re-initialization**: "the HM-LSTM has a top-down connection from (ℓ + 1) to ℓ, which is allowed to be activated only if a boundary is detected at the previous time step of the layer ℓ (see Eq. 6). This makes the layer ℓ to be initialized with more long-term information after the boundary is detected and execute the FLUSH operation. In addition, the input from the lower layer (ℓ − 1) becomes effective only when a boundary is detected at the current time step in the layer (ℓ − 1) due to the binary gate z_t^{ℓ−1}." (p. 6). So the long-term context is injected into the lower layer **only at flush steps**, not continuously; within a segment the lower layer carries it by its own LSTM recurrence.
- Layer 1 never copies (z_t^0 = 1): "the color of ‖h^1‖ changes quickly (at every time step) because there is no COPY operation in the first layer" (p. 9).

### 1.4 Boundary detector: what it sees
From Eqs. 4–7: z̃_t^ℓ is a linear function of (i) the layer's own previous hidden state h_{t−1}^ℓ (recurrent, ungated), (ii) the lower layer's current output h_t^{ℓ−1}, gated by z_t^{ℓ−1} — for ℓ = 1 this is the raw input x_t and the gate is always 1 — and (iii) the upper layer's previous state h_{t−1}^{ℓ+1}, only when z_{t−1}^ℓ = 1. So it sees **both input and state**, and the detector of the first layer sees the current token directly and ungated. The footnote-2 alternative makes it a function of the already-updated h_t^ℓ instead. The detector is evaluated **before** the state update (it uses h_{t−1}), i.e. "is this step the end of my segment, given what I have accumulated and the token arriving now".

### 1.5 Training the discrete variable (Sec. 3.3, p. 6)
> "Among a few methods for training a neural network with discrete variables such as the REINFORCE (Williams, 1992; Mnih & Gregor, 2014) and the straight-through estimator (Hinton, 2012; Bengio et al., 2013), we use the straight-through estimator to train our model. The straight-through estimator is a biased estimator because the non-differentiable function used in the forward pass (i.e., the step function in our case) is replaced by a differentiable function during the backward pass (i.e., the hard sigmoid function in our case). The straight-through estimator, however, is much simpler and often works more efficiently in practice than other unbiased but high-variance estimators such as the REINFORCE. The straight-through estimator has also been used in Courbariaux et al. (2016) and Vezhnevets et al. (2016)."

So: forward z = step(z̃ > 0.5) with z̃ = hard sigm(u); backward, the step is treated as identity, so ∂z/∂u := ∂ hard sigm(u)/∂u = (a/2)·1[|u| < 1/a]. *[inference from the hard-sigm definition + Eq. 9]* In the deterministic Step-Fn. mode the forward decision does not depend on a at all (hard sigm(u) > 0.5 ⟺ u > 0), so **slope annealing only changes the backward pass**: the surrogate gradient becomes a/2 on a band |u| < 1/a that shrinks as a grows (total gradient mass ∫ = 1 is conserved). Outside the band the gradient is exactly zero — a token whose pre-activation is confidently positive or negative gets no learning signal. In the "Soft" variant (z = z̃, no discretization) and the "Sampling" variant (z ~ Bernoulli(z̃)), a also changes the forward pass. The paper does not spell out how the case split in Eqs. 2–3 is made differentiable; *[inference]* implementations write it as arithmetic mixing with z and (1 − z), and in any case the multiplicative gates in Eqs. 6–7 give z a direct gradient path.

**Slope annealing trick** (p. 6): "The idea is to reduce the discrepancy between the two functions used during the forward pass and the backward pass. That is, by gradually increasing the slope a of the hard sigmoid function, we make the hard sigmoid be close to the step function. Note that starting with a high slope value from the beginning can make the training difficult while it is more applicable later when the model parameters become more stable. In our experiments, starting from slope a = 1, we slowly increase the slope until it reaches a threshold with an appropriate scheduling."
- PTB schedule (p. 8): **a = min(5, 1 + 0.04 · N_epoch)**; IAM-OnDB schedule (p. 10): **a = min(3, 1 + 0.004 · N_epoch)**. The text says "where N_epoch is the maximum number of epochs" (p. 8), which read literally makes a constant; *[inference]* it must mean the current epoch index (a reaches 5 at epoch 100 on PTB, 3 at epoch 500 on IAM-OnDB).
- "For the remaining tasks [Text8, enwik8], we fixed the hard boundary decision using the step function without slope annealing due to the difficulty of finding a good annealing schedule on large-scale datasets." (p. 8)

**Optimization details that matter** (pp. 7–8, 10):
- Adam; initial lr **0.002** (PTB), **0.001** (Text8, enwik8), **0.0003** (IAM-OnDB). "We divide the learning rate by a factor of 50 when the validation negative log-likelihood stopped decreasing." "The norm of the gradient is clipped with a threshold of 1." Layer normalization (Ba et al. 2016) on all their models ("LayerNorm HM-LSTM").
- Truncated BPTT: PTB mini-batch 64 × length 100, "The last hidden state of a sequence is used to initialize the hidden state of the next sequence to approximate the full backpropagation." Text8/enwik8 mini-batch 128; IAM-OnDB mini-batch 32.
- Sizes: PTB 512 units/layer and 512 output embedding; Text8/enwik8 1024 units/layer, 2048 output embedding; IAM-OnDB 400 units/layer and output embedding; 3 HM-LSTM layers everywhere; input embedding 128-d linear.
- **Not stated anywhere**: weight or bias initialization (including the boundary-detector bias), dropout, any regularizer or constraint on boundary frequency, any curriculum, any failure/restart statistics. The only statement about boundary frequency is the implicit reward/penalty argument quoted in §2 below.

## 2. Verbatim quotes that matter

- Lossless hold vs. leaky integration (p. 2): "The COPY operation simply copies the cell and hidden states of the previous time step. Unlike the leaky integration of the LSTM or the Gated Recurrent Unit (GRU) (Cho et al., 2014), the COPY operation retains the whole states without any loss of information. The FLUSH operation is executed when a boundary is detected, where it first ejects the summarized representation of the current segment to the upper layer and then reinitializes the states to start processing the next segment."
- Why LSTM memory is bounded (p. 3): "in practice, it is still limited to a few hundred time steps due to the leaky integration by which the contents to memorize for a long-term is gradually diluted at every time step."
- Given vs. inferred boundaries (p. 2): "While this is trivial if the hierarchical boundary structure is provided (Sordoni et al., 2015), it has been a challenge for an RNN to discover the latent hierarchical structure in temporal data without explicit boundary information."
- Fixed timescales don't fit variable segments (p. 4): "different words have different lengths, so a fixed hierarchy would not update its upper-level units in synchrony with the natural boundaries in the data."
- Clockwork RNN (p. 3): "In the CW-RNN, hidden units are partitioned into several modules, and different timescales are assigned to the modules such that a module i updates its hidden units at every 2^(i−1)-th time step. … However, finding proper timescales in the CW-RNN remains as a challenge whereas our model learns the intrinsic timescales from the data."
- Soft gating is not enough (p. 3): "In the biscale RNNs (Chung et al., 2016), the authors proposed to model layer-wise timescales adaptively by having additional gating units, however this approach still relies on the soft gating mechanism like LSTMs."
- LSTM's timescales are not hierarchical (p. 3): "LSTMs (Hochreiter & Schmidhuber, 1997) employ the multiscale update concept, where the hidden units have different forget and update rates and thus can operate with different timescales. However, unlike our model, these timescales are not organized hierarchically."
- Schmidhuber's chunkers (p. 2): "In Schmidhuber (1992), the author shows a model that can self-organize a hierarchical multiscale structure." and (p. 2) timescales "as dynamic variables that can be learned from the data (Schmidhuber, 1991; 1992; Chung et al., 2015; 2016)".
- Zoneout relation (p. 3): "In Zoneout, an identity transformation is randomly applied to each hidden unit at each time step according to a Bernoulli distribution. This results in occasional copy operations of the previous hidden states. … our model learns (a) to dynamically determine when to copy from the context inputs and (b) to discover the hierarchical multiscale structure and representation."
- What the detector learns (p. 4): "A key element of our model is the introduction of a parametrized boundary detector, which outputs a binary value, in each layer of a stacked RNN, and learns when a segment should end in such a way to optimize the overall target objective."
- Operation selection (p. 5): "The selection is determined by (1) the boundary state of the current time step in the layer below z_t^{ℓ−1} and (2) the boundary state of the previous time step in the same layer z_{t−1}^ℓ."
- The HRNN ideal (p. 4): "Note that the hidden states of the W2P-RNN remains unchanged while all the characters of a word are processed by the C2W-RNN. When the C2W-RNN starts to process the next word, its hidden states are reinitialized using the latest hidden states of the W2P-RNN, which contain summarized representation of all the words that have been processed by that time step, in that phrase."
- No boundary regularizer; implicit penalty (p. 9): "Another remarkable point is the fact that we do not pose any constraint on the number of boundaries that the model can fire up. The model, however, learns that it is more beneficial to delay the information ejection to some extent. This is somewhat counterintuitive because it might look more beneficial to feed the fresh update to the upper layers at every time step without any delay. We conjecture the reason that the model works in this way is due to the FLUSH operation that poses an implicit constraint on the frequency of boundary detection, because it contains both a reward (feeding fresh information to upper layers) and a penalty (erasing accumulated information). The model finds an optimal balance between the reward and the penalty."
- Boundaries track surprise, not just words (p. 9): "Note that 'tele' is a prefix after which a various number of postfixes can follow. From these, it seems that the model uses to some extent the concept of surprise to learn the boundary." and "Although interpretation of the second layer boundaries is not as apparent as the first layer boundaries, it seems to segment at reasonable semantic / syntactic boundaries".
- COPY visible in the norms (p. 9): "As we expect, we can see that there is no change in the norm value within segments due to the COPY operation."
- Interpretability (p. 9): "we can substitute the states of z_t^1 and z_{t−1}^2 into Eq. 2 and infer which operation among the UPDATE, COPY and FLUSH was applied to the second layer at time step t."
- Annealing is fragile at scale (p. 8): "due to the difficulty of finding a good annealing schedule on large-scale datasets."
- Hard beats soft, by a little (p. 8): "Note that the HM-LSTM using the step function for the hard boundary decision outperforms the others using either sampling or soft boundary decision (i.e., hard sigmoid)."
- Abstract (p. 1): "We show some evidence that the proposed model can discover underlying hierarchical structure in the sequences without using explicit boundary information."

## 3. Relevance to BDH-CQ reconstruction

Low direct relevance; one structural point.

- HM-LSTM's per-layer state (c^ℓ, h^ℓ) evolves as a **data-dependent choice among three update maps**: identity (COPY), gated LSTM correction (UPDATE), reset-and-write (FLUSH). In Pathway's notation this is the general form S_t = U_θ(S_{t−1}, D_t), where U_θ is piecewise and selected by binary variables that are themselves functions of (S_{t−1}, D_t). It is **not** the linear-correction special case S_t = S_{t−1} + U_θ(D_t): COPY is the degenerate U(D_t) = 0; UPDATE is multiplicative in S_{t−1} through the forget gate (S_t = f ⊙ S_{t−1} + i ⊙ g, additive only if f ≡ 1); FLUSH discards S_{t−1} entirely, which no additive rule can express. So HM-RNN does not match the wording "linear correction rules on S" and nothing in it is a linear-attention outer-product memory.
- There is **no latent refinement loop** (nothing like H_{r+1} = F_θ(H_r, S_K)); inference is a single causal pass, and no reasoning-style task (Sudoku, ARC) appears.
- The one thing worth carrying over *[inference]*: if BDH-CQ's U_θ is anything beyond linear attention, the most natural non-proprietary ingredients are exactly the ones HM-RNN names — a learned, event-driven "when to update the slow state" decision (hard or soft), a reset, and a top-down re-initialization — and HM-RNN is the canonical reference for training such hard decisions with the straight-through estimator. That is a plausibility argument, not evidence about what Pathway did.

## 4. Relevance to distant context cues

**Which component carries context across distance.** The upper layers' states (c^{ℓ+1}, h^{ℓ+1}). Between boundaries from below they execute COPY, which is an exact, lossless hold ("retains the whole states without any loss of information", p. 2; flat ‖h^2‖, ‖h^3‖ in Fig. 4). The context is re-injected downward only at the lower layer's flush step through the top-down term z_{t−1}^ℓ U_{ℓ+1}^ℓ h_{t−1}^{ℓ+1} (Eq. 6); between flushes, the lower layer carries whatever it needs by its own LSTM recurrence.

**Time scale.** Not fixed: it equals the learned segment length, which is data-dependent and in principle unbounded. Empirically on PTB (p. 10): layer 2 updates 56 times in 270 characters (≈ 1 hold per 5 chars, word-like), layer 3 9 times (≈ 1 per 30 chars, phrase-like). Distances of 8–16 tokens (our 2P) are well inside what layer 2 holds for.

**Given or inferred?** Inferred. The boundaries are latent binary variables trained only from the next-step likelihood (Eq. 10) — "without using explicit boundary information" (p. 1), "we do not pose any constraint on the number of boundaries" (p. 9). The paper contrasts this with the HRNNs of Sordoni et al. 2015 / Ling et al. 2015 where boundaries are given ("trivial if the hierarchical boundary structure is provided", p. 2) and with Fernández et al. 2007 / Kong et al. 2015 where segment labels supervise the structure (p. 3). There is no auxiliary loss, no entropy bonus, no firing-rate target.

**How the component is trained.** The detector pre-activation is a row of the layer's gate matrices (Eq. 4), so the same STE gradient that trains the LSTM trains the detector. Gradient reaches z through the multiplicative gates in Eqs. 6–7 and the case split in Eqs. 2–3 (identity-through-step, hard-sigmoid derivative), with slope annealing a: 1 → 5 (PTB) or 1 → 3 (handwriting). Discreteness choice: Step Fn. 1.25 vs Sampling 1.27 vs Soft 1.27 BPC on PTB; the gain from hardness is small but consistent in their hands.

**Important caveats for us** *[partly inference]*:
- The detector marks segment **ends**, and the summary ejected upward is the lower layer's state at the boundary step (including the token arriving then). For a header-first layout the header token is a start marker; firing at the header ejects "old block + header" upward. See §5 for how to invert this.
- The dense per-character loss on 100M-character corpora is what lets boundaries emerge; nothing in the paper speaks to a sparse, delayed loss like our end-of-sequence queries.
- Discovered boundaries were only approximately linguistic (fire inside words; "surprise"-driven). We should not expect a label-free detector to fire *only* at CTX tokens unless the loss makes every other firing costly.

## 5. Relevance to our gate

### 5.1 What the paper says about our existing results
- **Fading-memory (multi-scale EMA) gates, 0/10 on the header layout** — predicted by the paper's central critique: leaky integration dilutes "the contents to memorize for a long-term … gradually … at every time step" (p. 3). An EMA of embeddings over a block mixes the one header token with 2P key/value tokens, so the gate input is dominated by key identity → exactly the "key splits" we observe. The paper's remedy is a hard, lossless hold.
- **Recurrent gate (tanh RNN) failing and counting positions** — the paper's position is that soft gating "still relies on the soft gating mechanism like LSTMs" (p. 3, on biscale RNNs) and that fixed timescales (clockwork) "would not update … in synchrony with the natural boundaries" (p. 4). Caveat *[inference]*: in our header layout block length is fixed (2P+1), the sequence starts at a block boundary, so position mod (2P+1) = 0 *does* identify headers — a clockwork/position-counting gate could in principle solve it. If we want to test inferred (not counted) context, randomize P per block.
- **Window gate (LOCAL3), 2/10 by key splits** — the paper's bottom-up gate z_t^{ℓ−1} W h_t^{ℓ−1} is a width-1 conv gated by a learned binary event; its upper layer is a width-∞ hold. LOCAL3 is the former without the latter.
- **"Soft" vs hard** — on PTB the non-discretized boundary (Soft, 1.27) matched Bernoulli sampling and was 0.02–0.03 BPC worse than the step function (1.25/1.24). Supports trying binary latching, but the paper's own evidence that hardness matters is modest.

### 5.2 Concrete design: a boundary-latched context register in front of the gate
Template = HM-LSTM collapsed to one slow level, with roles inverted so the *register* is what gets hard-reset to the new header (FLUSH-write) and otherwise held (COPY). Everything below uses only mechanisms from the paper unless marked.

    u_t  = w_z · v_t + b_z            (+ optional U_z r_{t−1}: paper's detector also sees its own previous state, Eq. 5)
    z̃_t = max(0, min(1, (a·u_t + 1)/2))                      (paper's hard sigm, p. 6)
    z_t  = 1[z̃_t > 0.5]  forward (= 1[u_t > 0]);   ∂z_t/∂u_t := ∂z̃_t/∂u_t = (a/2)·1[|u_t| < 1/a]  backward (STE)
    r_t  = z_t · (W_r v_t) + (1 − z_t) · r_{t−1},   r_0 = 0   (FLUSH-write at a boundary; COPY otherwise; d_r ≈ 16–32)
    h_t  = tanh( W_in Σ_{j<3} w_j ⊙ v_{t−j} + W_r' r_t )      (fuse with LOCAL3 so the grouped layout still works)
    g_t  = softmax( W_g h_t )

- v_t is the raw embedding, as in our gates; the paper's first-layer detector likewise reads x_t directly and ungated (z_t^0 = 1), which is what makes a single header token detectable: a CTX token is a linear class in embedding space and one weight row w_z can fire on it. In HM-RNN terms, the header is the *end* of the previous block; firing there is fine causally.
- Why a FLUSH-write rather than the paper's UPDATE for the register *[inference]*: the paper's upper layer absorbs summaries with a forget gate (f ⊙ c_{t−1} + i ⊙ g), which is appropriate for accumulating a phrase from words; our register must hold a single identity and must not leak the previous block's stream, so use the reset form i ⊙ g (here simply W_r v_t). A gated variant r_t = z_t ⊙ (f ⊙ r_{t−1} + i ⊙ g) + (1 − z_t) ⊙ r_{t−1} is the faithful UPDATE if we later want the register to accumulate.
- Gradient path *[inference]*: loss at the query → write-gate at V_{i,s} → g_V → r_V = r_header through (1 − z) = 1 holds (identity, no decay — unlike EMA, where the header's gradient is attenuated by decay^{2P}) → z_header via the STE band and, for inner K/V tokens, ∂L/∂z_t = (W_r v_t − r_{t−1}) · ∂L/∂r_t, which pushes z down at K/V tokens exactly when latching the key would change the routing for the worse. This is the mechanism by which "key splits" get penalized and "stream splits" rewarded — but only if the loss actually prefers stream routing (see §5.4).
- Reading the register "for the next 2P tokens" is automatic: r_t is constant across the block as long as no inner token fires.

### 5.3 Training recipe, as specific as the paper allows
- Optimizer: Adam; the paper's lr 0.002 → ÷50 on validation plateau; **gradient-norm clipping at 1**; LayerNorm. Keep our slow-memory recipe (gate 1e-3, rest 1e-4 early); the paper has no equivalent of per-module lr.
- Discretization: use the **step function forward** (their best), not Bernoulli sampling (1.27) or a soft gate (1.27). Keep the paper's Soft variant (z = z̃) as a sanity baseline — it is essentially a hard-sigmoid version of our existing soft gates.
- Slope annealing: a = 1 → 5, linear over training (PTB: +0.04 per epoch to a cap of 5; handwriting: +0.004 per epoch to a cap of 3). Our analog: map "epoch" to a fraction of the update budget and reach the cap around the last third; anneal only once the detector's firing pattern has stabilized ("starting with a high slope value from the beginning can make the training difficult", p. 6). They themselves could not find a schedule at scale and dropped it for Text8/enwik8 — treat it as optional polish (+0.01 BPC, +30 nats on handwriting), not as the thing that makes boundaries appear.
- Initialization *[the paper gives none; inference]*: the STE gradient is exactly zero when |u_t| ≥ 1/a, so initialize so that u_t for all tokens lies inside the band (a = 1 → |u| < 1): b_z = 0, small w_z, LayerNorm'd inputs. If we want a prior of rare boundaries (ideal firing rate 1/(2P+1) ≈ 11% at P=4, 6% at P=8), bias b_z slightly negative but keep |b_z| < 1. Do not initialize confidently in either direction: a detector that starts at u ≪ −1 for every token can never recover (dead STE), which is the always-0 collapse, and u ≫ 1 is the always-1 collapse that reduces the register to the window gate.
- Collapse control: the paper has **no explicit mechanism**; it relies on FLUSH's "reward … and a penalty (erasing accumulated information)" (p. 9). In our register that penalty exists against firing at K/V tokens (it overwrites the header) but **there is no penalty against always-0** (register never written → constant gate → single channel) and the always-1 failure mode is precisely the window gate. Since at P=4, S=2 a single channel also binds (3/10, 7/10 with slow memory), the loss sits on a plateau where z does not matter. Outside-the-paper remedies if needed: a firing-rate regularizer λ·(mean_t z_t − ρ)² or a per-update budget term λ Σ_t z_t (the Skip-RNN style penalty, see §6), or our existing hinge/split tricks applied to the detector.

### 5.4 What the paper does not solve for us
- The discovery problem is the same as ours: hard structure learned from the loss alone. HM-RNN succeeded with a dense loss and ~10^8 training positions; our signal is a handful of queries per sequence. The 5%-labelled nudge that gets us 10/10 has an exact analog here — supervising z at CTX tokens for a fraction of sequences — and the paper's HRNN discussion ("trivial if the hierarchical boundary structure is provided", p. 2) is a reminder that the gap between given and inferred boundaries is the whole problem, not an implementation detail.
- Before any of this is informative, the task must be one a single channel provably cannot bind with a budget the oracle meets (the brief already says so). Randomizing block length per block (so counting fails) and raising S·P until single-channel interference is certain would make a register solution falsifiable.

### 5.5 Other transferable pieces
- **Per-layer / residual-stream gate**: Eq. 11 is a scalar gate per layer computed from the concatenation of *all* layers' states, g_t^ℓ = sigm(w^ℓ [h_t^1; …; h_t^L]); Eq. 12 mixes layer outputs with it. That is the paper's version of a gate reading the whole residual stack. Their top-down term (Eq. 6) is the paper's version of "copy the block's context into the lower layer", but it fires only at flush steps, not at every position — our per-layer-attention idea is more continuous than anything here.
- **Forget gate per channel**: the paper's slow layers do not forget at all (COPY) and forget completely at FLUSH; a learned per-channel forget is between the two. The paper's argument is that for *holding* a context across a segment, exact hold + occasional hard reset beats any leaky rate.
- **Two-level register** *[inference]*: a level-1 detector on K/V pairs and a level-2 detector on headers would mirror HM-RNN's nested boundaries (z^2 can only fire when z^1 fires); probably unnecessary for our task but it is the faithful multi-scale version.
- **Interpretability**: with hard z we can read off, per token, whether the register was written or held (p. 9's "substitute the states … into Eq. 2") — a much cleaner diagnostic than inspecting softmax gate entropies for position vs key vs stream splits.

## 6. Loose threads

- **No appendix, no code, no init details, no boundary statistics beyond one 270-character excerpt.** The task's requests for boundary-bias initialization and anti-collapse tricks cannot be answered from the text: none are stated. The only "trick" is slope annealing; the only robustness statement is the reward/penalty conjecture (p. 9).
- **"N_epoch is the maximum number of epochs" (p. 8)** — literal reading makes the slope constant; must mean the current epoch index.
- **Footnote 2 (p. 5)**: the detector can alternatively be a function of the already-updated state, z̃_t^ℓ = hard sigm(U h_t^ℓ). Useful if we want the register's write decision to depend on the fused window state h_t rather than the raw token.
- **FLUSH's "complete erasure" is of the cell only** — Eq. 5 is ungated, so the ejected h_t^ℓ still shapes the flush step's gates (§1.3). Matters if we reproduce the LSTM form.
- **No boundary at the top layer; z_t^0 = 1** — the bottom layer updates every step. A design where *every* level could skip would be a different model (closer to Skip-RNN).
- **No quantitative alignment metric** for boundaries vs words/strokes (Figs. 3–5 are visual). Table 1's hard-vs-soft spread (0.03 BPC) is the only ablation; there is no ablation of the top-down connection, of the output-module gates, or of the number of layers.
- **"Surprise" interpretation (p. 9)** — boundaries firing after "tele" suggest the detector responds to predictive uncertainty, echoing Schmidhuber's history-compression principle (pass up only the unpredicted). In our header layout the CTX token after a V is the only unpredictable transition type, so a surprisal-driven detector would naturally fire there *[inference]*; the paper does not use surprisal explicitly (cf. Rocki 2016b, which does).

## 7. Verdict

This paper is the cleanest published template for exactly the component we are missing: a per-token binary detector that reads the current token directly, a slow state that is held losslessly (COPY) until the detector fires, a hard reset-and-write at the boundary (FLUSH), a top-down re-injection, and a training recipe (step function forward, hard-sigmoid straight-through backward, slope annealing 1 → 5, Adam, gradient clipping at 1, LayerNorm). It also explains, in one sentence about leaky integration, why our EMA and recurrent gates cannot carry a header across 2P tokens and why the window gate degenerates to key splits. Implementing the §5.2 register in front of the LOCAL3 gate is cheap and I am confident (high) it can *express* the header solution and that the gradient path through the hold is sound. What the paper does not give us is any reason to believe the detector will be discovered label-free under our sparse query loss: it offers no initialization, no anti-collapse mechanism beyond FLUSH's implicit penalty, admits annealing was unusable at scale, and its own boundaries were only roughly linguistic. So: build the register, train it first with the labelled nudge to confirm the mechanism, then remove the nudge on a task where a single channel provably fails and block lengths are randomized — moderate confidence that it then beats the window gate, low confidence that it does so without a firing-rate prior or penalty.
